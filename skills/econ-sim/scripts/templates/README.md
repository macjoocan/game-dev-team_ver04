# econ-sim/ — 경제 검증 하네스

`econ-sim` 스킬이 쓰는 페르소나 코호트 시뮬레이터. **자기완결적**이라 플러그인 없이도 돈다.
`balance-sim`의 `sim/`과 통계 층(`lib-stats.mjs`)·시드 층(`rng.mjs`)을 공유한다.

## 쓰는 법

```bash
node econ-sim/econ-run.mjs --seed 7 --cohort 10000 --days 30
node econ-sim/econ-run.mjs --seed 7 --cohort auto --margin 0.02   # 목표 오차에서 코호트 역산
node econ-sim/econ-run.mjs --seed 7 --ab upgradeCostGrowth=1.15   # 원장 수치 A/B
node econ-sim/econ-run.mjs --seed 7 --cohort 5000 --out econ-out
```

종료 코드: `0` 충족 · `1` 미달 · `3` 측정 불가.

## 왜 페르소나별로 돌리나

**"평균 플레이어"는 존재하지 않는다.** 무과금 그라인더와 하이브리드 과금자는 같은 경제 안에서
완전히 다른 곡선을 그린다. 평균으로 뭉개면 그 격차가 사라지고, 이 스킬의 핵심 게이트 질문인
**"무과금도 합리적 시간 안에 완주 가능한가"** 에 답할 수 없다.

그래서 `personas.mjs`의 페르소나마다 코호트를 따로 돌려 비교한다. 리포트가 자동으로 판정하는 것:

| 판정 | 무엇을 보나 |
|---|---|
| 무과금 완주율 | F2P 코호트가 핵심 콘텐츠를 끝내는 비율 (95% CI) |
| 무과금 완주 소요 | 완주까지 중위 일수. 완주자가 0이면 페이월이다 |
| 무과금 진행 막힘 | 재화가 없어 진행 못 한 일수 비율 |
| **페이투윈 격차** | 최다 과금 페르소나 / 무과금 진행도 비율. 상한 초과 = 같은 게임이 아니다 |
| D1 리텐션(가중) | 페르소나 비중으로 가중한 전체 지표 |
| 재화 수지 | 획득 − 소비. 계속 쌓이면 싱크 부족(인플레) |

## 해야 할 일 (순서대로)

1. **`economy.mjs`의 `simulatePlayer`를 실제 경제 로직으로 바꾼다.** 지금은 자리표시자다.
   `PLACEHOLDER`가 `true`인 동안 판정은 무조건 **측정 불가**로 강제된다.
2. **`defaultConfig`를 프로젝트 경제 원장 import로 교체한다.**
   ```js
   import { ECONOMY } from '../src/data/economy.js';
   export const defaultConfig = ECONOMY;
   ```
3. **`personas.mjs`의 행동 파라미터를 게임에 맞춘다.** 세션/일, 광고 시청률, 주당 과금액,
   인내도. 페르소나가 실제 유저와 다르면 곡선 전체가 틀린다 — 라이브 데이터가 있으면 보정해라.
4. **`econ-targets.mjs`를 경제 원장 값으로 채우고 출처(경로·줄)를 주석에 적는다.**

## 시뮬로 판정되지 않는 것

리포트의 `[공백]`에 자동으로 들어가지만, 여기서도 못박아 둔다.

- **컴플라이언스.** 확률형 아이템 확률 공개(한국 등 법적 의무), 미성년 지출 보호는 사람이
  확인한다. 출시 전 실제 법률 검토가 필요하다 — 이 하네스는 변호사가 아니다.
- **다크패턴.** 강제 FOMO·미끼 확률·손실 회피 악용은 수치가 아니라 설계 리뷰 대상이다.
- **페르소나 파라미터의 타당성.** 이건 가정이다. 하네스는 가정이 맞는지 검증하지 못한다.

## 전제

**core 게임성(`balance-sim`, 파이프라인 ④)이 통과한 뒤에 이 트랙을 시작한다.** 재미가 먼저다.
재미없는 게임의 경제를 튜닝하는 건 순서가 틀린 일이다.
