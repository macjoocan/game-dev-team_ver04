# 3D 에셋 파이프라인

엔진에 깨끗하게 안착해야 하는 3D 게임 에셋에 쓴다.

## 필요한 스펙
- 엔진과 단위 스케일.
- 카메라 거리와 타깃 플랫폼.
- 폴리/삼각형 예산과 텍스처 크기.
- 피벗/원점과 forward/up 축.
- 콜리전 요구사항과 LOD 개수.
- 익스포트 포맷: 프로젝트가 FBX를 요구하지 않으면 **GLB/glTF**를 기본으로.

## Blender MCP 사용
Blender MCP가 붙어 있으면 모델링·머티리얼 세팅·리깅/애니메이션 확인·익스포트·검증 스크린샷을
그것으로 한다. 안 붙어 있으면 **정확한 Blender 조작과 임포트 설정을 담은 핸드오프 문서**를 낸다.
"할 수 없다"로 끝내지 않는다.

## 익스포트 체크리스트
- 원점/피벗이 **게임플레이 기준**으로 잡혀 있다.
- 스케일이 엔진 단위와 맞는다.
- 머티리얼 이름이 예측 가능하다.
- 텍스처가 패킹돼 있거나 경로가 문서화돼 있다.
- 콜리전 프록시가 포함되거나 명시돼 있다.
- LOD 명명이 일관되다.
- 애니메이션 클립 이름이 붙고 트림돼 있다.
- 엔진 안 스크린샷으로 스케일·라이팅을 확인했다.

## 방법이 여러 개면 후보로 비교한다
- 리타깃·리깅·가중치·줄이기 비율·굽기·임포트 설정처럼 결과를 수치·렌더로 비교할 수 있으면, 하나를 바로 고르지 않는다.
- 후보 2~3개를 같은 입력·카메라·프레임으로 돌리고 같은 지표 표로 비교한다(`scripts/blender-dump-frames.py` → `scripts/probe-metrics.py`).
- 리그·동작 결과는 `scripts/blender-rig-check.py`로 잰다. 판정 기준(접지 0.5cm, 이족은 발 속도, 디딘 구간 양 끝 1프레임 제외, 부위 영역은 기본 자세 위치)이 고정돼 있다. 새 모델도 바로 같은 표로 비교한다(`probe-metrics.py --rig-check`). 과제마다 검사 스크립트를 새로 만들지 않는다.
- 시작 전에 `references/lessons/`를 훑고, 끝나면 채택 이유와 교훈을 같은 형식으로 남긴다. 검사 통과는 외형 승인이 아니다.
- 절차·지표 표준표·입력 형식: [references/propose-probe-compose.md](references/propose-probe-compose.md)

## 흔한 실수
| 실수 | 교정 |
|---|---|
| 잘 만든 모델이 엉뚱한 스케일로 임포트됨 | 익스포트 전에 단위 스케일을 고정한다 |
| 피벗 때문에 배치가 괴로움 | 원점을 모델링 편의가 아니라 게임플레이 기준으로 잡는다 |
| 임포트에서 머티리얼이 깨짐 | 단순한 이름의 머티리얼 + 문서화된 텍스처 경로 |
| 콜리전을 잊음 | 핸드오프 전에 프록시나 명시적 콜리전 메모를 붙인다 |
| 텍스처 예산을 눈대중 | `asset-budget`으로 실측해 목표치와 대조한다 |

## 생성 모델 메시·리깅 함정 (2026-10 실전)
| 함정 | 교정 |
|---|---|
| 생성 모델(Meshy 등)을 줄이면 표면이 조각나 "자글자글한 실선"이 보임 | 텍스처 이음매마다 정점이 갈라져 있다. **줄이기 전에 정점 합치기**(1e-4), 내보낸 뒤 열린 모서리 수를 센다 |
| 정점을 합치니 평평한 면에 삼각형 얼룩 | 원래 노멀이 남았다. 사용자 노멀을 지우고 각도 기준(30°)으로 다시 부드럽게 준다. `shade_auto_smooth`는 모디파이어라 내보내기에서 빠진다 |
| 자동 가중치(heat)가 0을 냄 | 조각난 표면이면 정점을 합친 복사본으로 계산해 옮긴다. 작은 메시(약 0.35m)면 아마추어+메시 복사본을 10배로 키워 계산한다. 실패해도 조용히 끝나니 가중치 받은 정점 수를 센다 |
| 굽기 뒤 이음매에 검은 실금 | 같은 자리 정점의 가중치를 같게 맞춘다. 위상 기반 smooth 대신 위치 이웃 평균을 쓴다. "이음매 벌어짐" 지표를 처음부터 넣는다 |
| 메시를 바꾸니 동작이 안 먹음(Blender 5) | `obj.data`를 바꾸면 정점 그룹 이름이 사라진다. 같은 순서로 그룹을 다시 만든다. 동작 확인은 `action`과 `action_slot`을 같이 넣고 렌더로 실제 움직임부터 본다 |
| Blender MCP 스크립트 중 Blender가 꺼짐 | 임시 물체를 바로 지우거나 화면에 안 띄운 장면을 움직이면 꺼진다. 컬렉션에서 빼고 갱신한 뒤 다음 호출에서 지운다. 단계마다 저장한다 |
| Humanoid 동작에서 다리 뒤집힘·발 떨림 | Avatar 기준 자세의 다리를 곧게 편다. 바닥 보정은 동작 시작 때 한 번만 정한다. [교훈](references/lessons/2026-10-29-unity-humanoid-avatar-legs-and-floor.md) |
| 손가락 뼈가 실제 손가락과 어긋남 | 가중치가 아니라 메시 모양으로 손가락을 찾아 뼈를 맞춘다. 손바닥 방향은 렌더로 확인한다. [교훈](references/lessons/2026-10-28-hand-finger-normalize.md) |
| 체형이 다른 캐릭터끼리 동작 공유 | 크게 다르면 공유하지 않는다. 자기 동작 + 발 고정·팔 보정. [교훈](references/lessons/2026-10-31-biped-body-shape-foot-lock.md) |
| 네발 캐릭터 발 미끄러짐·관통 | 뼈대는 두고 다리만 보행 생성 + 클립 기반 굽기. [교훈](references/lessons/2026-10-30-quadruped-gait-and-clip-weights.md) |
| 원본 동작부터 고치려 함 | 먼저 "도구 프리뷰에서도 이상한지"를 가른다. 게임에서만 이상하면 엔진 쪽 원인이다 |
