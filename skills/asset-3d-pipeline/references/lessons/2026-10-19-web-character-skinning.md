# 생성 모델을 기존 모션 리그에 맞추기 (웹 three.js 캐릭터)

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-15~19 (정리 2026-10-19) |
| 과제 | 이미지 기반 3D 생성 모델에 기존 모션 라이브러리를 깨지 않고 붙이기 |
| 조건 | 웹 three.js 캐릭터, GLB 출력. 원본 모션 리그 70뼈, 원본 메시 약 6만~8만 삼각형 |

> 아래 수치는 **한 사례의 값**이다. 다른 모델에 옮겨 쓰지 않는다.

## 후보와 결과

| 과제 | 후보 | 결과 |
|---|---|---|
| 리그와 모델 중 무엇을 맞추나 | 모델에 임시 리그를 새로 붙임 / 다른 대상 리그(22뼈)로 리타깃 / **모션 리그(70뼈)를 고정하고 새 모델을 맞춤** | 임시 리그는 동작이 부자연스러웠다. 22뼈 리타깃은 팔 뜯김이 재발해 보류했다. 70뼈 고정 + 모델 맞춤을 채택 |
| 가중치 계산 순서 | 축소 후 heat / 전역 smoothing / voxel remesh / **원본 표면 연결 → 축소 → heat** | 마지막을 채택. voxel remesh는 UV 외형이 깨져 폐기 |
| 손 | 손 전체 축소 / 가중치 평활화 / 연속 변형 v2~v4 | v4를 선택 후보로 보존(기본 OFF). 강한 주먹 접힘은 미해결 |
| 시간 키 | GLB 기본 내보내기 / **원본 시간·local TRS 직접 출력** | 기본 내보내기는 `force_sampling=False`여도 24fps로 재샘플링됐다. 직접 출력을 채택 |

| 지표 | 이전 | 원본 재시도 | 조건 |
|---|---:|---:|---|

| 어깨 간선 최대 늘어남 | 46.08mm | 21.59mm | 같은 영역·같은 155자세, 임시 기준 30mm |

메시 해상도(60,000 → 79,999삼각형)와 몸통 처리도 함께 달라졌다. 개선을 표면 연결 하나의 효과로 단정하지 않는다.

## 채택 이유와 교훈

1. **모션 리그를 고정하고 모델을 맞춘다.** 원본 관절을 옮겨 스킨 문제를 가리지 않는다. 리그를 바꿔야 하면 별도 버전으로 두고 기존 동작을 다시 검증한다.
2. **표면을 먼저 연결하고 스키닝한다.** UV는 loop에 두고 정점만 합친다(모델 크기 약 1에서 weld `1e-5`). 축소를 먼저 하면 경계 양쪽이 다르게 줄어 겹친 면이 남는다.
3. **손은 길이만 보지 않는다.** 손바닥·기저부 두께와 굽힘 면 배치를 함께 본다. 손 간선 늘어남이 줄어도 Idle 면적이나 손바닥 접힘이 나빠지면 채택하지 않는다.
4. **원본 시간 키를 보존한다.** 내보내기 옵션만 믿지 않는다. 내보낸 GLB의 sampler input을 읽어 원본과 대조한다.
5. **같은 카메라·조명·동작 시각으로 비교한다.** 얼굴 중심을 따로 맞춘 화면은 정밀 비교가 아니다.

## 적용 범위와 반례

- 적용 범위: 기존 모션 라이브러리를 그대로 써야 하고, 새 모델을 그 리그에 맞출 수 있는 경우.
- 반례: 뼈 이름 70개가 같아도 몸·머리·다리 파트의 bind가 달랐다. 이름 일치만으로 호환을 확정하지 않는다.
- weld 값과 위 수치는 이 모델의 기록이다. **다른 모델의 통과 근거로 쓰지 않는다.**
- Unity Humanoid처럼 근육 공간으로 리타깃하는 엔진에는 그대로 옮겨지지 않을 수 있다 [확인 필요].
