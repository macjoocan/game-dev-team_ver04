이식 결과가 원본 데이터와 **같은 것을 그리고 있는지** 판정한다. "돌아간다"(R5)와 "맞다"(R6)는 다른 주장이고, 이 스킬은 뒤쪽만 담당한다.

## 두 곳에서 쓴다

| 시점 | 무엇을 대조하나 |
|---|---|
| **R2** — 이식 전 | 추출본 자체가 온전한가. 개수·실패 수·집계가 baseline과 맞는가 |
| **R6** — 이식 후 | 유니티 화면이 추출본과 같은가. 셀 단위로 맞는가 |

R2를 건너뛰면 R6에서 어긋났을 때 **데이터가 틀린 건지 이식이 틀린 건지 가릴 수 없다.** 순서를 지킨다.

## 표본 뽑기

전량 대조는 느리고, 앞에서 20개만 보는 건 표본이 아니다.

- **세트·포맷·난이도별로 골고루** 뽑는다. 포맷이 여러 개면(예: layered / board / random) 각각에서 최소 3개.
- **경계를 반드시 포함한다**: 첫 레벨, 마지막 레벨, 가장 큰 보드, 가장 작은 보드, 레이어 최대치, 기믹이 가장 많은 레벨.
- 표본 목록은 **시드를 적어 고정**한다. 다음 회차가 같은 표본을 다시 뽑을 수 있어야 비교가 된다.

경계값이 비어 있는 스위트는 통과해도 아무것도 보증하지 않는다 — 버그는 대부분 거기 있다.

## 대조 항목

| 항목 | 기준(원본) | 확인 방법 |
|---|---|---|
| 레벨 개수 | `baseline.md`의 세트별 개수 | 로드된 레벨 수 |
| 보드 크기 | 추출 JSON의 행·열 | 런타임 그리드 크기 |
| **셀 값** | 추출 JSON의 셀 배열 | 셀 단위 diff. 첫 불일치의 좌표·기대값·실제값을 찍는다 |
| 팔레트 | `palette.json` 색 수와 인덱스 | 인덱스→색 매핑이 같은가 |
| 기믹·엔티티 수 | summary.xlsx 집계 | 레벨별 카운트 |
| 좌표계 | 추출 노트(예: 타일 1개 = 2×2유닛) | 겹침·오프셋이 재현되는가 |
| **출처 세트** | 추출 zip의 `levels/<세트>/` 경로 | 이식된 파일을 **해시로 역추적**해 어느 세트에서 왔는지 확인 |

**뷰어 HTML이 사람 눈으로 볼 기준 화면이고, JSON이 기계 대조의 기준이다.** 눈으로만 보고 "같아 보임"은 증거가 아니다.

**출처 세트 대조를 빼먹지 마라.** 레벨 번호만 남기고 세트를 버리는 이식 경로에서는, 같은 번호의
다른 세트 레벨이 조용히 들어온다. 셀 값 대조는 "원본 어딘가와는 같다"까지만 증명하지
"우리가 의도한 그 레벨과 같다"를 증명하지 않는다. 이식 파일의 해시를 추출 zip 전체와 맞춰
경로를 역추적하면 한 번에 드러난다 — PixelFlow 첫 실측에서 표본 5개 중 2개가 이렇게 걸렸다.

## 판정

`ORCHESTRATION.md §5`를 그대로 따른다.

| 판정 | 뜻 | 되돌림 |
|---|---|---|
| 충족 | 표본 전부 일치 | 다음 단계(전량 이식·구현) |
| 미달 | 대조했고 어긋난 셀·개수가 있음 | **이식(developer)** — 파서·좌표계 수정 |
| 측정 불가 | 대조 수단이 없음(런타임에서 보드 상태를 못 읽음, 표본을 못 고정함) | **하네스 수리** — 상태를 덤프하는 창구부터 만든다 |

셋을 섞지 않는다. 특히 "런타임 상태를 못 읽어서 확인 못 했다"를 미달로 적으면 멀쩡한 파서를 뜯게 된다.

## 보고 (검증 리포트 5섹션)

- **주장**: 판정 한 줄
- **증거**: 실행 명령·출력, **표본 시드·표본 수·대상 커밋**, 불일치 목록(레벨 번호 / 좌표 / 기대 / 실제)
- **기준**: `baseline.md`의 어느 수치와 비교했는지(파일·줄)
- **공백**: 대조하지 않은 포맷·세트·항목. 예: "random 포맷 783개는 보드가 없어 셀 대조 대상 아님"
- **잔여 위험**: 표본은 통과했지만 전량에서 깨질 수 있는 지점

## 하지 않는 것

- 재미·난이도 판단 (`balance-sim` 소관)
- 색감·가독성·UI 겹침 판단 (`visual-qa` 소관)
- 코드 수정 — 어긋난 곳을 좌표와 함께 developer에게 되돌린다
