# sim/ — 게임성 검증 하네스

`balance-sim` 스킬이 쓰는 헤드리스 시뮬레이터. **자기완결적**이라 플러그인 없이도 돈다
(`lib-stats.mjs`가 복사돼 있다). 하네스는 세션보다 오래 살아야 한다.

## 쓰는 법

```bash
node sim/run.mjs --seed 42 --runs 1000 --policy greedy
node sim/run.mjs --seed 42 --runs auto --margin 0.02        # 목표 오차에서 판수 역산
node sim/run.mjs --seed 42 --runs 1000 --ab damageMax=25    # 수치 A/B (공통 난수)
node sim/run.mjs --seed 42 --runs 1000 --out sim-out        # report.md + results.json
node sim/curve-check.mjs sim-out/results.json               # 난이도 곡선 판정
```

종료 코드: `0` 충족 · `1` 미달 · `3` 측정 불가. CI 게이트로 쓸 수 있다.

## 해야 할 일 (순서대로)

1. **`game.mjs`의 `simulateRun`을 실제 런 로직으로 바꾼다.** 지금은 자리표시자라 측정치가
   의미 없다 — 그 상태의 판정은 충족이 아니라 **측정 불가**다.
2. **`defaultConfig`를 프로젝트 밸런스 데이터 테이블로 교체한다.** 숫자를 여기 박지 말고
   기존 테이블을 import 해라. 그래야 스윕이 된다.
   ```js
   import { BALANCE } from '../src/data/balance.js';
   export const defaultConfig = BALANCE;
   ```
3. **`policies.mjs`의 `scoreOption`을 구현한다.** 비어 있으면 greedy가 random과 같다.
4. **`targets.mjs`를 기획 문서 값으로 채우고 출처(경로·줄)를 주석에 적는다.**

## 지켜야 할 것

- **난수는 인자로 받은 `rng`만 쓴다.** `Math.random()`을 한 군데라도 부르면 재현이 깨지고,
  재현이 안 되는 수치는 게이트 근거가 아니다.
- **판 시드는 `runSeed(SEED, i)`로만 만든다.** A/B가 같은 시드로 짝을 맞춰야 공통 난수
  효과가 나온다 — 적은 판수로 효과를 잡는 이유가 그것이다.
- **UI·엔진 API를 부르지 않는다.** 헤드리스여야 수천 판이 돈다.
- 리포트의 **[공백]** 칸을 비우지 마라. 비우면 "전부 검증했다"는 주장이 된다.

## 판정 규칙 (중요)

점추정만 보지 않는다. 95% 신뢰구간이 목표 구간 안에 **완전히** 들어가야 충족이다.

| 상황 | 판정 | 되돌릴 곳 |
|---|---|---|
| 구간 전체가 목표 안 | **충족** | 다음 단계 |
| 구간이 목표를 벗어나 확실히 낮/높음 | **미달** | 기획 (수치 재조정) |
| 구간이 목표 경계를 걸침 · 오차가 목표 폭보다 넓음 | **측정 불가** | 판수를 늘린다 |

세 번째를 미달로 착각해 수치를 흔들면 멀쩡한 밸런스를 망치고 원인은 그대로 남는다.

예: 목표 35~55%에서 100판 52%는 구간이 42~62%라 **측정 불가**다. 같은 52%를 1000판에서
얻으면 구간이 49~55%로 좁아져 **충족**이 된다. 판수가 판정을 바꾼다.
