이 스킬은 "재밌는가 / 밸런스가 맞는가"를 감이 아니라 데이터로 검증한다.
소유자는 game-designer이며, 필요한 시뮬 하네스는 developer가 만든다.

## 절차

### 1. 성공 지표 확인
기획(AGENTS.md/CLAUDE.md·기획 문서)에서 목표 지표를 가져온다. 없으면 game-designer에게 정의를 요청한다.
전형적 지표:
- 목표 승률 구간 (예: 초심자 30~50%)
- 평균 런/전투 길이
- 전투당 의미 있는 선택 수(선택지가 실제로 갈리는가)
- 사망 분포(특정 구간 급사 여부)
- 카드/선택지 픽률 편중도(특정 카드 독점 = 밸런스 붕괴)
- (HP 유지 로그라이크면) 회복 예산: 구간별 예상 피해 vs 회복량

### 2. 시뮬레이션 하네스 구성 — **처음부터 만들지 않는다**

```bash
node <플러그인>/skills/balance-sim/scripts/sim-scaffold.mjs --out sim
```

`sim/` 에 골격이 생긴다. 플러그인은 게임을 모르므로 **계약만 정하고 나머지를 다 가져간다**:

| | 소유 |
|---|---|
| `simulateRun({ rng, config, policy })` | **프로젝트** — 런 로직 (여기만 구현하면 된다) |
| 시드·배치·집계·신뢰구간·판정·리포트·커밋 스탬핑 | 스캐폴드 |

생성물: `run.mjs`(배치 실행+리포트) · `curve-check.mjs`(난이도 곡선) · `rng.mjs`(시드 고정) ·
`policies.mjs`(정책 2종) · `game.mjs`(계약 스텁) · `targets.mjs`(기획 소유 목표) ·
`lib-stats.mjs`(통계) · `README.md`. **자기완결적**이라 플러그인 없이 프로젝트 CI에서 돈다.

해야 할 것: `game.mjs`의 `simulateRun`을 실제 로직으로, `defaultConfig`를 프로젝트 밸런스
테이블 import로, `policies.mjs`의 `scoreOption`을 게임 가치 함수로, `targets.mjs`를 기획 값으로.

- **`game.mjs`의 `PLACEHOLDER`가 `true`인 동안 판정은 무조건 `측정 불가`로 강제된다.**
  자리표시자가 만든 숫자가 게이트 리포트에 미달로 올라가면 기획이 멀쩡한 밸런스를 흔들기 시작한다.
- 난수는 **인자로 받은 `rng`만** 쓴다. `Math.random()`을 한 군데라도 부르면 재현이 깨진다.
- 판 시드는 `runSeed(SEED, i)`로만 만든다 — A/B가 같은 시드로 짝을 맞춰야 공통 난수 효과가 나온다.
- 정책 최소 2종(무작위=하한 / 휴리스틱)으로 상·하한을 본다.

### 3. 몬테카를로 실행 — **판수는 목표 오차에서 역산한다**

```bash
node sim/run.mjs --seed 42 --runs auto --margin 0.02   # 오차 ±2pp 를 만족하는 판수 자동 계산
node sim/run.mjs --seed 42 --runs 1000 --policy greedy
```

"1000판 이상"은 임의의 관습이었다. 실제로는 **승률 100판이면 95% 구간이 ±9pp, 2400판이면 ±2pp**다.
목표 구간이 30~50%(폭 20pp)인데 오차가 ±9pp면 그 판정은 애초에 성립하지 않는다.
`--runs auto --margin`을 쓰면 판수가 "왜 그만큼인지 설명되는 수치"가 된다.

**A/B(기능/수치 ON-OFF)는 공통 난수로 짝지어 비교한다:**
```bash
node sim/run.mjs --seed 42 --runs 800 --ab damageMax=25
```
같은 시드 목록으로 양쪽을 돌려 대응표본 차이를 낸다. 게임 자체의 편차가 상쇄돼 독립 표본보다
훨씬 적은 판수로 효과를 잡는다. **차이 구간이 0을 포함하면 "효과가 있다"고 말할 수 없다.**

### 4. 리포트 (목표 대비) — 점추정이 아니라 **구간**으로 판정한다
`run.mjs`가 `지표 | 목표 | 실측 | 95% CI | 판정` 표와 5섹션을 자동으로 낸다.
이상 징후 플래그: 승률 0/100% 근접, 특정 카드 픽률 독점, 특정 구간 급사, 회복 예산 붕괴,
선택지가 사실상 하나로 수렴(선택 밀도 낮음).

### 5. 난이도 곡선 판정
```bash
node sim/curve-check.mjs sim-out/results.json
```
스테이지별 통과율의 **수열 모양**을 본다 — 좌절 벽 · 후반 램프 사망 · 급락 스파이크 · 역전 구간.
두 가지를 지켜야 결과가 의미를 갖는다:
- **조건부 통과율로 본다.** "그 스테이지에서 죽은 판수"는 난이도가 아니다 — 뒤쪽은 도달한 사람이
  적어서 사망자도 적다. 도달한 판 중 넘은 비율이 난이도다.
- **`targets.mjs`의 `stageOrder`를 채운다.** 진행 순서를 모르면 곡선 판정이 성립하지 않는다.
  비워두면 이름 자연순으로 추론하고, 실제와 다르면 역전 판정이 전부 허위가 된다.

초반 통과율이 높은 건 정상이다(램프). 후반부(뒤 1/3)가 상한을 넘으면 난이도가 안 오르는 것이다.

### 6. 판정 & 되돌림
지표 미충족이면 "어떤 수치를 얼마로" 조정할지 가설을 제시하고 game-designer/기획 단계로 반환한다.
임의로 밸런스 수치를 고치지 않는다(수치 변경은 기획 게이트 소관).

종료 코드로 CI 게이트를 걸 수 있다: `0` 충족 · `1` 미달 · `3` 측정 불가.

## 신규 기믹/모드 검증 (기능 세트 단위 · 실전 검증 반영)
새 메커니즘(대시·그레이즈·유물 등)이나 새 모드를 추가할 때는 기존 스테이지 sim을 돌리는 게 아니라
**전용 sim으로 baseline 대비 효과를 측정**한다:
1. 수치는 전부 데이터 테이블 신설 키로(`<추정>` 표기) — 로직에 숫자를 심지 않는다.
2. **같은 봇, 같은 시드**로 기능 OFF(baseline) vs ON을 비교 — "기능이 지표를 얼마나 움직였나"가 판정 대상.
   (예: 대시 도입 → 생존턴 +72% 실측. 봇이 기능을 소극적으로 쓰면 하한 추정임을 명시)
3. 게임을 깨는지 확인: 상한 도달률(cap 도달 0이어야 난이도 램프가 살아 있음), 기존 모드 회귀 테스트.
4. 기능이 특정 모드 전용이면 **다른 모드 불변을 테스트로 계약화**한다(소급 적용은 별도 게이트).
5. 봇이 측정 못 하는 축(체감·연출)은 [공백]에 명시하고 사람 실플레이로 넘긴다.

## 검증 리포트 (필수 형식)
"승률 52%"는 **지어내기 가장 쉬운 형식**이다. 그래서 완료 보고는 5섹션을 전부 채운다.
한 칸이라도 못 채우면 그건 통과가 아니라 **측정 불가**다 (ORCHESTRATION.md §5).

```
[주장]      충족 / 미달 / 측정 불가 — 한 줄
[증거]      실행한 명령 그대로 + 출력 요약
            예) node sim/run.mjs --seed 42 --runs 1000 --commit $(git rev-parse --short HEAD)
            시드 · 판수 · 대상 커밋이 없으면 증거가 아니다
[기준]      목표 지표의 출처(문서 경로·줄). 이전 측정치와 비교했다면 그 커밋
[공백]      안 돌린 것 · 못 돌린 것 (빈칸이면 "전부 검증했다"는 주장이 된다)
[잔여 위험] 통과했지만 남는 위험
```

- **미달**(측정했는데 목표 미달)은 기획으로 되돌린다.
- **측정 불가**(하네스 없음·시드 안 잡힘·데이터 커밋 불일치)는 developer에게 하네스 수리를 요청한다.
- 둘을 섞으면 멀쩡한 밸런스를 헛되이 흔들거나, 못 맞춘 밸런스를 통과시킨다.

### 오차 폭이 판정을 바꾼다 (구간 대 구간)
점추정만 보면 안 되는 이유가 이것이다. `run.mjs`가 이 판정을 자동으로 한다.

| 상황 | 판정 | 되돌릴 곳 |
|---|---|---|
| 95% 구간 **전체**가 목표 안 | 충족 | 다음 단계 |
| 구간이 목표를 벗어나 확실히 낮/높음 | 미달 | **기획** (수치 재조정) |
| 구간이 목표 경계를 걸침 · 오차가 목표 폭보다 넓음 | **측정 불가** | **개발** (판수를 늘린다) |

예: 목표 35~55%에서 **100판의 52%는 구간이 42~62%라 측정 불가**다. 같은 52%를 1000판에서
얻으면 구간이 49~55%로 좁아져 충족이 된다. 판수가 판정을 바꾼다 — 그래서 판수 없는 승률은
증거가 아니다.
