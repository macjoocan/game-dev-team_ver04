PR/변경분을 **정확성** 기준으로 리뷰한다. 장르/엔진 무관하게 적용되는 게임 코드 공통 위험에 집중.

## 절차
1. diff(또는 브랜치)를 가져온다(GitHub MCP `get_diff`/`pull_request_read` 또는 로컬 git diff).
2. 아래 체크리스트로 점검하고, 라인 단위 코멘트를 남긴다(GitHub 연결 시 리뷰로 제출).
3. 판정: **통과 / 조건부 통과(후속 이슈 명시) / 반려(사유 목록)**.

## 게임 코드 공통 체크리스트
- [ ] 빌드/런타임/콘솔 에러 0
- [ ] **밸런스·수치가 로직에 하드코딩되지 않았는가**(데이터 테이블로 분리)
- [ ] 전투/런 등 코어 로직이 UI·엔진과 분리 유지(헤드리스 시뮬 전제 훼손 없음)
- [ ] 경계값(0/최대/음수/사망·부활 상태)에서 안전
- [ ] 상태 이월/초기화 버그(턴/라운드/씬 전환 경계)
- [ ] RNG 결정성 훼손 없음(시드 시뮬 재현성 유지)
- [ ] 리소스 로딩/해제(메모리 누수), 프레임 영향
- [ ] **기존 기능 회귀 없음** — 테스트/스모크로 확인
- [ ] 시큐리티: 검증 안 된 입력·직렬화·치트 취약(해당 시)

## 검증 리포트 (필수 형식)
"회귀 없음"는 **지어내기 가장 쉬운 형식**이다. 그래서 완료 보고는 5섹션을 전부 채운다.
한 칸이라도 못 채우면 그건 통과가 아니라 **측정 불가**다 (ORCHESTRATION.md §5).

```
[주장]      충족 / 미달 / 측정 불가 — 한 줄
[증거]      실행한 명령 그대로 + 출력 요약
            예) git diff --stat origin/main...HEAD · npm test · 빌드 로그
            시드 · 판수 · 대상 커밋이 없으면 증거가 아니다
[기준]      목표 지표의 출처(문서 경로·줄). 이전 측정치와 비교했다면 그 커밋
[공백]      안 돌린 것 · 못 돌린 것 (빈칸이면 "전부 검증했다"는 주장이 된다)
[잔여 위험] 통과했지만 남는 위험
```

- **테스트를 돌리지 않았으면 "회귀 없음"이라고 쓰지 않는다.** "미실행"이라고 쓴다.
- 체크리스트에서 확인하지 못한 항목은 통과가 아니라 [공백]에 적는다.
- 이전 빌드의 결과를 이번 결과처럼 제시하지 않는다.

## 산출물
- 라인 코멘트 + 판정 + (조건부/반려 시) 수정 요청 목록. 코드는 직접 고치지 않고 developer에게 반환.
