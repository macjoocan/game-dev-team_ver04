## 팀 구성 (허브-앤-스포크)
```
        [사람 = 최종 권위자]
              │ 승인/지시
        [오케스트레이터 = 메인 세션]

```
- 에이전트는 서로 직접 대화하지 않는다. 결과는 오케스트레이터로 돌아오고, 오케스트레이터가 다음 역할로 전달한다.
- 오케스트레이터는 직접 창작/구현하지 않는다. 분배·게이트 확인·사람 보고가 역할.

| 에이전트 | 언제 부르나 |
|---|---|
| `pm` | 태스크 분해·우선순위·이슈 관리 |
| `game-designer` | 기획/밸런스 설계·검토, 게임성 지표 정의·검증 |
| `developer` | 프로토(스파이크)·본구현·시뮬 하네스 |
| `qa` | 정확성 검증·코드 리뷰·버그 리포트 |
| `meta-economy-designer` | 성장 구조·수익화·리텐션 설계·경제 검증 (core 통과 후) |
| `artist` | 카드/UI 비주얼 시안·톤, 연출(폴리싱) 디렉션 |

## 파이프라인 & 게이트 (사람 승인 없이 다음 단계 금지)
0. **컨셉 발굴/코어 확보** (`concept-discovery` — 오케스트레이터가 사람과 대화) — 아이디어·코어 규칙을 유사 사례 조사와 함께 다듬어 코어 컨셉을 확정한다. **발산 단계**(수치 게이트 없음). 게이트: 사람이 코어 확정 승인.
1. **기획/밸런스 + 게임성 지표 정의** (`game-designer`)
   - 게이트: 근거 없는 수치 0 · 미결 명시 · 핵심 수치 공란 0 · 게임성 성공 지표(목표 승률·런 길이·선택 밀도 등) 숫자로 정의.
2. **태스크 분해** (`pm`).
3. **프로토타입(스파이크)** (`developer`) — 버려도 되는 최소 구현. 핵심 재미만 싸게.
4. **게임성 검증** (`game-designer` + `balance-sim`)
   - 자동 시뮬로 승률·런 길이·픽률·사망 곡선을 목표 지표와 대조.
   - 게이트: 지표 충족. **미충족 시 1번(기획)으로 되돌려 재조정(반복 루프).**
5. **본구현** (`developer`) — 검증 통과안을 정식 구현. worktree 브랜치, 작은 커밋.
6. **정확성 검증** (`qa`) — 버그·회귀·콘솔 에러. 통과/조건부/반려.
7. **아트/시각 QA** (`artist`) — `art-direction`으로 `VISUAL_DESIGN.md` 확정 → 에셋 제작(asset-pipeline manifest 기록) → `visual-qa` 검수.
   - 게이트: `VISUAL_DESIGN.md` 존재 · asset manifest 기록 · 실제 화면 visual-qa 증거 확인.
P1. **1차 폴리싱 — 코어 연출 패스** (`polish` · artist+developer) — 게임성 검증 통과한 코어에 최소 연출(타격감·핵심 전환)로 손맛 확보. **연출은 game feel 레이어**(재미=4, 정확성=6과 별개). 게이트: 핵심 액션 피드백 존재 + 사람 사인오프.

> **3↔4는 반복 루프다.** 재미가 안 나오면 5(본구현)로 넘어가지 않는다. 반복 예산(예: 최대 N회)을 정해 무한루프를 막는다.
> **QA(6)와 게임성 검증(4)은 다르다.** QA=정확성(버그), 게임성 검증=재미/밸런스(데이터).

- **게이트 모드**: <lean/full/solo> — lean=핵심 게이트만(코어 확정·게임성 검증·머지, **기본**), full=모든 게이트(정식·출시 준비 시), solo=게이트 없음(잼/실험).
- 게이트 통과 이력과 현재 단계는 레포 루트 `PIPELINE_STATE.md`에 기록한다.

## 아트/에셋 규칙
- 아트 제작 전 `VISUAL_DESIGN.md`로 팔레트, 실루엣, 카메라, UI 톤, 금지 스타일을 고정한다.
- 에셋은 stable ID, 승인 상태, 출처/라이선스, source/raw/final 경로를 manifest에 남긴다.
- 스프라이트는 seed frame 승인 후 시트/스트립으로 만들고 프레임 크기, 피벗, baseline을 통일한다.
- UI 아트는 HUD, 버튼, 카드, 아이콘, 상태/피해 숫자의 상태별 변형과 작은 화면 가독성을 확인한다.
- 3D 에셋은 scale, pivot, material, collision proxy, LOD, GLB/FBX export 기준을 정한다.
- visual-qa는 실제 게임 화면과 가장 작은 목표 화면에서 스크린샷 또는 preview sheet 증거를 남긴다.

- **밸런스 수치(HP·데미지·계수 등)는 코드 로직에 흩뿌리지 말고 한 곳(데이터 객체/테이블)에 모은다.**
- <프로젝트 고유 규칙: 색 변수, 타입 문자열 네이밍 등>
- 전투/런 로직은 UI와 분리해 헤드리스 시뮬이 가능하도록 설계(게임성 검증 전제).
- 기존 동작을 깨지 않는다 — 변경 시 QA가 회귀 확인.
- 규모가 커지면 파일 분리안을 제안하되 사람 승인 후 분리.

## 라이브 서비스 트랙 (core 게임성 통과 후에만 진입)
> **전제: 파이프라인 4번(게임성 검증)이 통과해야 시작.** 재미없는 게임에 수익화를 붙이지 않는다.
8. **메타/수익화 설계 + 경제 지표 정의** (`meta-economy-designer`)
   - 성장 구조·재화 원장·수익화(가챠+광고+F2P)·리텐션 사이클.
   - 게이트: 근거 없는 수치 0 · 무과금 진행 가능(F2P fairness) · 다크패턴 없음 · 확률 공개 등 컴플라이언스.
9. **경제 검증** (`meta-economy-designer` + `econ-sim`)
   - 코호트 시뮬로 리텐션·재화수지·전환율·LTV·무과금 완주율을 목표와 대조. 미달 시 8번으로 되돌림(반복 루프).
10. **구현**(`developer`) → **정확성 QA**(`qa`).
> 경제 검증(9, 지속가능/공정) ≠ 게임성 검증(4, 재미) ≠ QA(정확성).
