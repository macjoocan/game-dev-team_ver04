파이프라인 상태를 짧게 요약해 사람이 "다음에 뭔 결정/승인해야 하는지" 즉시 알게 한다.

## 절차
1. 소스 수집(연결된 것만): GitHub(열린 PR·리뷰 대기·실패 CI·오래된 브랜치), 트래커(진행/블로커 이슈),
   레포 상태(CLAUDE.md 게이트·미결 목록).
2. 파이프라인 단계별로 매핑: 기획/게임성검증/구현/QA/아트/경제/폴리싱 중 어디에 무엇이 걸려 있나.
3. **사람의 결정이 필요한 게이트**를 최상단에 별도로 모은다.

## 산출물 (짧게)
- **승인/결정 대기**: (있으면) 게이트 목록 — 사람이 바로 판단할 것.
- **진행 중**: 단계별 1줄.
- **블로커/위험**: 리뷰 지연·실패 CI·미결 등.
- **오늘 추천 액션**: 1~3개.
> 장황 금지. 예약 작업(매 평일 오전)으로 돌리면 상시 대시보드 역할.

## 상태 파일 — `docs/pipeline/state.json`

브리핑 후 **이 파일을 실제 상태로 갱신한다.** 플러그인의 `SessionStart` 훅이 이 파일을 읽어
매 세션 시작 시 현재 단계·열린 게이트·반복 예산을 자동으로 주입한다. 파일이 없으면 훅은 조용히
아무것도 하지 않으므로, 파이프라인을 쓰기 시작할 때 한 번 만들어 두면 그때부터 상시 동작한다.

```json
{
  "stage": 4,
  "stageName": "게임성 검증(balance-sim)",
  "openGates": [
    "④ 게임성 검증: 승률 62%로 목표(30~50%) 초과 — 기획 반환 승인 대기"
  ],
  "loopBudget": { "name": "3↔4", "used": 2, "max": 3 },
  "blockers": ["보스 2페이즈 전이 조건 미결"],
  "updated": "2026-08-03"
}
```

| 필드 | 의미 |
|---|---|
| `stage` | 파이프라인 번호 0~11. `stageName` 생략 시 번호로 이름을 채운다 |
| `openGates` | **사람 승인 대기 중인 게이트.** 비면 훅은 게이트 경고를 내지 않는다 |
| `loopBudget` | 3↔4(게임성)·8↔9(경제) 반복 예산. `used >= max`면 훅이 "계속/피봇/보류 질문 필요"를 띄운다 |
| `blockers` | 사람이 풀어야 할 막힘 |

같은 디렉터리의 `audit.log`는 `SubagentStop` 훅이 자동으로 쌓는다(역할 에이전트가 끝날 때마다
한 줄). 손으로 쓰지 않는다 — 브리핑할 때 최근 활동 근거로 읽기만 한다.
