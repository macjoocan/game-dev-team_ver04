# wan22-5b-sprite-motion 워크플로 메모

**정지 스프라이트 한 장에서 움직임을 만든다.** 확산 이미지 모델로 프레임을 따로 뽑으면 프레임마다 캐릭터가
달라지는데(실측: img2img 는 포즈가 안 바뀌고, ControlNet 만으로는 정체성이 깨진다), 영상 모델은 시간축을
같이 보므로 그 문제가 구조적으로 없다.

## 필요한 파일 (약 15GB)

| 파일 | 폴더 |
|---|---|
| `wan2.2_ti2v_5B_fp16.safetensors` | `models/diffusion_models/` |
| `wan2.2_vae.safetensors` | `models/vae/` |
| `umt5_xxl_fp8_e4m3fn_scaled.safetensors` | `models/text_encoders/` |

앞의 둘은 `Comfy-Org/Wan_2.2_ComfyUI_Repackaged`, 텍스트 인코더는 `Comfy-Org/Wan_2.1_ComfyUI_repackaged` 의
`split_files/` 아래에 있다. 커스텀 노드는 필요 없다 — ComfyUI 0.33+ 가 `Wan22ImageToVideoLatent` 를 내장한다.

**5B 를 써라. 14B 는 24GB VRAM 이 필요하다.** 5B 는 8GB 에서 ComfyUI 기본 오프로딩으로 돈다(시스템 RAM 32GB 권장).

## 노드

- **7 `Wan22ImageToVideoLatent`** — 5B 전용이다. 14B 용 `WanImageToVideo` 와 잠재 채널 수가 다르니(48 vs 16)
  섞어 쓰면 조용히 망가진다. `start_image` 에 스프라이트를 넣는다
- **7.width/height** — 32의 배수. 640² 가 8GB 에서 33프레임이 도는 선. 늘리려면 length 를 줄인다
- **7.length** — 프레임 수. `(length-1)` 이 4의 배수여야 한다(33 · 49 · 81). 33프레임이면 걷기 한 사이클에 넉넉하다
- **8 `ModelSamplingSD3` shift 8.0** — WAN 계열 권장값. 낮추면 움직임이 과해지고 캐릭터가 녹는다
- **9 sampler `uni_pc` / scheduler `simple` / cfg 5.0** — 공식 예시 조합
- **11 `SaveImage`** — 프레임을 낱장 PNG 로 낸다. 영상 파일이 아니라 **프레임이 필요하므로** 일부러 이렇게 한다.
  이후 기존 체인(`rembg` 또는 `cutout` → `sprite-normalize` → `atlas-pack`)으로 그대로 잇는다

## 프롬프트 규칙 — 배경보다 **카메라**를 막는 게 중요하다

영상 모델은 기본적으로 카메라를 움직이려 한다. 스프라이트에서는 그게 곧 실패다(캐릭터가 화면 안에서 흔들린다).
- 긍정: `walks in place, steady loop, camera locked, no zoom, no pan`
- 부정: `camera motion, zoom, pan, background change, morphing`
`in place`(제자리) 를 빼면 캐릭터가 화면 밖으로 걸어 나간다.

## 한계 (알고 시작한다)

- **루프가 안 맞는다.** 첫 프레임과 끝 프레임이 이어지지 않는다. 걷기 사이클로 쓰려면 사람이 구간을 고른다
- 프레임 간 미세한 화풍 흔들림은 남는다. 2026 인디 실무 정리도 "프로토타입용, 손으로 다듬어 쓴다"고 적는다
- 33프레임 전부를 쓰지 않는다. 대개 4~8장을 골라 쓴다

API Format JSON 에 주석 키를 넣지 마라 — `_comment` 가 노드로 해석돼 500 이 난다.


## 한계와 다음 단계 — 프롬프트로는 여기까지다 (실측 2026-09-08)

`shift` 하나로 움직임을 조절하는 건 **손잡이가 하나뿐인 조종**이다. 캐릭터에 따라 그 손잡이의
유효 구간이 없을 수도 있다 — hex-danmaku 의 창 든 고블린(`lunger`)이 그랬다. 8회 시도 전부 실패:

| 여백 | shift | 결과 |
|---|---|---|
| 92% | 3.0 | 움직임 좋음, **발이 프레임 밖** |
| 65% | 2.5 | **형태 붕괴** |
| 65% | 2.75 / 2.85 / 3.0 | 거의 안 움직임 |
| 55% | 3.0 | 거의 안 움직임 |

2.5(붕괴)와 2.75(정지) 사이에서 뒤집힌다. 같은 방법으로 후드 고블린(`chaser`)은 한 번에 됐다.
차이는 **비스듬히 든 큰 강체(창)** 로 보인다 — 모델이 살짝 흔들거나 부수거나 둘 중 하나로만 다룬다.

### 입력 여백 규칙 (먼저 지킬 것)

WAN 은 `camera locked` 를 줘도 미세하게 확대한다. **입력이 캔버스를 꽉 채우면 그만큼 사지가 밖으로 나간다.**
실측: 92% 로 넣으면 6/6 프레임에서 발이 잘렸고, 55~65% 로 넣으면 0/12 였다.
`cutout` 뒤에 배경 제거 모델을 의심하기 전에 **원본 프레임에 사지가 있는지부터 본다** —
rembg 모델 4종(u2net·u2netp·isnet·birefnet)을 다 바꿔 봐도 결과가 같았다. 없는 다리는 못 만든다.
대신 여백이 커질수록 모델이 조심스러워져 움직임이 줄어드는 상충이 있다.

### 결론 (2026-09-08 후속) — 이 경로를 걷기 애니메이션의 답으로 쓰지 마라

같은 캐릭터에 LoRA + ControlNet 까지 다 돌려 게임 크기에서 재봤다. **세 갈래 모두 막혔다.**
자세한 표와 수치는 `char-art-system/SKILL.md` 의 "걷기 프레임은 코드로 만든다" 절에 있다.
요지: 확산·영상 모델은 프레임마다 독립 표본이라 "의상은 그대로, 다리만" 을 구조적으로 못 지킨다.

걷기·제자리 동작은 **`walk-composite.mjs`**(정지 한 장 + 기하 변형)로 간다. 의상 차이가 정확히 0 이다.
WAN 은 여전히 **참고용 포즈 소스**로는 쓸모가 있다 — 정체성이 잘 보존된 프레임을
LoRA 데이터셋에 넣는 용도로 실제로 썼다. 완성 프레임을 뽑는 용도가 아니다.

### 다음 단계 — Time-to-Move (TTM)

프롬프트 대신 **움직임을 직접 그려서 지시**하는 방법이 있다.
[TTM(Time-to-Move)](https://github.com/time-to-move/TTM) 은 학습 없이 도는 모션 제어로,
영역 마스크와 궤적을 줘서 "이 다리를 여기로" 를 지정한다. 우리 문제(다리는 움직이되 창은 그대로)에 정확히 맞는다.

- WAN 2.2 **5B 에서 돌고 6~8GB** 면 된다 — 이 PC 사양 안이다
- ComfyUI 에서 `kijai/ComfyUI-WanVideoWrapper` 커스텀 노드가 필요하다(지금 워크플로는 커스텀 노드 0)
- 마스크와 궤적을 사람이 그려야 하므로 **한 캐릭터당 손이 더 든다.** 대신 shift 도박이 사라진다

아직 이 레포에서 검증하지 않았다. **위 결론이 나온 뒤로는 우선순위가 내려갔다** —
걷기는 코드 합성으로 해결됐다. TTM 은 코드로 못 만드는 동작(관절이 접히는 공격 모션 등)이
필요해지면 그때 본다.
