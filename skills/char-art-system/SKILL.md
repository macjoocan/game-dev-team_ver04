캐릭터는 UI(`ui-art-system`)·이펙트(`fx-art-system`)와 다르다. 저 둘은 결과물이 **규격**이라 코드로 그리는 게 정확하지만, 캐릭터는 **인상**이 결과물이라 생성 모델이 필요하다.

## 전제 — 백엔드

로컬 ComfyUI 가 `http://127.0.0.1:8188` 에 떠 있어야 한다. 세팅: **[references/comfyui-setup.md](references/comfyui-setup.md)**
(RTX 50 시리즈는 CUDA 12.8+ PyTorch 가 아니면 커널 없이 죽는다 — 가이드의 경고 항목을 먼저 본다.)

**안 떠 있으면 "생성 실패"가 아니라 `측정 불가`로 보고한다.** 되돌아갈 곳이 프롬프트가 아니라 환경이다.

## 이 축의 본질은 정체성이다

"예쁜 캐릭터 한 장"은 쉽다. 어려운 건 **같은 캐릭터가 포즈·앵글·표정이 바뀌어도 같아 보이는 것**이다. 강도 순:

| 방법 | 강도 | 언제 |
|---|---|---|
| 시드 고정 | 약 | 같은 구도 변주만 |
| IP-Adapter / reference-only | 중 | 시안 단계, 세팅 쉬움 |
| **캐릭터 LoRA 학습** (시안 10~20장) | 강 | **양산 단계. 여기까지 가야 자동화다** — 아래 "정체성 고정" 절 |

## 생성 경로 두 가지 — GPU가 없어도 시작할 수 있다

| 경로 | 전제 | 정체성 고정 | 언제 |
|---|---|---|---|
| **로컬 ComfyUI** | GPU + 세팅 1~2시간 | **LoRA 학습까지 간다** | 양산 단계. 장당 비용 0, 사외 반출 없음 |
| **Codex 내장 `image_gen`** | Codex 세션. GPU·API 키 불필요 | 프롬프트·레퍼런스까지 | **시안 단계**, GPU 없는 환경, 빠른 탐색 |

**Codex 경로가 중요한 이유**: 이 스킬은 "아트 3축 중 유일하게 절차적 생성이 안 되는 축"이라
백엔드 세팅이 선행됐다. Codex의 내장 `image_gen`은 **투명 배경을 네이티브로 지원**하고
API 키가 필요 없어서, 그 선행 조건 없이 시안을 시작할 수 있다.

```
Codex 세션에서:  $imagegen 으로 시안 생성 (투명 배경 요청)
                 ↓ 생성물이 $CODEX_HOME/generated_images/ 에 떨어진다
                 ↓ **반드시 프로젝트 경로로 옮긴다** — 기본 경로에 두면 다른 세션이 못 찾는다
아래 결정론적 체인은 두 경로가 공유한다:
  cutout → sprite-normalize → rig-split/sheet-split → atlas-pack → style-score
```

- **알파가 깔끔하지 않으면 마젠타 배경으로 생성하고 `cutout --chroma "#FF00FF"` 를 쓴다.**
  마젠타는 자연스러운 아트에 거의 안 나오는 색이라 배경 판정이 애매해질 여지가 없다 —
  "흰 옷을 배경으로 오인해 먹는" 사고가 원천적으로 안 생긴다.
  마젠타에서는 `--feather 8` 정도가 맞다(실측: 기본 1.5에서 경계 번짐 112px, 8에서 16px).
- **정체성 고정이 필요해지면 로컬 경로로 옮긴다.** LoRA 학습은 CUDA 전제다 —
  Codex 경로로는 캐릭터 1종을 수백 장 양산할 때의 정체성 드리프트를 못 잡는다.
- 두 경로 중 무엇으로 뽑았는지 **manifest 에 기록한다**(출처·라이선스 칸). 나중에 재현·교체 근거다.

> **선행 사례**: 이 "생성은 모델이, 정리는 결정론적 스크립트가" 구조는 우리만의 것이 아니다.
> `agent-sprite-forge` 도 독립적으로 같은 결론에 도달했다 — *"스크립트는 창작 두뇌가 아니다.
> 에이전트가 비주얼·파이프라인 결정을 하고, 도구는 반복 가능한 픽셀·익스포트 작업만 한다."*
> 마젠타 크로마키도 거기서 널리 쓰이는 수법이다.

## 실행 (로컬 ComfyUI 백엔드가 떠 있을 때)

```bash
node <플러그인>/skills/char-art-system/scripts/comfy-run.mjs \
  <플러그인>/skills/char-art-system/references/workflows/sdxl-character.api.json \
  --out art/char --batch 8 --seed 1000 \
  --set 6.text="<프롬프트>"
```

- `--batch N` 으로 시안을 한 번에 N장. **시드는 자동으로 기록된다**(`run-log.json`)
- `--set <노드id>.<입력>=<값>` 으로 프롬프트·해상도·스텝을 바깥에서 바꾼다. 워크플로 파일은 안 건드린다
- 서버가 없으면 스크립트가 **`측정 불가`** 로 끝난다 — 실패로 처리하지 않는다
- **배치가 끝나면 모델을 자동으로 내린다.** SDXL 하나가 커밋 10GB 를 잡는다(실측 14.6GB → 4.4GB).
  연속으로 돌릴 때만 `--keep-loaded` 를 준다 — 그 경우 다음 배치가 모델 재로딩 90초를 아낀다.
- 작업이 다 끝났으면 서버도 내린다. 모델은 디스크에 남으므로 재다운로드는 없다.

워크플로는 `references/workflows/` 에 API Format 으로 둔다. 웹UI 에서 새로 만들었으면
**"Save (API Format)"** 으로 저장해야 한다(일반 Save 는 `/prompt` 가 400 으로 거부).

## 얼굴이 깨질 때 — 순서대로 본다

실측(2026-08-21, SDXL Base · RTX 5060)에서 얻은 순서다. **위에서부터 한다.**

| 순서 | 조치 | 비용 | 실측 효과 |
|---|---|---|---|
| 1 | **구도 고정** — 세로 프레임(832×1216) + "한 명을 크게" 프롬프트 | 0원 | **통과율 1/6 → 5/6** |
| 2 | **hires 2패스** — 잠재 1.5배 확대 후 denoise 0.4 재생성 | 0원, 시간 2배 | 얼굴 디테일 향상 |
| 3 | 특화 체크포인트 | 6.6GB | 아래 주의 참고 |

**1번이 압도적이다.** 얼굴이 깨지는 주된 이유는 모델이 나빠서가 아니라 **캐릭터가 작게 그려져서**다.
1024 정사각에 9마리가 격자로 들어가면 얼굴에 쓸 픽셀이 20~30px 뿐이라 눈을 그릴 수가 없다.
즉 **다중 피사체 문제와 얼굴 깨짐은 같은 문제**이고, 구도를 고치면 둘 다 낫는다.
`sprite` 라는 단어 자체가 스프라이트 시트를 부르므로 `full body portrait of one character,
large in frame` 쪽으로 쓴다.

### 주의 — 체크포인트를 바꾸면 프롬프트도 바꿔야 한다

Animagine XL 4.0 을 같은 프롬프트로 넣었더니 **캐릭터가 아니라 추상 무늬**가 나왔다. 확인한 것:
- 파일 정상(6.9GB · 텐서 2,514 · SDXL 구조) — 손상 아님
- v-prediction 가설도 틀림(강제했더니 회색 단색으로 더 나빠짐)
- 남은 유력 원인: **태그 학습 모델에 자연어 프롬프트**를 넣은 것. `flat cel shading` ·
  `clean readable silhouette` 같은 문구를 미니멀 벡터 스타일 지시로 해석한 것으로 보인다

교훈: **체크포인트는 프롬프트 문법과 한 세트다.** 태그 기반 모델(Danbooru 계열)로 바꾸려면
프롬프트도 태그식(`1girl, chibi, full body, simple background`)으로 다시 써야 하고, 그건
별도 튜닝 작업이다. 모델만 갈아끼우면 결과가 무너진다.

### 워크플로 JSON 주의

**API Format JSON 에 주석 키를 넣지 마라.** `_comment` 를 넣었더니 ComfyUI 가 노드로 해석해
`/prompt` 가 500 을 냈다. 설명은 옆에 `.notes.md` 로 둔다.

## 스프라이트 파이프라인 — 생성부터 아틀라스까지

전부 **커스텀 노드 없이, 의존성 0**으로 돈다. 순서대로 이으면 유니티에 넣을 규격 에셋이 나온다.

```bash
# 1) 시트 생성 — 여러 포즈를 한 장에 (아래 "왜 시트인가" 참고)
node comfy-run.mjs <워크플로>.api.json --style <profile.json> --out out --batch 2

# 2) 셀 분리 + 알파
node sheet-split.mjs out/<시트>.png --out cells --min 0.012

# 3) 규격 통일 — 캔버스·크기·발바닥 정렬
node sprite-normalize.mjs cells --out norm --canvas 512x768 --fit 0.86 --anchor bottom

# 4) 아틀라스
node atlas-pack.mjs norm --out atlas.png --trim --pad 2 --pot
```

낱장 캐릭터라면 2번 대신 `cutout.mjs` 로 배경만 지우면 된다. 리깅용으로 부위를 나누려면
`rig-split.mjs`, ControlNet 용 포즈 스켈레톤이 필요하면 `pose-skeleton.mjs`.

### 왜 "한 장에 여러 포즈"인가 — 정체성 때문이다

**한 장 안에서는 캐릭터가 유지된다.** 같은 디노이징 과정이라 모델이 스스로 일관성을 잡는다.
별도로 4번 생성하면 후드 모양이 바뀌고 없던 토끼귀가 생긴다(실측). LoRA 없이 정체성 문제를
상당 부분 우회하는 방법이라, 지금 구성에서 가장 실용적인 경로다.

주의:
- **정사각 캔버스(1216² 등)를 써라.** 가로로 긴 캔버스를 주면 12~16개 초소형 셀이 나와 못 쓴다
- **셀 수를 지정해도 안 지킨다.** 2x2 를 요청해도 7개가 나온다. 그래서 `sheet-split` 은 격자
  좌표를 가정하지 않고 연결 성분으로 찾는다
- **포즈는 지정할 수 없다.** 모델이 고른다. 걷기 8프레임 같은 특정 시퀀스는 이 방법으로 안 된다

### 각 단계에서 실제로 밟은 함정

| 단계 | 함정 |
|---|---|
| 배경 제거 | "흰색을 지워라"로 하면 **캐릭터의 흰 옷이 뚫린다.** 테두리에서 번져 들어가는 flood fill 을 쓴다 |
| 배경 제거 | 접지 그림자는 배경도 전경도 아니다. 단일 임계값으로 지우려 하면 캐릭터가 뚫린다 → **2단 임계값**(tol/soft)으로 반투명 처리 |
| 규격 통일 | 최근접 축소는 선을 끊는다. **면적 평균**으로 리샘플 |
| 규격 통일 | 반신 컷이 섞이면 잘못 확대된다 → 높이 비율로 **이상치 경고** |
| 아틀라스 | trim 없이 담으면 규격 통일로 생긴 빈 공간이 아틀라스를 절반 넘게 먹는다 |
| 아틀라스 | JSON 은 **좌상단 원점**, 유니티 Sprite Editor 는 좌하단이다. 안 뒤집으면 스프라이트가 어긋나 잘린다 |

### 프레임 애니메이션은 이 경로로 안 된다

실측으로 확인한 것:

| 방법 | 정체성(실루엣 IoU) | 포즈 제어 |
|---|---|---|
| img2img (denoise 0.35~0.5) | **0.87~0.90** | ✗ denoise 0.92 까지 올려도 자세가 안 바뀐다 |
| ControlNet OpenPose | 0.50~0.67 | △ **치비 지시가 인체 비율을 이긴다.** 치비를 빼야 포즈가 먹는다 |
| 시트 생성 + 분리 | 높음(한 장 안) | ✗ 모델이 고른다 |

레퍼런스 게임들(Royal Match·Royal Kingdom·Zen Match)은 프레임 스프라이트가 아니라 **Spine
스켈레탈 애니메이션**을 쓴다 — assets zip 에서 `.skel`/`.atlas` 가 73~134건 나왔다. 생성으로
프레임을 뽑는 대신 **한 장을 잘 만들어 뼈대에 물리는 쪽**이 현실적이다(`rig-split.mjs` 가 그 앞단).

## 정체성 고정 — 캐릭터 LoRA 학습

시트 생성은 우회다. 캐릭터 1종을 스킨·표정·포즈로 **계속** 양산해야 하면 LoRA 를 학습한다.
상세(설치·데이터셋 규칙·8GB 프리셋 근거·고르는 법): **[references/lora-training.md](references/lora-training.md)**

```bash
# 1) 데이터셋 — 채택본(알파 PNG) 10~20장 → 배경 합성·축소·중복 제거·캡션 → dataset.toml
node lora-dataset.mjs art/char/approved --out art/char/lora-ds --token gdt_hero --captions captions.json

# 2) 학습 — 8GB 프리셋(batch 1 · grad ckpt · TE 캐시 · fp8 · bf16). 에폭마다 저장
node lora-train.mjs art/char/lora-ds --name hero_v1 --base sdxl        # --dry-run 으로 설정만 먼저

# 3) 고르기 — 에폭 × 강도(0/0.6/0.8/1) × 포즈 프롬프트 4종 격자 한 장. 사람은 이것만 본다
node lora-eval.mjs --lora art/char/lora-ds/train --token gdt_hero --out art/char/lora-eval

# 4) 생성 — LoraLoader 워크플로. 프롬프트는 토큰으로 시작
node comfy-run.mjs references/workflows/sdxl-character-lora.api.json --set 10.lora_name=hero_v1-000007.safetensors \
  --set 10.strength_model=0.7 --set 10.strength_clip=0.7 --set 6.text="gdt_hero, winter coat, front view, ..."
```

지켜야 하는 것 세 가지:
- **캡션에는 그 장에서 변하는 것만**(포즈·앵글·표정). 머리색·옷을 쓰면 그 단어에 학습돼 토큰만으론 안 나온다
- **트리거 토큰은 사전에 없는 단어**(`gdt_hero`). `hero` 는 모델이 아는 개념과 섞인다
- **결과는 파일이 아니라 (에폭, 강도)다.** 마지막 에폭이 최선인 경우는 드물다. 격자에서 정체성이 붙는 가장
  이른 에폭·낮은 강도를 고르고, 그걸 manifest 에 적는다

학습기(sd-scripts venv)가 없으면 `lora-train.mjs` 는 **측정 불가**로 끝난다. ComfyUI 와 별도 설치다.
학습 중엔 ComfyUI 모델을 내려야 한다(SDXL 하나가 커밋 10GB — 둘이 같이 못 산다).

**실측(2026-09-03, RTX 5060 8GB):** 같은 캐릭터 13장 × 12반복 × 10에폭 = 1,560스텝, SDXL Base 1024px,
8GB 프리셋 그대로 → **31분 완주, 1.0초/스텝, OOM 없음.** 격자에서 LoRA 없는 행은 매번 다른 캐릭터, LoRA 행 10개는
전부 같은 캐릭터(머리·눈·의상·비율)에 포즈 프롬프트 4종이 다 먹었다. 채택: **에폭 8 @ 0.9 + 프롬프트에 후드 명시.**
빠진 요소(후드)는 강도를 올려 억지로 붙이지 말고 프롬프트로 말한다 — 강도 1.0 은 배경이 새기 시작한다.

### 모션 스프라이트 — LoRA + ControlNet 실측

같은 날 채택 LoRA 에 OpenPose(`sdxl-character-lora-openpose.api.json`) 를 얹어 스켈레톤 4종을 뽑았다.

| | LoRA 없이 ControlNet (8/21) | **LoRA + ControlNet (9/3)** |
|---|---|---|
| 정체성 | 후드 모양·귀·비율이 포즈마다 바뀜 | **4포즈 모두 같은 캐릭터** |
| 포즈 적중 | 4/4 | 3/4 (팔 올리는 cheer 가 idle 로 뭉개짐) |
| 배경 | 흰색 유지 | "hooded cape" 프롬프트가 눈밭·마을을 끌어옴 → 네거티브·강도 0.8 로 눌러야 한다 |

결론: **키프레임 포즈(idle·walk·attack 같은 정지 포즈) 는 이 조합으로 된다.** 걷기 8프레임 같은 연속 동작은
여전히 생성으로는 안 되고, 한 장을 잘 만들어 Spine 뼈대에 물리는 `rig-split` 경로가 답이다.

### 스타일 LoRA — 레퍼런스 화풍만 빌리기 (실측 2026-09-03)

레퍼런스 게임 초상화 70장(캐릭터 70종 × **1장씩**, WD14 자동 캡션)으로 스타일 LoRA 를 학습해 우리 캐릭터 LoRA 와
체인(`sdxl-character-lora-style.api.json`)으로 썼다. 상세 규칙은 `lora-training.md` 의 스타일 LoRA 절.

| 조합 | 결과 |
|---|---|
| 스타일 단독, 에폭 5 @ 0.7 | 굵은 외곽선·스티커 테두리·광택·장식 패턴 — **화풍이 옮겨졌다.** 사람 피부 유지 |
| 스타일 단독, 에폭 10~15 @ 1.0 | **피부가 비스킷 색, 흰 아이싱** — 레퍼런스의 "캐릭터가 쿠키다"까지 학습됨. 이건 IP 누출이라 쓰면 안 된다 |
| 캐릭터 0.9 + 스타일 0.5 | 정체성 유지 + 화풍 전이 + **배경이 흰색으로 돌아옴**(스타일 데이터가 전부 흰 배경) |
| 캐릭터 0.9 + 스타일 0.8 | 스타일이 캐릭터를 밀어냄. 얼굴이 레퍼런스 평균으로 |

누출의 원인은 캡션이었다. 태거 결과에서 `cookie` 계열 태그를 전부 지웠더니, "쿠키다"라는 **내용**이 캡션 대신
스타일 토큰에 붙었다. **내용 태그(food·cookie·gingerbread)는 남기고 IP 이름(작품명)만 지운다.** 그래야 비스킷 피부는
`cookie` 단어에, 그리는 법만 토큰에 남는다. 선택 기준: **이른 에폭(5~7) · 강도 0.5~0.7 · 캐릭터 LoRA 와 합 1.5 이하.**

v2(모든 캡션에 "gingerbread cookie character, biscuit-colored skin, food" 명시, 1,400스텝, 30분)로 재학습한 결과:
강도 0.7 에서는 에폭 5·10 모두 사람 피부 유지, 스티커 테두리·광택만 옮겨옴. 1.0 에서는 여전히 얼굴이 노랗게 기운다.
캡션이 대부분을 고치고, 나머지는 "0.7 이하" 규칙이 막는다.

### 그림이 구린 진짜 이유는 베이스 모델이었다 (실측 2026-09-03)

같은 시드·같은 LoRA·같은 4포즈로 세 조합을 비교했다(`sdxl-character-lora-style-hires.api.json`).

| 조합 | 결과 |
|---|---|
| SDXL Base + hires + 캐릭터 0.9 + 스타일 0.5 | 정체성 OK, 배경 흰색 OK. 얼굴 평면적, 앉기 포즈 뭉개짐 |
| **Animagine XL 4 + hires + 캐릭터 0.8** (태그 프롬프트) | **선·얼굴·손 전부 정리, 포즈 4/4, 흰 배경.** 다른 급의 그림 |
| Animagine XL 4 + hires + 캐릭터 0.8 + 스타일 0.5 | 위와 같으면서 외곽선·음영이 조금 더 또렷 |

- **SDXL Base 로 학습한 LoRA 는 Animagine 에 재학습 없이 얹힌다.** 구조가 같아서다. 강도는 0.1 낮췄다(0.9 → 0.8)
- 체크포인트를 바꾸면 **프롬프트 문법도 바꾼다.** Animagine 은 태그식(`masterpiece, best quality, 1girl, solo, chibi, white hair, red eyes, ...`).
  자연어를 넣으면 추상 무늬가 나온다(8/21 실측). 정체성 태그(white hair, red eyes)를 프롬프트에 같이 써도 된다 — LoRA 와 싸우지 않는다
- 학습 데이터(13장)가 SDXL Base 산출물이라는 한계는 남아 있다. 다음 캐릭터 LoRA 는 Animagine 으로 뽑은 시안으로 학습한다

### 캐릭터 LoRA v2 — 좋은 모델로 뽑은 데이터로 다시 학습 (실측 2026-09-03)

위 기준 조합으로 포즈·앵글·표정·소품을 바꿔 24장을 뽑고, 배경이 들어간 4장과 비율이 깨진 1장을 빼서 **19장**으로
Animagine XL 4 를 베이스로 학습했다(× 8반복 × 10에폭 = 1,520스텝, **32분**, 1.1초/스텝).

| | v1 (SDXL Base 데이터·SDXL Base 학습) | **v2 (Animagine 데이터·Animagine 학습)** |
|---|---|---|
| 실제 프롬프트(정체성 태그 포함)로 4포즈 | 안정적. 점프에서 후드 모양이 흔들림 | **후드 모양·다이아몬드 문양이 포즈마다 일정.** 선이 더 또렷 |
| 토큰만으로(정체성 태그 없이) 격자 | 4포즈 모두 같은 캐릭터 | 흰 머리·붉은 눈·망토는 오지만 **후드가 자주 벗겨짐**, 측면에서 Animagine 기본 취향이 섞임 |

토큰만으로 약해진 이유는 캡션이다. 19장 전부에 `hood up` 을 넣었는데, **전 장에 공통인 단어는 정체성인데도 캡션에 쓰면
토큰이 아니라 그 단어에 붙는다.** 실제 생성 프롬프트에는 `hood up` 이 들어가므로 실사용엔 문제가 없지만, v3 는 캡션에서
공통 특징을 뺀다(`lora-training.md` "전 장에 공통인 특징" 절).

**현재 기준 조합**: `animagine-xl-4.0` · 태그 프롬프트(정체성 태그 + `hood up` 포함) · hires 1.5× denoise 0.42 ·
캐릭터 LoRA **redhood_v2 에폭 8 @ 0.8** · 스타일 LoRA(ckstyle_v2 에폭 5) 0.5.

## 절차

1. **기준 확인** — `VISUAL_DESIGN.md` 의 팔레트·프로포션·금지 스타일을 프롬프트에 넣는다. 없으면 `art-direction` 부터.
2. **시안 배치 생성** — 한 캐릭터당 8~16장. 시드를 전부 기록한다.
3. **자동 스코어링** — 규격(캔버스·배경 순도·알파 여백) + 팔레트 정합 + 실루엣 판독성. 하위는 자동 탈락.
4. **사람 채택** — 상위 3장에서 1장. **이 한 단계는 남긴다** (취향·IP·톤은 사람 판단).
5. **정체성 고정** — 채택본으로 LoRA 학습(`lora-dataset` → `lora-train` → `lora-eval`)하거나 IP-Adapter 레퍼런스로 등록.
6. **변형 양산** — 표정·포즈·의상 변형. 프레임 시트가 필요하면 `sprite-pipeline` 으로 넘긴다.
7. **등록** — `asset-pipeline` manifest 에 **모델·시드·프롬프트·LoRA 버전**까지 적는다.

## 재현성 (이 축에서 제일 자주 깨지는 것)

생성물은 **모델 + 시드 + 프롬프트 + LoRA 버전** 이 없으면 다시 만들 수 없다. 6개월 뒤 스킨 하나 추가하려는데 원본 캐릭터를 재현 못 하면 처음부터 다시 그리게 된다.

manifest 에 반드시 남긴다:
```
checkpoint / lora(+가중치) / seed / sampler·steps·cfg / 프롬프트 원문 / 레퍼런스 이미지 경로
```

## 보고 (검증 리포트 5섹션)

- **증거**: 실행한 워크플로와 `prompt_id`, **시드·생성 장수·채택 기준**, 결과 경로
- **기준**: `VISUAL_DESIGN.md` 의 어느 항목과 대조했는지
- **공백**: 안 만든 변형(표정·앵글), 스코어링 못 한 항목
- **잔여 위험**: 정체성이 흔들릴 수 있는 변형 범위

## 하지 않는 것

- 톤·팔레트 결정 (`art-direction` 소관)
- 프레임 시트 정규화·아틀라스 (`sprite-pipeline` 소관)
- 실존 IP·타 게임 캐릭터를 모방한 생성 — 레퍼런스는 스타일 기준이지 복제 대상이 아니다
- 백엔드가 없는데 "대충 비슷한 결과"로 넘어가기 — 그건 `측정 불가`다
