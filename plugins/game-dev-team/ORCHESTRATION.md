# 오케스트레이션 가이드 (다양한 게임을 만드는 범용 팀)

오케스트레이터(메인 세션)가 역할 에이전트를 어떻게 조율하는지에 대한 플러그인 차원의 규칙.
각 프로젝트 `AGENTS.md` 또는 `CLAUDE.md`는 이 규칙을 그 프로젝트 맥락으로 구체화한 것이다. **최종 권위자는 항상 사람.**

## 1. 구조 — 허브-앤-스포크
```
        [사람 = 최종 권위자]  ← 게이트 승인
              │
        [오케스트레이터 = 메인 세션]
        ┌────┬────┬────┬────┬────┬──────────────┐
       pm designer dev  qa artist meta-economy-designer
```
- 에이전트는 **서로 직접 대화하지 않는다.** 결과는 오케스트레이터로 돌아오고, 오케스트레이터가 다음 역할로 전달한다.
- 오케스트레이터는 **직접 창작/구현하지 않는다.** 역할: 분배 · 게이트 확인 · 사람 보고.
- **대화형 단계는 위임하지 않는다.** `concept-discovery`(0단계)처럼 사람과 여러 턴 왕복하는 일은
  오케스트레이터가 직접 진행한다(서브에이전트는 1회 실행·반환이라 부적합).

### 에이전트가 스킬에 닿는 방식 — `skills:` 는 권한이 아니다
역할 파일의 `skills:` 는 **세션 시작 시 스킬 전문을 주입하는 목록**이고, 목록에 없는 스킬을
런타임에 부르려면 `tools:` 에 **`Skill`** 이 있어야 한다. 이걸 혼동해서 두 사고가 동시에 났다
(REVIEW.md B-7):
- `skills:` 를 "소유권 지도"로 써서 artist 가 매 호출마다 **799줄**을 작업과 무관하게 주입받았다.
- `Skill` 이 아무 역할에도 없어서, 아래 라우팅표가 공동 소유로 적은 **7건이 실제로는 호출 불가**였다.
  pm 은 `skills:` 자체가 비어 있어 소유 스킬 두 개를 아예 못 썼다.

**규칙**: `skills:` 에는 그 역할이 **항상** 쓰는 것만 넣고(현재 팀 전체 324줄), 나머지는 `Skill` 툴로
필요할 때 부른다. 아래 라우팅표의 소유권은 `scripts/validate-plugin.mjs` 가 기계로 대조한다 —
소유자로 적었는데 선주입도 `Skill` 도 없으면 검사가 실패한다.

## 3. 게이트 (사람 승인 없이 다음 단계 금지)
각 단계 산출물을 오케스트레이터가 게이트 조건과 대조한 뒤 **사람에게 보고하고 승인받는다.**
- 0→1 코어 확정 / 1→2 기획 게이트(근거 없는 수치 0·미결 명시·지표 정의)
- 3↔4 게임성 검증 루프(미달 시 기획 반환, **반복 예산 정함**)
  — **봇(`balance-sim`)과 사람(`playtest-capture`) 둘 다 필요하다.** 봇 지표만 충족이면
  판정은 조건부이고, [공백]에 "사람 실플레이 미실시"가 남는다. 봇은 승률·픽률·난이도 곡선을
  재지만 첫 인상·이해 실패·학습 곡선은 구조적으로 측정하지 못한다.
- **4→5 버티컬 슬라이스**: ④를 통과했다고 ⑤ 전면 착수로 가지 않는다. **최종 품질 기준을
  증명한 한 조각**(플레이 가능 + 아트·연출·사운드가 출시 수준)이 먼저다. 이게 없으면
  "재미는 검증됐는데 품질 바를 못 맞추는" 실패가 본구현을 다 끝낸 뒤에 드러난다.
  슬라이스 범위는 사람이 정한다(보통 1스테이지 또는 1런).
- 6 정확성(QA 판정) / 머지 승인
- 7 아트: `VISUAL_DESIGN.md`, asset manifest, visual-qa 증거 확인, **asset-budget 예산 대조**(실서비스)
- 8·9 경제(core 통과 후) / P1·P2 폴리싱 사인오프

### 게이트 모드 (프로젝트 규모에 맞게)
- **lean**(기본): 핵심 게이트만 — 코어 확정(0→1) · 게임성 검증(4) · 머지.
- **full**: 위 게이트 전부. 정식 프로젝트·출시 준비 단계에서 **명시적으로 선택**한다.
- **solo**: 게이트 없음. 게임잼/1회성 실험용 — 사람이 명시적으로 선택했을 때만.

**기본값이 lean인 이유**: 초기 게임 개발의 품질은 프로세스 엄격함보다 **이터레이션 횟수**에서
나온다. 게이트를 하나 더 세울 때마다 한 바퀴가 느려진다. 플레이테스트에서 RITE(3명→수정→3명)가
큰 테스트 1회를 이기는 것과 같은 이유다 — 싸고 빠른 루프가 먼저다.
`full`은 얻는 것(누락 방지)이 잃는 것(속도)보다 커지는 시점에 켠다: 팀이 여러 명이 됐거나,
출시·심의가 걸렸거나, 되돌리기 비용이 큰 결정이 남았을 때.

모드는 프로젝트 `AGENTS.md`/`CLAUDE.md`에 기록하고, 진행 중 변경하면 그 시점부터 적용한다.
**모드를 올리는 것도 게이트다** — 사람에게 왜 올리는지 보고하고 승인받는다.

**게이트 상태는 `docs/pipeline/state.json`(기계용)에, 통과 이력은 `PIPELINE_STATE.md`(사람용 장부)에 기록한다.**
게이트가 열리면 `openGates`에 추가하고, 사람이 승인하면 지운다. 이건 오케스트레이터의 책임이다 —
플러그인의 `SessionStart` 훅이 state.json을 읽어 다음 세션에 현재 단계와 대기 게이트를 자동으로
되살리므로, 갱신하지 않으면 세션이 바뀔 때 게이트가 통째로 증발한다. 형식은 `skills/pipeline-brief/SKILL.md`.

## 4. 보고 형식 (오케스트레이터 → 사람)
매 게이트에서 3줄 이내로: **① 무엇을 했나 ② 게이트 통과/미달(근거) ③ 다음 결정 필요 사항.**
장황한 과정 나열 금지 — 사람이 승인/반환만 빠르게 판단하게.

## 5. 검증 주장 무결성 — 안 돌린 검증을 통과로 말하지 않는다
이 플러그인의 전제는 "재미를 감이 아니라 데이터로 판정한다"다. 그런데 에이전트가 *"1000판 돌렸더니
승률 52%"* 라고 말하는 것과 실제로 돌린 것 사이에는 지금 아무 강제도 없다. 수치는 지어내기 가장
쉬운 형식이라, 이 구멍 하나가 게이트 전체를 장식으로 만든다.

**금지 3가지 — 모든 역할 에이전트에 적용된다.**
1. 실행하지 않은 검증을 통과로 보고하지 않는다.
2. 예전에 측정한 값을 이번 측정치인 것처럼 제시하지 않는다.
3. 관찰하지 않은 것을 "문제없음"으로 넘기지 않는다.

### 검증 리포트 5섹션
`balance-sim` · `playtest-capture` · `econ-sim` · `qa` · `pr-review` 의 **완료 보고는 이 형식을 따른다.**

| 섹션 | 들어갈 것 |
|---|---|
| **주장** | 판정 한 줄 (충족 / 미달 / 측정 불가) |
| **증거** | 실제 실행한 명령과 출력. 게임에서는 **시드 · 판수 · 대상 커밋**이 빠지면 증거가 아니다 |
| **기준** | 무엇과 비교했나 — 목표 지표의 출처(기획 문서 위치·줄), 이전 측정치면 그 커밋 |
| **공백** | 못 돌린 것·안 돌린 것. 이 칸이 비면 "전부 검증했다"는 주장이 된다 |
| **잔여 위험** | 통과했지만 남는 위험 |

### 게임 특유의 위조 패턴 (증거로 인정하지 않는다)
- **시드를 안 밝힌 승률** — 재현이 안 되면 다음 측정과 비교할 수 없다.
- **판수를 안 밝힌 "충분히 돌렸다"** — 30판과 3000판은 다른 주장이다.
- **오차 폭을 안 밝힌 구간 판정** — 판수만으로는 부족하다. 승률 100판이면 95% 구간이 ±9pp고,
  목표 구간이 20pp인데 오차가 ±9pp면 그 판정은 애초에 성립하지 않는다.
  하네스(`sim/run.mjs`·`econ-run.mjs`)가 구간을 자동으로 내므로, **손으로 적은 승률은
  그 자체로 의심 대상**이다.
- **표본 수를 안 밝힌 플레이테스트 결론** — "유저들이 좋아했다"의 1명과 15명은 다른 주장이다.
  5명은 사용성 이슈의 55~95%를 잡는다(분산이 크다) — 표본 수 없이는 커버리지를 말할 수 없다.
- **하네스가 읽은 밸런스 데이터의 커밋 ≠ 지금 코드의 커밋** — 다른 게임을 측정한 것이다.
- **목표 지표 없이 "괜찮아 보임"** — 기획 게이트에서 이미 반려됐어야 할 상태다.

### 미달과 측정 불가를 섞지 마라
증거를 못 만들었으면 판정은 **미달이 아니라 `측정 불가`** 다. 둘은 되돌아가는 곳이 다르다.

| 판정 | 뜻 | 되돌림 |
|---|---|---|
| 충족 | 목표 지표를 만족 | 다음 단계로 |
| 미달 | 측정했고 목표에 못 미침 | **기획**(수치 재조정) |
| 측정 불가 | 하네스가 없거나·안 돌았거나·시드가 안 잡힘 | **개발**(하네스 수리) |

측정 불가를 미달로 보고하면 멀쩡한 밸런스를 헛되이 흔들게 되고, 미달을 측정 불가로 보고하면
못 맞춘 밸런스가 통과한다. 어느 쪽도 사람에게 잘못된 결정을 시킨다.

## 6. 반복 루프 관리 (무한루프 방지)
- 3↔4(게임성)·8↔9(경제)는 반복 루프. **1회 조정 노브 최대 2개, 반복 예산 N회(기본 3)**.
- 예산 소진 시 사람에게 "계속/피봇/보류" 결정을 요청한다.

## 7. 병렬화 (선택)
독립적이고 잘 분해된 작업은 서브에이전트를 **한 번에 병렬** 스폰. 같은 파일을 만지는 작업은
`isolation: worktree`(developer)로 충돌 방지. 사소한 작업은 위임하지 말고 직접 처리(토큰 절약).

## 8. 범용성 원칙 (다양한 게임 대응)
- 장르/엔진 특화 내용은 에이전트/스킬에 하드코딩하지 않는다 — 프로젝트 `AGENTS.md`/`CLAUDE.md`가 담당한다.
- 새 게임은 `setup-game-team`으로 스택 감지 후 팀 규칙 생성부터 시작한다.
- **진행 중인 프로젝트는 ⓪부터 다시 돌리지 않는다** — `setup-game-team` 온보딩으로 현재 상태를
  진단해 올바른 단계로 중간 진입하고, 충족된 게이트는 근거와 함께 백필한다(진입 단계 판정 자체가
  사람 승인 게이트).
- 비주얼 기준은 프로젝트별 `VISUAL_DESIGN.md`로 분리하고, 플러그인에는 범용 절차만 둔다.

## 9. 레퍼런스 이식 트랙 (R) — 배포 빌드에서 뜯어 유니티로
경쟁작·레퍼런스 게임의 **데이터 구조를 실제로 돌려 보며** 배우는 트랙. 본 파이프라인(⓪~⑩)과
별개로 돌고, 산출물은 ①(기획)의 근거나 ③(프로토)의 입력으로 들어간다.

```
R0 합법성·목적 확인(사람)
 → R1 추출(resource-extract)
 → R2 데이터 정합성(port-parity)
 → R3 유니티 골격 → R4 데이터 이식(unity-port)
 → R5 실행 확인(컴파일 0 · 플로우 완주)
 → R6 재현 정합성(port-parity)
 → R7 에셋 교체(artist + qa)
```

- **R0은 스킵하지 않는다.** 목적(사내 리서치) · 취득 경로 · 기술적 보호조치 유무 · 배포 범위를
  사람에게 확인받는다. **암호화·DRM이 걸려 있으면 거기서 멈춘다** — 우회는 법무 확인 전 금지.
- **R2와 R6은 같은 스킬을 다른 시점에 쓴다.** R2(추출본이 온전한가)를 건너뛰면 R6에서 어긋났을 때
  데이터 문제인지 이식 문제인지 가릴 수 없다.
- **R5 ≠ R6.** "돌아간다"와 "맞다"는 다른 주장이다. 컴파일 0·콘솔 0이어도 보드가 틀릴 수 있다.
- **R7은 배포 경로로 나가기 전의 하드 게이트다.** 추출 원본 에셋이 프로덕션 경로에 하나도 없어야
  하고, `asset-pipeline` manifest의 출처·라이선스·승인 상태로 증명한다. 판정은 artist + qa.
- 이식 대상은 **데이터**(레벨 배치·난이도 곡선·팔레트)다. 원본 게임 코드를 디컴파일해 옮기지 않는다.
- 추출물은 `_reference/` 아래에만 둔다. R 트랙 산출물을 프로덕션 경로에 섞지 않는다.

R 트랙의 검증 보고도 §5의 5섹션을 따른다. 증거에는 **대상 빌드의 버전·해시, 도구 버전,
표본 시드·표본 수**가 들어간다 — 빠지면 다음 회차와 비교할 수 없다.

## 10. 아트 트랙 공동 컨트롤 — Claude Code + Codex 양쪽에서

아트는 **양쪽 하네스가 같이 컨트롤한다.** 한쪽에 넘기고 기다리는 게 아니다.
그게 가능한 이유는 하나다 — **아트 파이프라인이 결정론적이기 때문이다.**

```
같은 palette.json + 같은 spec → 재생성 → 같은 산출물
```

즉 **생성 산출물은 병합할 대상이 아니다. 재생성하면 된다.** 그래서 두 세션이 동시에 작업해도
충돌이 날 수 있는 건 정본 텍스트/JSON 몇 개뿐이고, 그건 git이 처리하고 게이트가 검증한다.

### 공동 컨트롤의 세 축

**① 같은 도구** — 아트 도구는 전부 의존성 0의 결정론적 Node 스크립트다. 모델이 결과를
만들지 않으므로 **어느 하네스에서 돌려도 같은 결과**가 나온다(미러 경로로 실측 확인).

**② 같은 판정 표면** — `scripts/art-gate.mjs` 하나로 아트 전체를 판정한다.
```bash
node <플러그인>/scripts/art-gate.mjs --init          # 프로젝트에 art-gate.json 생성 (커밋한다)
node <플러그인>/scripts/art-gate.mjs --out art-out   # CVD·오버플로·회귀·규격·예산 한 번에
```
CVD · 텍스트 오버플로 · 에셋 회귀 · 스타일 규격 · 텍스처 예산을 순서대로 돌려 **하나의 판정 +
5섹션 리포트**를 낸다. 리포트에 **어느 하네스에서 돌렸는지와 대상 커밋이 박힌다** — 두 세션의
판정을 비교할 수 있는 근거다. 종료 코드 `0`/`1`/`3`으로 CI 게이트도 된다.

각 세션이 도구를 따로따로 골라 돌리면 "어느 쪽 판정이 최신인가"를 사람이 추적해야 하고,
그건 결국 추적되지 않는다. **판정은 한 명령으로 모은다.**

**③ 정본은 한 곳** — 아래 파일 표. 동시에 고쳐도 되는 것과 안 되는 것이 갈린다.

### 하네스별로 실제로 되는 것 (2026-09 기준, 공식 스펙 확인)

| 컴포넌트 | Claude Code | Codex |
|---|---|---|
| 스킬 (아트 도구 전부) | O | **O** — `.codex-plugin`이 `"skills": "./skills/"`로 배선 |
| 역할 에이전트 6개 | O | **X** — Codex 커스텀 에이전트는 TOML이고 플러그인 배포가 미지원 |
| 훅 4종 | O | **X** — `hooks/hooks.json` 위치는 맞지만 경로가 `${CLAUDE_PLUGIN_ROOT}`이고 이벤트명이 Claude 체계 |
| `/gate` 커맨드 | O | **X** — 게이트 판정은 `art-gate.mjs` + `AGENTS.md`로 한다 |
| 에이전트 메모리 (`memory: project`) | O | X |
| 이미지 생성 | 로컬 ComfyUI 경유 | **내장 `image_gen`** (투명 배경 지원, API 키 불필요) |

**서로 강한 데가 다르다**: Claude Code는 게이트·훅·에이전트 배선이 있고, Codex는 **GPU 없이
이미지를 생성**할 수 있다. 그래서 공동 컨트롤이 분업보다 낫다 — 캐릭터 시안은 Codex가 뽑고,
게이트 판정과 상태 관리는 Claude Code가 하고, **도구와 판정 표면은 공유한다.**

### 무엇이 하네스 무관인가

아트 도구는 전부 **의존성 0의 결정론적 Node 스크립트**다. 모델이 결과를 만들지 않는다.

| 작업 | 실제로 누가 하나 | 하네스 의존 |
|---|---|---|
| UI·FX 생성 (`ui-kit-gen`·`fx-gen`) | Node 절차 생성 | 없음 |
| 레퍼런스 측정 (`ref-analyze`·`ref-classify`·`style-score`) | Node | 없음 |
| 스프라이트 정규화·아틀라스·컷아웃 | Node | 없음 |
| 판정 (`cvd-check`·`pseudo-loc`·`asset-baseline`) | Node + 종료 코드 | 없음 |
| 캐릭터 생성 | **로컬 ComfyUI + GPU** | 없음 |
| 아트 방향·팔레트 결정 | 에이전트 판단 | **있음** |
| 스펙 값 결정 (`ui-spec.json` 수치) | 에이전트 판단 | **있음** |
| 연출 구현 (`polish`) | 코드 작성 | **있음** |

### 하네스별로 실제로 되는 것 (2026-09 기준, 공식 스펙 확인)

| 컴포넌트 | Claude Code | Codex |
|---|---|---|
| 스킬 (아트 도구 전부 포함) | O | **O** — `.codex-plugin` 이 `"skills": "./skills/"` 로 배선 |

(`state.json` 주입 훅이 없다) 그리고 **감사 로그를 안 남긴다**(`SubagentStop` 훅이 없다).
그래서 아래 계약이 필요하다.

### 파일 표 — 동시에 고쳐도 되는 것과 안 되는 것

충돌은 **정본을 동시에 고칠 때만** 난다. 나머지는 재생성 가능하므로 충돌이 문제가 아니다.

| 파일 | 성격 | 동시 편집 |
|---|---|---|
| `palette.json` | **정본** — UI·FX 색의 유일한 출처 | **금지.** 한 세션이 고치고 커밋한 뒤 다른 쪽이 pull |
| `VISUAL_DESIGN.md` | **정본** — 톤 기준 | **금지.** 위와 같다 |
| `docs/pipeline/state.json` | **정본** — 게이트 상태 | **오케스트레이터만.** 훅 없는 세션이 고치면 상태가 갈라진다 |
| `PIPELINE_STATE.md` | **정본** — 게이트 이력 | 오케스트레이터만 |
| asset manifest `status` | **정본** — `approved` 승격 | artist만. 다른 세션은 승격을 **요청**한다 |
| `art-gate.json` | 정본(설정) | 드물게 바뀜. 바꾸면 양쪽이 같은 판정을 내게 커밋한다 |
| `ui-spec.json` · `fx-spec.json` | 작업본 | **자유.** 충돌나면 git이 처리(작은 JSON) |
| 생성 산출물 (PNG·manifest·아틀라스) | **파생물** | **병합하지 않는다 — 재생성한다** |
| `baseline.json` | 작업본 | 의도한 변경 후 다시 snap |

**핵심 규칙 두 개:**
- **`palette.json`을 고쳐야 하면 스펙에 hex를 박아 우회하지 마라.** 그 순간 팔레트가 정본이
  아니게 되고 톤이 조용히 갈라진다. 팔레트를 고치고 → `art-gate` 를 돌리고 → 커밋한다.
- **생성 산출물은 git 충돌을 해결하지 말고 재생성한다.** 결정론적이라 그게 항상 맞고 더 빠르다.
  프로젝트에 따라 파생물을 `.gitignore` 하고 스펙만 커밋하는 것도 좋다.

### 왕복 절차 (양쪽 다 같다)

**작업 시작 전**
1. `git pull` — 상대 세션의 정본 변경을 먼저 받는다.
2. `docs/pipeline/state.json` 의 `openGates` 를 읽는다. Claude Code는 훅이 주입하지만
   **Codex는 자동 주입이 없으니 직접 읽어야 한다.**
3. `art-gate.mjs` 를 한 번 돌려 **현재 상태를 확인한다.** 남이 깨놓은 걸 내가 깬 것으로
   오해하지 않으려면 이게 먼저다.

**작업 끝낸 뒤**
1. `art-gate.mjs --out <dir>` 로 판정한다. **미달이면 커밋하지 않는다.**
2. 5섹션 리포트(§5)에 **도구 출력을 그대로** 붙인다. 요약은 증거가 아니다.
3. 정본을 고쳤으면 커밋 메시지에 **무엇을 왜 고쳤는지** 적는다 — 상대 세션이 pull할 때 읽는다.
4. manifest `status` 승격이 필요하면 요청만 남긴다.

### 훅 없는 하네스의 증거 규칙

훅이 안 도는 세션은 §5 의 증거를 **손으로 채워야 한다.** 손으로 적는 칸이 늘면 위조 여지도
늘어난다 — 그래서 **도구 출력을 그대로 붙이는 것**만 증거로 인정한다.

- 판정 도구는 전부 리포트 + 종료 코드(`0` 충족 / `1` 미달 / `3` 측정 불가)를 낸다.
  **요약해서 옮겨 적지 말고 출력을 붙여라.** 요약은 증거가 아니다.
- 대상 커밋을 직접 적는다(`git rev-parse --short HEAD`). Claude 쪽 하네스는 자동으로 박지만
  여기선 안 박힌다 — 안 적으면 다음 회차와 비교할 수 없다.
- 게이트 상태를 자동으로 못 보므로, **작업 시작 전에 `state.json` 의 `openGates` 를 읽는다.**
  열린 게이트가 있으면 그게 이 작업과 무관한지 먼저 확인한다.
- 감사 로그가 안 쌓이므로, 무엇을 했는지 **인수인계 리포트가 유일한 기록**이다.
