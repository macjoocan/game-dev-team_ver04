이 스킬은 "느낌(game feel)"을 담당한다. 재미/밸런스(game-designer)·정확성/버그(qa)와 별개의 표현 레이어다.
소유: **artist(연출 디렉션) + developer(구현)**.

**"느낌이 좋은가"의 최종 판정은 사람이 한다** — 주관 축이기 때문이다. 그런데 연출에는
**느낌과 무관하게 틀린 것**과 **안전 문제**가 섞여 있고, 그 둘은 기계가 판정할 수 있다.
이 스킬의 도구는 그 부분만 맡는다.

## 연출 상수는 한 곳에 모은다 — `feel.json`

숫자를 코드에 흩뿌리면 일관성 검사가 불가능해진다. hit-stop 프레임·흔들림 진폭·이징·타이밍을
**하나의 표(feel bible)**에 모으고 코드가 그 표를 읽는다.

뼈대: `art-direction/references/starter-kit/feel.json` (복사해서 값만 바꾼다)

```json
{
  "fps": 60,
  "pace": { "actionIntervalMs": 700 },
  "reducedMotion": { "declared": true, "disables": ["flash"], "scales": { "shake": 0 } },
  "events": {
    "hit_light":    { "class": "hit", "weight": 1, "hitStopFrames": 3,
                      "shake": { "amplitudePx": 2, "durationMs": 80, "decay": "expo" },
                      "flash": { "durationMs": 50 }, "sound": "sfx_hit_light" },
    "button_press": { "responseFrames": 1, "easing": "easeOutQuad", "durationMs": 90 }
  }
}
```

- `class`로 이벤트 부류를 명시한다. **무게 비교는 같은 부류 안에서만** 의미가 있다 —
  "플레이어 피격"과 "적에게 강타"를 한 축에 놓으면 오탐이 난다(실제로 났다).
- `pace.actionIntervalMs`를 **프로젝트 실측값으로** 채운다. 이게 틀리면 예산 검사가 무의미하다.

## 도구 1 — 연출 상수 감사

```bash
node <플러그인>/skills/polish/scripts/feel-audit.mjs <feel.json> [--out dir]
```

**"느낌이 좋은가"는 판정하지 않는다.** 느낌과 무관하게 틀린 것만 본다.

| 판정 | 무엇 | 왜 미달인가 |
|---|---|---|
| **미달** · 무게역전 | 강한 쪽이 약한 쪽보다 피드백이 약하다 | 취향이 아니라 값이 뒤집힌 것이다 |
| **미달** · 예산초과 | 피드백 총 길이 > 액션 간격 × 0.6 | 다음 입력이 피드백에 묻혀 조작감이 망가진다 |
| **미달** · 접근성 | 모션 감소 경로가 없다 / 흔들림·플래시를 안 끈다 | 모션 민감·광과민 사용자에게 대안이 없다 (P2 필수) |
| 경고 | hit-stop·흔들림 범위 이탈, 이징 방향·일관성, 반응 지연, 사운드 누락 | 업계 관행 인용값이라 장르에 따라 다르다 |

**경고는 게이트를 막지 않는다.** 권장 범위는 절대 기준이 아니다 — 턴제면 hit-stop 상한이
무의미하고, 리듬 게임이면 반응 지연 기준이 훨씬 엄격하다. 어긋나는 이유를 한 줄 적으면 끝이다.

참고 범위(업계 관행): hit-stop 3~5프레임이 흔하고 40~80ms 대, 넓게는 3~12프레임(0.05~0.2초).
입력→반응은 100ms 아래면 즉각적으로 느껴지고 액션 게임은 더 낮게 잡는다.
피드백 총 길이 = hit-stop(게임이 멈추므로 직렬) + max(흔들림, 플래시)(병행).

## 도구 2 — 광과민성 플래시 안전 판정 **(안전 게이트)**

```bash
node <플러그인>/skills/polish/scripts/flash-check.mjs <fx manifest.json>
node <플러그인>/skills/polish/scripts/flash-check.mjs <프레임폴더> --fps 30 --loop
node <플러그인>/skills/polish/scripts/flash-check.mjs <시트.png> --frames 8 --fps 30
```

**이건 취향 문제가 아니다.** WCAG 2.3.1(Three Flashes or Below Threshold)은 1초 안에 3회를
넘는 플래시를 금지하고, 콘솔 플랫폼 심의도 같은 종류를 본다. 광과민성 발작은 실제로 사람을
해치므로 **미달은 출하 차단 사유로 다룬다.**

판정 기준:
- **플래시** = 상대휘도의 대립 변화(올랐다 내리거나 그 반대)가 최대치의 **10% 이상**이고
  **어두운 쪽이 0.80 미만**일 때. 둘 다 밝으면 면제.
- **1초 창 안에 3회 초과면 미달.** 루프 이펙트가 1초보다 짧으면 반복으로 실효 플래시율이
  올라가므로 그걸 반영해 계산한다.
- **면적 25% 이하면 면제 가능** — 단 시야 10도 기준이라 **화면상 크기를 아는 사람이 판단한다.**
  도구는 면적 비율만 내고 판정을 `조건부`로 둔다.
- **적색 플래시는 더 위험하다**(사람이 적색에 더 민감하다). 포화 적색이 관여하면 별도 경고하고,
  전용 도구(PEAT 등)로 다시 확인하라고 안내한다.

`fx-art-system`이 만든 이펙트는 manifest에 `frames`·`fps`·`loop`·`blend`가 있어 바로 검사된다.
이펙트는 보통 가산 합성이라 **배경 위에 얹은 결과**로 재며, 기본 배경은 어둡게 둔다
(가산 합성에서 대비가 가장 커지는 최악 조건). 실제 배경이 밝으면 `--bg`로 넣어 다시 돌려라.

- 고치는 방법: 플래시 횟수를 줄이거나 · 휘도 변화폭을 0.10 미만으로 낮추거나 · 영역을 줄이거나
  · **모션 감소 설정에서 그 이펙트를 끈다.**
- **에셋 단위 검사다.** 실제 화면에서는 여러 이펙트가 겹치고 카메라 흔들림·화면 전환이 더해져
  더 나빠질 수 있다. 최종 확인은 **실기기 녹화 + 전용 도구**로 한다.

## 2패스

### 1차 — 코어 연출 패스 (게임성 검증 통과 후)
목표: 핵심 액션이 "손맛" 나게. **최소한의 피드백만. 과설계 금지.**
- 입력→반응 피드백: 버튼·카드 배치·타격에 즉각적 반응.
- 타격감 기본기: hit flash, 유닛/화면 흔들림, 데미지 숫자 타이밍.
- 핵심 전환(씬/턴) 이징.
- **게이트(P1)**: 핵심 액션 각각에 눈에 보이는 피드백이 있는가(체크리스트 커버) ·
  `feel.json`이 존재하고 `feel-audit` 미달 0 · 사람 사인오프.

### 2차 — 파이널 연출 패스 (출시 전)
목표: 전체 완성도·일관성·성능·안전.
- 모든 UI 전환/상태 변화 애니메이션의 일관성.
- 전투 연출 완성(파티클·hit-stop·연출 리듬), 사운드 훅.
- **성능**: 목표 프레임 유지(연출이 프레임을 깎지 않는가).
- **접근성**: 모션 감소 옵션 실제 동작 · 색약 배려(`visual-qa`의 `cvd-check`).
- **게이트(P2)**: 프레임 목표 충족 · **`flash-check` 미달 0** · 모션 감소 옵션 제공 ·
  `feel-audit` 미달 0 · 연출 일관성 · 사람 최종 사인오프.

## 원칙
- 연출은 **가독성을 해치면 안 된다**(정보 전달 우선). 과하면 번다.
- 밸런스·로직을 바꾸지 않는다 — 연출은 표현 레이어(수치는 designer, 로직은 developer 소관).
- 타이밍·이징·강도 값은 `feel.json` 한 곳에 모은다. **코드에 따로 박아두면 감사가 장식이 된다.**

## 도구가 판정하지 않는 것
- **느낌이 좋은가.** 사람 사인오프가 P1·P2 게이트의 본체다.
- **선언과 구현의 일치.** 코드가 `feel.json`을 실제로 읽는지는 검사하지 않는다.
- **실제 프레임 유지.** 실기기 프로파일링 몫이다.
- **이펙트 밖의 플래시원.** 화면 전환·피격 시 전체 화면 flash·번개 배경은 검사 범위 밖이다.

## 산출물
- `feel.json`(연출 상수 정본), 구현, `feel-audit`·`flash-check` 리포트, 1차/2차 체크리스트 결과.
