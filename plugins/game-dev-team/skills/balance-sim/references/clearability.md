# 클리어 가능성 검사 계약

```bash
node skills/balance-sim/scripts/clearability-check.mjs sim/clearability.mjs --out clear-out
```

어댑터는 `PLACEHOLDER=false`와 `model()`을 내보낸다. 실제 게임 테이블을 읽어 아래 축을 제공한다. 가져오기·실행 실패, 잘못된 형식, 빈 모델은 측정 불가다.

| 필드 | 계약 |
|---|---|
| `supply` | 자원 이름별 획득 가능한 총량. 유한한 0 이상 수치 |
| `require` | `{id, needs: {자원: 소비량}}` 배열. 모든 행은 반드시 거치는 구간이며 소비량을 합산 |
| `locks` | `{id, needs: [선행 ID]}` 배열. 모든 선행 항목이 있어야 해제. 시작점은 빈 needs |
| `order` | `[선행 ID, 후행 ID]` 쌍 배열 |

축은 선택해서 제공한다. 미제공·빈 축은 공백에 남기며, 한 축도 측정하지 못하면 exit 3이다. 부분 검사 충족은 게임 전체의 클리어 가능성을 보장하지 않는다.

공급에 없는 자원, 미정의 잠금, 중복 ID, 잘못된 수치는 exit 3이다. 자원 부족이나 순환을 확인하면 exit 1이다. 정상적으로 검사한 축에 모순이 없고 잘못된 입력이 없으면 exit 0이다. 확인된 실패와 다른 축의 공백이 함께 있으면 실패를 보고하고 공백도 보존한다.

`require`는 소비 자원 계약이다. 재사용 키, 서로 배타적인 경로, 선택 보상, 시간에 따른 충전은 이 합계로 판정하지 않는다. 해당 축을 제외하고 적용 조건을 명시하거나 별도 검사 모델을 사용한다. 어댑터가 실제 데이터를 잘못 옮긴 경우와 사람의 체감 난이도는 자동으로 확인할 수 없다.

결과는 `clearability-report.md`와 `clearability.json`에 저장한다. 5섹션 보고서와 대상 어댑터·커밋을 남긴다. 사람 승인, 테스트 실행, 원본 데이터 매핑의 정확성을 대신하지 않는다.
