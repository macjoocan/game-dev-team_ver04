# 기존 프로젝트 온보딩 체크리스트

이미 개발이 진행 중인 프로젝트에 팀 파이프라인을 붙일 때의 진단표.
**증거가 있는 항목만 "있음"** — 파일 경로·커밋·실행 결과를 근거로 남긴다.

## A. 기획 상태
- [ ] 코어 루프가 한 문장으로 설명 가능한가 (core fantasy·30초 루프·실패 조건)
- [ ] 기획 문서(GDD·노트·이슈)가 존재하는가 → 경로:
- [ ] **게임성 성공 지표가 숫자로 정의**돼 있는가 (승률·런 길이·픽률 등) — 대부분 없음, 없으면 갭
- [ ] 밸런스 수치의 근거(의도)가 기록돼 있는가

## B. 코드 상태
- [ ] 실행/빌드 방법이 문서화돼 있고 실제로 되는가 → 명령:
- [ ] 전투/런 로직이 UI와 분리돼 있는가 (헤드리스 시뮬 가능 여부 — balance-sim 전제)
- [ ] 밸런스 수치가 데이터 객체/테이블에 모여 있는가, 코드에 흩어져 있는가
- [ ] RNG 시드 고정이 가능한가
- [ ] 테스트가 있는가 (단위/스모크/엔진 테스트) → 실행 결과:

## C. 검증 상태
- [ ] 재미에 대한 근거가 있는가 (시뮬 결과·플레이테스트 기록·유저 반응·지표)
- [ ] 자동 플레이/시뮬 하네스가 있는가
- [ ] 최근 빌드가 에러 없이 도는가 (콘솔/빌드 에러 0)

## D. 아트 상태
- [ ] 시각 기준 문서(`VISUAL_DESIGN.md` 또는 동등물)가 있는가
- [ ] 에셋 출처/라이선스가 추적되는가 (manifest 유무)
- [ ] 목표 화면비/최소 해상도에서 확인된 화면 증거가 있는가

## E. 운영 상태 (해당 시)
- [ ] 라이브 서비스 중인가 (스토어·서버) — 그렇다면 리텐션/경제 지표 접근 가능한가
- [ ] 수익화가 붙어 있는가 (가챠 확률 공개 등 컴플라이언스 확인 필요)

## 판정 가이드
- **B의 "헤드리스 시뮬 가능"이 없으면** ④(게임성 검증)에 진입하더라도 developer의
  분리 리팩터가 선행 태스크다 — 이것부터 태스크화한다.
- **A의 "게임성 지표"가 없으면** 어느 단계로 진입하든 game-designer의 지표 정의가
  병행 태스크다(①의 잔여분). 지표 없이는 ④ 게이트를 판정할 수 없다.
- C에 재미 근거가 하나도 없으면 코드가 아무리 많아도 ④부터다 — 본구현을 계속하기 전에
  재미를 데이터로 확인한다.
- 백필은 이 체크리스트의 증거 항목을 그대로 `PIPELINE_STATE.md` 근거 칸에 옮겨 적는다.
