## 파이프라인
0. 컨셉 발굴: core fantasy, 30초 루프, 실패 조건을 정한다.
1. 기획+게임성 지표: 숫자로 성공 기준을 정의한다.
2. 태스크 분해: PM이 작은 구현 단위와 게이트를 만든다.
3. 프로토타입: developer가 버려도 되는 최소 구현을 만든다.
4. 게임성 검증: balance-sim 또는 플레이 관찰로 목표 지표와 대조한다.
5. 본구현: 통과한 안만 정식 품질로 구현한다.
6. 정확성 QA: 회귀, 빌드, 로직 오류를 검증한다.
7. 아트/연출: artist 디렉션으로 P1 core polish를 적용한다.
8. 메타/수익화: core 통과 후 성장, 리텐션, 경제를 설계한다.
9. 경제 검증: econ-sim 또는 코호트 모델로 검증한다.
10. 출시 전 P2 polish: 최종 연출, 성능, 릴리즈 노트를 정리한다.

## 사람 승인 게이트
- 게이트 모드: <lean/full/solo> — lean=핵심 게이트만(코어 확정·게임성 검증·머지, **기본**), full=모든 게이트(정식·출시 준비 시), solo=게이트 없음(잼/실험).
- 게이트 통과 이력과 현재 단계는 레포 루트 `PIPELINE_STATE.md`에 기록한다.
- 0→1: 코어 확정.
- 1→2: 근거 없는 수치 0, 미결 명시, 핵심 수치 공란 0, 게임성 성공 지표 정의.
- 3↔4: 반복 예산 기본 3회, 1회 조정 노브 최대 2개.
- 5→6: 빌드/콘솔 에러 0, 테스트 가능 상태.
- 8→9: core 재미 통과 후에만 경제 검증 진입.
- 7 아트: `VISUAL_DESIGN.md`, asset manifest, 실제 화면 visual-qa 증거 확인.

## 아트/에셋 규칙
- 아트 제작 전 `VISUAL_DESIGN.md`로 팔레트, 실루엣, 카메라, UI 톤, 금지 스타일을 고정한다.
- 에셋은 stable ID, 승인 상태, 출처/라이선스, source/raw/final 경로를 manifest에 남긴다.
- 스프라이트는 seed frame 승인 후 시트/스트립으로 만들고 프레임 크기, 피벗, baseline을 통일한다.
- UI 아트는 HUD, 버튼, 카드, 아이콘, 상태/피해 숫자의 상태별 변형과 작은 화면 가독성을 확인한다.
- 3D 에셋은 scale, pivot, material, collision proxy, LOD, GLB/FBX export 기준을 정한다.
- visual-qa는 실제 게임 화면과 가장 작은 목표 화면에서 스크린샷 또는 preview sheet 증거를 남긴다.

## 역할 라우팅
- `pm`: 태스크 분해, 우선순위, 현황.
- `game-designer`: core 기획, 밸런스, 게임성 지표, balance-sim 해석.
- `developer`: 프로토타입, 본구현, 시뮬 하네스.
- `qa`: 정확성 검증, 회귀, 코드 리뷰.
- `artist`: 비주얼 방향, UI 톤, 에셋 파이프라인, 시각 QA, 연출 디렉션.
- `meta-economy-designer`: core 통과 후 성장/수익화/리텐션.
