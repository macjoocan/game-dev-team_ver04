# .claude/rules/ 템플릿 (게임 레포 · Claude Code용)

Claude Code는 `.claude/rules/*.md`를 자동 로드하며, frontmatter `paths:`의 glob과
일치하는 파일을 다룰 때만 해당 규칙을 적용한다(path-scoped). CLAUDE.md에 다 넣는
것보다 토큰 효율이 좋고 규칙이 필요한 순간에 정확히 뜬다.

아래 파일들을 프로젝트 경로에 맞게 수정해 게임 레포 `.claude/rules/`에 저장한다.
`<...>`는 실제 경로로 치환.

---

## core-logic.md — 전투/런 로직 규칙

```markdown
---
paths:
  - "<src/core/**>"        # 예: src/core/**, Game.Core/** 등 전투/런 로직 경로
---

# 코어 로직 규칙 (게임성 검증의 전제)

- 밸런스 수치(HP·데미지·계수·확률)를 이 경로에 하드코딩하지 마라 — 데이터
  테이블(<data/balance.json 등>)에서 읽는다.
- RNG는 시드 주입형만 사용한다. `Math.random()`/`Random.Range()` 직접 호출 금지 —
  balance-sim 재현성이 깨진다.
- UI·렌더·입력 코드를 참조하지 마라. 이 경로는 헤드리스로 실행 가능해야 한다.
- 기존 동작을 바꾸면 변경 이유와 함께 qa 회귀 확인 대상으로 표시한다.
- 업그레이드/버프처럼 수치를 변형하는 시스템은 **유효값 함수 하나**(예: `effDashCost(state)`)를
  만들어 로직과 UI가 같은 함수를 쓰게 한다 — 양쪽에 따로 계산식을 두면 반드시 어긋난다.
```

## balance-data.md — 밸런스 데이터 규칙

```markdown
---
paths:
  - "<data/**>"            # 밸런스 데이터 파일 경로
---

# 밸런스 데이터 규칙

- 수치 변경은 기획 게이트 소관이다 — 근거(기획 문서·시뮬 결과) 없이 수치를 바꾸지 마라.
- 스키마를 지켜라: 필드 추가/삭제는 로더 코드와 함께 변경한다.
- 변경 시 balance-sim 재검증이 필요한지 판단하고, 필요하면 게이트로 보고한다.
```

## ui-code.md — UI 코드 규칙 (선택)

```markdown
---
paths:
  - "<src/ui/**>"          # UI 코드 경로
---

# UI 코드 규칙

- 게임 상태를 UI가 소유하지 마라 — 코어 로직의 상태를 읽기만 한다.
- 밸런스 수치를 UI에서 재정의하지 마라(표시 포맷만 담당).
- `VISUAL_DESIGN.md`의 팔레트·톤 기준을 따른다.
```
