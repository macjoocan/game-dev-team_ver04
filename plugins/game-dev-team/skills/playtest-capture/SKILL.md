# 플레이테스트 캡처

`balance-sim`은 승률·픽률·난이도 곡선을 잰다. 그건 **밸런스 프록시이고 재미가 아니다.**
승률 45%, 런 8분, 픽률 고른 게임이 지루할 수 있다. 그리고 봇 승률 ≠ 사람 승률이다 —
봇은 규칙을 알고 시작하지만 사람은 배우면서 한다.

**이 스킬은 balance-sim 리포트의 `[공백]` 칸을 받는 짝이다.** 거기 "체감·연출·첫 인상은
사람 실플레이로 넘긴다"고 적히면, 넘어오는 곳이 여기다.

## 판정 규율은 balance-sim과 같다

| 판정 | 뜻 | 되돌릴 곳 |
|---|---|---|
| 충족 | 목표를 만족 | 다음 단계 |
| 미달 | 측정했고 목표에 못 미침 | **기획** (설계 재조정) |
| **측정 불가** | 표본이 부족하거나·프로토콜이 깨졌거나·빌드가 달랐다 | **표본 수집** (사람을 더 모은다) |

**1명 보고 "재밌다더라"는 통과가 아니라 측정 불가다.** 수치가 지어내기 가장 쉬운 형식이라면,
플레이테스트 결론은 **표본 수를 안 밝히기가 가장 쉬운 형식**이다. 같은 구멍이다.

## 1. RITE 루프 — 3명 → 수정 → 3명

Rapid Iterative Testing and Evaluation. 큰 테스트 1회보다 작은 테스트 여러 회가 이긴다.

```
3명 테스트 → 즉시 수정 → 3명 더 → 수정 → 3명 더
```

- **회차 사이에 반드시 수정한다.** 같은 빌드로 9명을 보는 건 RITE가 아니다. 고칠 수 있는
  문제를 놔두고 표본만 늘리면, 뒤 6명은 이미 아는 문제를 재확인하는 데 쓰인다.
- **반복 예산을 정한다**(기본 3회차). 3↔4 게임성 루프와 같은 규칙이다. 소진되면 사람에게
  "계속/피봇/보류"를 묻는다.
- 매 회차 **빌드 커밋**을 기록한다. 회차별로 다른 빌드를 본 것이므로, 커밋 없이 회차를
  합산하면 서로 다른 게임의 데이터를 섞는 것이다.

## 2. 표본 수 — 몇 명이면 되나 (정직하게)

5명이면 사용성 이슈의 **약 85%**를 찾는다는 게 통설이지만, **실제 분산은 55~95%**다.
표본을 늘리면 하한이 올라간다.

| 표본 | 발견 커버리지 | 쓸 곳 |
|---|---|---|
| 3명 | 낮음 (RITE 1회차용) | 명백한 막힘·크래시 |
| 5명 | 평균 85%, **최저 55%** | 1회차 판정에는 부족 |
| 10명 | 최저 80% | 회차 합산 기준선 |
| 15명 (5명×3회차) | 거의 전부 | 게이트 판정 |

- **리포트에 표본 수와 그에 따른 커버리지 주장을 함께 적는다.** "5명 테스트 결과 문제 없음"은
  "이슈를 최대 45% 놓쳤을 수 있음"과 같은 말이다.
- **유저군이 다르면 표본을 나눠 센다.** 5명 규칙은 동질 집단 전제다. 코어 게이머와 캐주얼을
  섞어 5명을 봤으면 각 군은 2~3명이고, 그건 어느 군에 대해서도 판정이 안 된다.
- 정량 지표(완주율·이탈률)를 주장하려면 표본이 훨씬 커야 한다 — `funnel-report.mjs`가
  95% 신뢰구간을 내니 구간 폭을 보고 판정해라.

## 3. 세션 진행 — think-aloud

플레이어에게 **하는 생각을 소리 내어 말하게** 하고, 진행자는 개입하지 않고 기록한다.
상세 절차·대본·기록 시트: `references/session-protocol.md`

지켜야 할 것 세 가지:
- **도와주지 않는다.** 막히는 지점이 데이터다. 힌트를 주면 그 데이터가 사라진다.
- **설명하지 않는다.** "이건 원래 이렇게 하는 거예요"를 말한 순간 이해 실패를 못 잰다.
- **묻지 말고 본다.** "재밌었나요?"는 예의상 "네"를 받는다. 행동(재시도 여부·이탈 지점·
  표정·욕설)이 응답보다 정확하다.

## 4. 척도 — 설문을 새로 만들지 않는다

검증된 척도를 쓰고 **어느 척도를 썼는지 리포트에 적는다.** 자작 설문은 비교가 안 된다
(회차 간·프로젝트 간·업계 벤치마크 간).

| 척도 | 재는 것 | 쓸 때 |
|---|---|---|
| **GEQ** (Game Experience Questionnaire) | 몰입·유능감·도전·긴장·부정정서·긍정정서 | 일반적 재미·체감 난이도 |
| **PENS** (Player Experience of Need Satisfaction) | 자율성·유능감·관계성 | 동기·지속 플레이 의향 |
| SUS | 사용성 | UI·조작 |

- 척도는 **회차 간 비교용**이다. 절대값 자체보다 수정 전후의 변화가 신호다.
- 자유 응답은 척도를 대체하지 않는다. 둘 다 받아라 — 척도는 방향, 자유 응답은 원인.

## 5. FTUE 퍼널 — 평균이 아니라 단계로 본다

**평균 튜토리얼 완료율은 쓸모가 없다.** 이탈은 단계별로 일어난다. 첫 퀘스트도 못 끝내는
이탈이 20% 수준으로 흔하다 — 그게 "튜토리얼 완료율 65%" 하나로 뭉개지면 어디를 고칠지 모른다.

```bash
node <플러그인>/skills/playtest-capture/scripts/funnel-report.mjs events.jsonl --steps steps.json
```

각 단계의 도달·통과·이탈을 95% 구간과 함께 낸다. 계측할 이벤트 목록·속성·세션1→2 전환:
`references/ftue-telemetry.md`

- **세션1 → 세션2 전환**이 D1 리텐션의 선행지표다. 첫 세션 안의 지표보다 이게 먼저다.
- 좌표가 있으면 사망·이탈 위치를 뭉치로 본다 — 뭉쳐 있으면 충돌 버그·과도한 난이도·
  동선 혼란 중 하나이고, 셋은 고치는 곳이 다르다.

## 6. 검증 리포트 (필수 형식)

ORCHESTRATION.md §5의 5섹션. balance-sim·econ-sim과 같은 형식이다.

```
[주장]      충족 / 미달 / 측정 불가 — 한 줄
[증거]      표본 수 · 유저군 구성 · 회차 · **빌드 커밋** · 사용한 척도 이름
            관찰 기록과 퍼널 출력. 표본 수·빌드가 없으면 증거가 아니다
[기준]      목표의 출처(기획 문서 경로·줄). 이전 회차와 비교했다면 그 커밋과 표본 수
[공백]      안 본 것 — 테스트하지 않은 유저군·플랫폼·구간. 표본 수로 인한 커버리지 한계
[잔여 위험] 통과했지만 남는 위험
```

### 증거로 인정하지 않는 것
- **표본 수를 안 밝힌 "유저들이 좋아했다"** — 1명과 15명은 다른 주장이다.
- **빌드 커밋 없는 회차 합산** — 회차마다 다른 게임을 본 것이다.
- **진행자가 힌트를 준 세션** — 이해 실패를 측정하지 못한 세션이다. [공백]에 적어라.
- **"재밌었나요?"의 응답** — 행동 데이터 없이 만족도만 있으면 그건 예의다.
- **자작 설문 점수** — 비교 대상이 없어 회차 간 변화를 말할 수 없다.

## 이 레포에서의 위치

- **소유**: game-designer. 파이프라인 ④(게임성 검증)의 **필수 동반 축**이다 —
  새 단계 번호를 만들지 않는다. balance-sim이 봇으로 재고, 이 스킬이 사람으로 잰다.
- ④ 게이트는 **둘 다** 있어야 통과다. 봇 지표만 충족이면 판정은 조건부이고, [공백]에
  "사람 실플레이 미실시"가 남는다.
- `polish`(연출)·`visual-qa`(보이는 것)와 다른 축이다. 여기선 **사람이 무엇을 했고 왜
  막혔는지**만 본다.
- 경제 축의 사람 검증(과금 의향·체감 공정성)은 `econ-sim`의 페르소나 가정을 보정하는 데 쓴다.
