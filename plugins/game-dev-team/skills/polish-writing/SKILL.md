두 축을 동시에 노린다.

1. **사람처럼** — "이거 AI가 썼네" 소리가 안 나오게.
2. **쉽게** — 누구나 **한 번 읽고** 이해하게.

> 내용을 요약하거나 의미를 바꾸지 않는다. **표현과 문장 구조만** 손댄다.
> **숫자·일정·대상·범위는 절대 빼먹지 않는다.** 짧게 만들다 사실이 사라지면 실패다.

## 절대 원칙 — 안전 교정 (가장 중요)

기획서는 사실관계가 핵심이다. 표현을 다듬다가 **없던 사실을 만들면** 게이트가 통째로 무너진다.
`gdd-completeness-checker`가 "근거 없는 수치 0"을 요구하는데 문체 정리가 수치를 지어내면
검수를 통과한 문서가 거짓이 된다.

- **원문에 없는 수치·근거·사례·일정·성과·인과관계는 새로 만들지 않는다.**
- 추상 표현을 구체화해야 하는데 근거가 없으면, 임의의 수치를 넣지 말고
  `[수치 확인 필요]` · `[근거 필요]`로 표시한다.
- 불확실한 내용을 단정하지 않는다. 단정형이 필요하면 `[확인 필요]`로 남긴다.
- 표현은 다듬되 **의도·논리·사실관계는 바꾸지 않는다.**

```
금지:  "충분한 가능성을 가지고 있다" → "30% 오를 수 있다"    ← 원문에 없는 수치를 지어냄
정답:  "충분한 가능성을 가지고 있다" → "가능성이 있다 [근거 필요]"
```

## 작업 범위 — 문체 교정 vs 재구성

- **기본은 문체 교정이다.** 어색함·장황함·번역투·AI 티만 손댄다.
- **요약·축약·구조 재배치·내용 재구성은 사람이 명시적으로 요청했을 때만** 한다.
- 요청이 없으면 문단 순서나 분량을 임의로 바꾸지 않는다.

## 쉬운 문장 6규칙

1. **짧게 나눈다** — 한 문장이 길거나 `그리고/및/하며`가 여러 번이면 두 문장으로.
2. **한 문장 한 메시지** — 한 문장엔 생각 하나만.
3. **능동태로** — "~에 의해 처리된다" → "서버가 처리한다". 누가 하는지 드러낸다.
4. **명사화를 동사로/개조식으로** — "개선을 도모한다" → "개선한다" 또는 "개선".
5. **쉬운 낱말로** — 한자어·전문어·번역투 대신 일상어.
6. **모호 수식어 제거** — "매우/상당히/다양한/여러" → 빼거나 **구체 수치**로.

이중부정("~하지 않을 수 없다")은 긍정으로("~해야 한다").

## 번역투·명사화·모호표현 교체표

| 어려움/번역투 | 쉬운 말 |
|---|---|
| ~에 의해 / ~에 의하여 | (능동) 누가 ~한다 |
| ~으로 인하여 | ~때문에 / ~라서 |
| ~을 통하여 | ~로 / ~을 써서 |
| ~에 대하여 / ~에 대한 검토 | ~을(를) / 검토한다 |
| ~되어지다 | ~된다 (이중 수동 제거) |
| ~하는 것으로 보인다 | ~로 보인다 / ~인 듯하다 |
| ~라고 할 수 있습니다 | ~입니다 (단정) |
| ~을 진행합니다 / 실시합니다 | ~합니다 / ~함 |
| 개선을 도모한다 | 개선한다 / 개선 |
| 매우 / 상당히 | (빼거나 수치) |
| 다양한 / 여러 가지 | 무엇무엇 (구체 명시) |
| 전반적으로 / 등등 | 범위·항목 명시 |

## AI 말투 교체 예시

| AI 말투 | 사람 말투 |
|---|---|
| 종합적으로 고려하였을 때 | 정리하면 / 결론은 |
| 효과적인 방안을 모색하여 | 방법을 찾아 |
| 지속적인 성장을 도모하기 위해 | 계속 성장하려면 |
| 상기 내용을 바탕으로 | (삭제하거나 "앞서 말한 것처럼") |
| 면밀한 검토가 필요합니다 | 검토가 필요함 |
| 도출하였습니다 | 나왔습니다 / 확인함 |

### 나쁜 예 (AI 말투의 특징)
- 수식어가 많고 문장이 길다. 본론 전 배경 설명이 길다.
- 뻔한 맥락 서술("상기 내용을 바탕으로"), 과한 격식체.
- 추상어 남용("활성화", "도모", "모색").
- **과교정도 나쁘다** — 툭툭 끊기는 punchy 문어체로 바꾸면 오히려 더 딱딱해진다.
  사람처럼 = 자연스러운 실무체이지, 세고 짧게가 아니다.

## 팀 문체 모드 (프로젝트별 설정)

팀마다 기본 톤이 다르다. **프로젝트 `CLAUDE.md`에 팀 문체가 정의돼 있으면 그것을 우선 따른다.**
정의가 없으면 문서 성격으로 판단한다 — 사내 실무 문서는 개조식, 대외 문서는 정중체.

한국어 게임팀에서 흔한 **개조식 + 음슴체** 톤의 예시(원하는 팀만 쓰면 된다):

- 서술 항목은 **명사형** 또는 **~음 / ~함 / ~중**으로 끝낸다 (`~습니다`·`~한다` 지양).
- 진행 상태 = **~중**. 가능성·검토 = **~할 수 있는지 / ~여부**.
- 담백하게, 수식 최소. **구조화 우선**(표·불릿). 근거·성과는 **수치**로.
- 팀 실무어(공수·리소스·챕터·지표·납품 등)는 바꾸지 말고 그대로 둔다.

| 정중/신문체 | 개조식 실무 톤 |
|---|---|
| 반복 작업을 효율화하고 있습니다 | 반복 작업 효율화중 |
| 이 프로젝트는 자동화를 적용하지 않는다 | 이 프로젝트는 자동화 적용 없음 |
| 시간을 절약할 수 있는지 검토가 필요하다 | 시간을 절약할 수 있는지 (여부) |
| 데이터를 자동으로 정리해 보고 시간을 줄여준다 | 데이터 자동 정리 → 보고 시간 절약 |

> 대외·사업 공유 문서는 정중체가 맞다. 이 모드는 **사내 실무 문서** 기본 톤으로만 쓴다.

## 작업 방식

1. **전체를 먼저 읽고** 흐름·의도를 파악한다.
2. **문서 성격 판단** — 사내 실무/기획서면 개조식, 대외·사업 공유면 정중한 서술.
3. **섹션 성격 판단**(요약/기능/지표/시장/결론).
4. 규칙과 교체표로 다시 쓴다 — **의미·숫자는 보존**.
5. **변경 요약**을 1~2줄로 안내한다.

### 섹션별 가이드
- **요약**: 2줄 이내, 숫자로 시작, "왜 중요한가" 한 줄.
- **기능**: "무엇을 한다"만. 배경 설명 불필요.
- **지표/KPI**: 숫자 + 측정 방법만.
- **시장·레퍼런스**: 출처 + 숫자 + 날짜, 코멘트 1줄.
- **결론**: 행동 지향으로 끝냄.

### (선택) 3버전 모드
"여러 버전"을 원하면: **짧은 버전**(핵심만) / **공식 버전**(보고·대외용) / **읽기 쉬운 버전**(가장 평이하게).

## 출력 형식
```
[다듬은 텍스트]

---
💡 주요 변경: [무엇을 왜 바꿨는지 1~2줄]
```
바꿀 게 거의 없으면 "이미 쉽고 자연스럽다"고 말해도 된다.

## 하지 말아야 할 것
- 내용 요약·생략 (표현·구조만 바꾼다)
- 의미 변경, **숫자·일정·대상·범위 누락** (사실 보존이 최우선)
- 밸런스 수치·결정사항 손대기 — 문체 정리 중 수치가 바뀌면 기획 게이트가 무너진다
- 불필요한 설명 추가, 원문보다 길어지기 (보통 짧아져야 한다)
