# 선택적 2D 캐릭터 포즈·레퍼런스 파일럿

**범위:** 승인 전 콘셉트에서 서로 다른 동작 포즈의 정체성이 유지되는지 확인한다. 두 프레임은 애니메이션 시트, 런타임 에셋, 양산 방법의 검증이 아니다. `asset-pipeline` manifest 상태를 `concept`로 유지하고 사람 승인 전에는 프로덕션에 넣지 않는다.

## 시작 조건과 설정

프로젝트마다 아래 값을 명시한다. 경로는 프로젝트 루트 기준으로 기록하고, 환경에 설치된 모델 파일명은 실제 파일과 대조한다. 이 문서는 특정 프로젝트의 Python 스크립트나 ComfyUI 노드 JSON을 플러그인에 복사하지 않는다.

| 설정 | 역할 |
|---|---|
| 프로젝트 루트·출력 폴더 | 산출물과 manifest의 소유 위치 |
| ComfyUI 주소·버전·실행 옵션 | 재실행 환경 (`--lowvram` 여부 포함) |
| 체크포인트·스타일 LoRA·OpenPose ControlNet·IP-Adapter·이미지 인코더 파일명 | 실제 로드할 모델. 각 파일의 SHA-256과 출처를 manifest에 기록 |
| 승인된 캐릭터 레퍼런스 경로 | 포즈 간 정체성 기준. 미승인 생성 프레임이면 파일럿 상태에서 멈춤 |
| 포즈 PNG 폴더와 프레임 순서 | 프레임별 OpenPose 입력. 공통 캔버스·발 기준선을 명시 |
| 시드·긍정/부정 프롬프트·캔버스 크기 | 재현 가능한 생성 입력 |
| IP-Adapter 가중치·적용 구간 | 정체성 제어 입력. `0.75`는 한 파일럿의 출발값이지 기본 승인값이 아님 |
| 내보내기 크기·게임 표시 크기·배경 | 최종 판독성 검사 조건 |

예시 파일럿은 512px 캔버스의 포즈 2장과 128px 게임 표시 크기를 썼다. SDXL Base 1.0, Pixel Art XL LoRA, SDXL OpenPose ControlNet, IP-Adapter Plus와 ViT-H 인코더를 8GB VRAM의 ComfyUI `--lowvram` 환경에서 사용했다. 이 조합을 다른 캐릭터의 통과 기준으로 일반화하지 않는다.

## 단계별 작업

1. **포즈 작성:** 동작별 OpenPose 스타일 PNG를 같은 캔버스와 기준선으로 만든다. 프레임 순서와 각 포즈의 목적을 기록한다.
2. **생성:** 각 포즈를 고정 시드·프롬프트로 따로 생성한다. 첫 프레임을 캐릭터 레퍼런스로 쓸 때는 그 프레임의 승인 상태를 확인한다. IP-Adapter를 추가한 비교 실행에서는 포즈와 의상·시선 방향을 함께 본다. 포즈가 맞아도 정체성이 바뀌면 채택하지 않는다.
3. **알파 정리:** 거의 단색인 배경에서만 테두리 대표색과의 거리로 전경을 잡고 가장 큰 연결 성분을 남길 수 있다. 테두리색이 변하거나 그림자·장비가 분리된 경우 이 방법의 결과를 신뢰하지 않는다. 수동으로 가장자리, 그림자, 분리된 장비를 확인하고 수정한다.
4. **규격·내보내기:** RGBA 프레임의 하단 경계와 피벗을 맞추고 시트로 묶는다. 도트 격자를 의도한 파일럿이면 최근접 축소를 쓸 수 있지만, 일반 일러스트에는 `sprite-normalize`의 면적 평균 축소가 더 적합할 수 있다. 어느 필터를 썼는지 남긴다.
5. **검수·승인:** 실제 게임 배경 위 실제 표시 크기로 일반/1px 어두운 외곽선 버전을 함께 본다. 장비 실루엣, 방향, 의상, 알파 경계, 접지, 행동 읽힘을 사람에게 확인받는다. `sprite-qa`는 정합성 근거로만 쓰고, 2장으로 타이밍·연속성을 통과 처리하지 않는다. 산출물은 `review-loop`에 `concept` 상태로 등록하고, 사람의 승인 전에는 manifest를 승격하지 않는다.

각 단계의 원본 입력과 출력은 분리한다. 생성 결과를 다시 돌리더라도 알파 수정을 덮어쓰지 않게 하고, 승인된 레퍼런스를 새 생성물로 조용히 바꾸지 않는다.

## 산출물 옆에 남길 증거

- 안정 에셋 ID, `concept` 상태, 소유자, 원본·포즈·레퍼런스·RGBA·시트·프리뷰 경로.
- 긍정/부정 프롬프트, 시드, 포즈별 API 그래프, ComfyUI 버전, 커스텀 노드의 upstream revision.
- 모델 파일명·크기·SHA-256·출처와 도구/모델별 라이선스 검토 기록. 외부 워크플로의 라이선스가 불명확하면 아이디어만 참고하고 파일을 복사하지 않는다.
- 참고 파일럿의 manifest에는 IP-Adapter Plus 노드가 GPL-3.0으로 기록돼 있고, 사용한 모델 저장소의 표기는 Apache-2.0이다. 공유 파이프라인에 포함할 때는 각각의 배포 조건을 다시 확인한다. 라이선스 표시가 없는 공개 워크플로는 복사하지 않는다.
- 알파 추출 방식과 임계값, 프레임별 bounds·기준선 보정량, 축소 필터, 표시 크기, 배경 프리뷰.
- 생성 시간은 환경 정보와 함께 측정치로만 기록한다. 한 파일럿의 20.8초·8.2초를 성능 보장으로 쓰지 않는다.
- 시각 QA 결과와 미해결 사항. 장비 표현, 알파, 동작 연속성, 실제 게임 삽입 여부를 각각 적는다.

## 통과 범위

이 파일럿에서 레퍼런스 적용 후 방향과 의상색 일관성은 개선됐고, 1px 외곽선은 배경 분리를 조금 개선했다. 그래플링 팔의 표현은 약했고, 투명 경계·그림자는 수동 정리가 필요했다. 공격 타이밍, 8–16프레임 연속 동작, 실제 게임 삽입은 검증하지 않았다. 양산 전에는 승인된 캐릭터 기준 이미지가 필요하며, 필요하면 캐릭터 LoRA나 수작업 보정을 검토한다.

관련 판정: `sprite-pipeline`은 프레임 정합, `visual-qa`는 실제 크기·배경 판독성, `asset-pipeline`은 상태와 출처, `polish`는 애니메이션 타이밍을 맡는다.

## ComfyUI 실행 전 검사와 수동 수정

API Format 그래프를 저장한 뒤 서버를 켜고 아래 검사를 먼저 실행한다. `/object_info`에 노드와 모델 선택지가 있는지 확인하고, 모델 manifest를 주면 로컬 파일의 크기와 SHA-256도 확인한다. 해시는 1MB씩 읽어 8GB 환경에서 대형 모델 전체를 메모리에 올리지 않는다.

```bash
node skills/char-art-system/scripts/comfy-preflight.mjs graph.api.json --host 127.0.0.1:8188 --model-manifest models.json --model-root D:/ComfyUI/ComfyUI_windows_portable
node skills/char-art-system/scripts/comfy-run.mjs graph.api.json --out concept-out --seed 42 --model-manifest models.json --model-root D:/ComfyUI/ComfyUI_windows_portable
```

`models.json`은 `{"models":[{"name":"모델파일.safetensors","path":"ComfyUI/models/checkpoints/모델파일.safetensors","bytes":실제바이트수,"sha256":"실제 SHA-256 64자리"}]}` 형식이다. 경로는 `--model-root` 기준 상대 경로다. 파일명·경로·크기·해시는 해당 설치에서 확인한 값만 기록한다. 실행 결과의 `graph-s<seed>.api.json`과 `run-log.json`은 실제 제출 그래프, 시드, 프롬프트, 모델 해시, 출력 파일을 연결한다. 사전 검사는 노드 설치와 모델 파일을 확인할 뿐, 이미지 품질이나 라이선스 승인을 대신하지 않는다.

수동 수정은 원본 PNG와 별도 파일로 남긴다. Krita AI Diffusion([공식 저장소](https://github.com/Acly/krita-ai-diffusion))이나 Pixelorama([공식 저장소](https://github.com/Orama-Interactive/Pixelorama))는 선택 가능한 편집 도구다. 작은 게임 크기에서 장비의 형태, 투명 경계, 그림자, 픽셀 격자를 사람이 고친 뒤 원본·수정본·실제 배경 미리보기를 `review-loop`에 함께 등록한다. 승인 전 상태는 계속 `concept`다. 외부 도구와 모델을 공유 패키지에 넣기 전에는 각각의 라이선스와 배포 조건을 검토한다.
