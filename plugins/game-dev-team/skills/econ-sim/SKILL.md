이 스킬은 "경제가 성립하는가 / 공정한가 / 지속 가능한가"를 감이 아니라 데이터로 검증한다.
소유자는 meta-economy-designer, 시뮬 하네스는 developer가 만든다.
전제: core 게임성(balance-sim)이 이미 통과한 상태여야 의미가 있다.

> **수익화 전이라도 성장 시스템이 붙으면 경제 축이다.** 영구 업그레이드·해금 같은 재화 싱크를
> 추가할 때는 "핵심 페이싱 지표 = 첫 구매까지 N런 / 완주까지 N런"을 실측한다:
> 실제 봇으로 무강화/풀강화 수입을 측정 → 탐욕 구매 진행 시뮬로 런 수 곡선을 뽑는다
> (중간 상태를 보간했다면 <추정> 명시). 싱크 없는 재화는 인플레 — 온보딩 진단에서 갭으로 잡는다.

## 절차

### 1. 경제 성공 지표 확인
기획(AGENTS.md/CLAUDE.md 경제 지표 섹션·경제 원장)에서 목표를 가져온다. 없으면 meta-economy-designer에게 요청.
전형적 지표:
- 리텐션: D1 / D7 / D30 목표 구간
- 무과금 진행: F2P 코호트의 핵심 콘텐츠 완주율·소요 시간
- 재화 수지: 소스−싱크 균형(인플레이션/디플레이션 상한)
- 가챠: 목표 획득까지 기대 시행·천장 도달률, 확률 공개 일치
- 수익화: 전환율(payer %), ARPPU/ARPDAU, (참고)LTV
- 광고: 시청율·빈도 상한 준수, 보상 밸런스

### 2. 시뮬 하네스 구성 — **처음부터 만들지 않는다**

```bash
node <플러그인>/skills/econ-sim/scripts/econ-scaffold.mjs --out econ-sim
```

`balance-sim`의 `sim/`과 같은 계약 방식이고 통계 층(`lib-stats.mjs`)·시드 층(`rng.mjs`)을 공유한다.

| | 소유 |
|---|---|
| `simulatePlayer({ rng, config, persona, days })` | **프로젝트** — 경제 로직 |
| 코호트·시드·집계·신뢰구간·공정성 판정·리포트 | 스캐폴드 |

생성물: `econ-run.mjs` · `personas.mjs` · `economy.mjs`(계약 스텁) · `econ-targets.mjs` ·
`lib-stats.mjs` · `rng.mjs` · `README.md`.

- `economy.mjs`의 `PLACEHOLDER`가 `true`인 동안 판정은 무조건 `측정 불가`다.
- 재화 소스(플레이 보상·미션·광고)와 싱크(강화·가챠·상점)를 원장으로 모델링한다.
- 가챠는 시드 고정 RNG + 천장 규칙. 리텐션은 이탈 확률 곡선.
- balance-sim의 전투 결과(진행 속도)를 입력으로 연결하면 정확도가 올라간다.

### 3. 페르소나별 실행 — **평균 1명을 시뮬하지 않는다**

```bash
node econ-sim/econ-run.mjs --seed 7 --cohort 10000 --days 30
node econ-sim/econ-run.mjs --seed 7 --cohort auto --margin 0.02   # 목표 오차에서 코호트 역산
node econ-sim/econ-run.mjs --seed 7 --ab upgradeCostGrowth=1.15   # 원장 수치 A/B (공통 난수)
```

**"평균 플레이어"는 존재하지 않는다.** 무과금 그라인더와 과금자는 같은 경제 안에서 완전히
다른 곡선을 그린다. 평균으로 뭉개면 그 격차가 사라지고, 이 스킬의 핵심 게이트 질문인
**"무과금도 합리적 시간 안에 완주 가능한가"** 에 답할 수 없다.

`personas.mjs`의 페르소나(무과금/소과금/하이브리드/고래)마다 코호트를 따로 돌린다.
각 페르소나는 행동 파라미터의 묶음이다 — 세션/일, 광고 시청률, 주당 과금액, 인내도, 기본 이탈률.
**페르소나 파라미터는 가정이고, 하네스는 그 가정이 맞는지 검증하지 못한다.** 라이브 데이터가
있으면 대조해 보정해라.

### 4. 리포트 (목표 대비) — 공정성이 기계 판정된다
`econ-run.mjs`가 자동으로 판정하는 것:

| 판정 | 무엇을 보나 |
|---|---|
| 무과금 완주율 | F2P 코호트가 핵심 콘텐츠를 끝내는 비율 (95% CI) |
| 무과금 완주 소요 | 완주까지 중위 일수. **완주자가 0이면 페이월이다** |
| 무과금 진행 막힘 | 재화가 없어 진행 못 한 일수 비율 |
| **페이투윈 격차** | 최다 과금 페르소나 / 무과금 진행도 비율. 상한 초과 = 같은 게임이 아니다 |
| D1 리텐션(가중) | 페르소나 비중으로 가중한 전체 지표 |
| 재화 수지 | 획득 − 소비. 계속 쌓이면 싱크 부족(인플레) |

경보 플래그: 무과금 진행 막힘(페이월), 재화 인플레 폭주, 가챠 천장 미도달률 과다,
D7 급락, 특정 세그먼트 의존 과다, **다크패턴/확률 불일치**.

종료 코드로 CI 게이트를 걸 수 있다: `0` 충족 · `1` 미달 · `3` 측정 불가.

### 5. 판정 & 되돌림
미달·불공정·컴플라이언스 위반이면 "어떤 수치를 얼마로" 조정 가설과 함께 기획으로 반환.
임의로 수치를 고치지 않는다.

## 검증 리포트 (필수 형식)
"D7 리텐션 38%"는 **지어내기 가장 쉬운 형식**이다. 그래서 완료 보고는 5섹션을 전부 채운다.
한 칸이라도 못 채우면 그건 통과가 아니라 **측정 불가**다 (ORCHESTRATION.md §5).

```
[주장]      충족 / 미달 / 측정 불가 — 한 줄
[증거]      실행한 명령 그대로 + 출력 요약
            예) node econ-sim/run.mjs --seed 7 --cohort 10000 --days 30
            시드 · 판수 · 대상 커밋이 없으면 증거가 아니다
[기준]      목표 지표의 출처(문서 경로·줄). 이전 측정치와 비교했다면 그 커밋
[공백]      안 돌린 것 · 못 돌린 것 (빈칸이면 "전부 검증했다"는 주장이 된다)
[잔여 위험] 통과했지만 남는 위험
```

- 코호트 크기와 시뮬 일수를 안 밝힌 LTV·리텐션 수치는 증거가 아니다.
- **오차 폭도 밝힌다.** 코호트 400명의 D7 38%는 구간이 33~43%다 — 목표가 30~40%면 그 판정은
  성립하지 않는다(측정 불가). `econ-run.mjs`가 95% 구간을 자동으로 낸다.
- 확률·천장 검증은 **실측 분포**를 붙인다. 설계값을 그대로 옮겨 적는 건 검증이 아니라 인용이다.
- 측정 불가면 기획이 아니라 developer(하네스)로 되돌린다.

### 시뮬로 판정되지 않는 것 (반드시 [공백]에 남긴다)
- **컴플라이언스.** 확률 공개(한국 등 법적 의무)·미성년 지출 보호는 사람이 확인한다.
  출시 전 실제 법률 검토가 필요하다 — 하네스는 변호사가 아니다.
- **다크패턴.** 강제 FOMO·미끼 확률·손실 회피 악용은 수치가 아니라 설계 리뷰 대상이다.
- **페르소나 파라미터의 타당성.** 가정이 틀리면 곡선 전체가 틀린다.
