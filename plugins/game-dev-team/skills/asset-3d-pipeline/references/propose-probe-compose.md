# 후보 비교로 정하기 (Propose → Probe → Compose)

고칠 방법이 여러 개일 때 하나를 바로 고르지 않는다. 후보 2~3개를 **같은 조건**으로 돌려 보고, 결과 차이로 고른다. 근거가 남은 교훈만 다음 작업으로 넘긴다.

| 단계 | 하는 일 | 남길 것 |
|---|---|---|
| Propose | 같은 과제에 고칠 안을 2~3개 낸다 | 후보 이름과 서로 다른 점 1줄 |
| Probe | 후보를 같은 입력·카메라·프레임으로 돌린다. 정답 없이 결과끼리 비교한다 | 지표 표, 같은 각도 렌더 |
| Compose | 좋은 쪽을 고르거나 합친다. 교훈을 기록한다 | 채택·기각 이유, `lessons/` 기록 |

출처: Google Research **harness2**의 방법만 가져왔다. 논문 "Harness²: Recursive Agent Harnessing for an Open World"(https://arxiv.org/abs/2610.14224), 저장소 https://github.com/google-research/harness2 (Apache-2.0). **이 스킬은 harness2 코드를 설치·복사·사용하지 않는다.**

## 언제 쓰나

결과를 **수치나 렌더로 비교할 수 있는** 에셋 과제에 쓴다.

| 과제 | 후보 예 |
|---|---|
| 리타깃 방식 | 지금 방식 / 아바타 보강 / 새 리그에서 리타깃 없이 재생 |
| 리깅·가중치 계산 | heat / 위치 이웃 평균 / 표면 연결 후 heat |
| 줄이기(Decimate) 비율 | 1/10 / 3/10 / 정점 합친 뒤 3/10 |
| 텍스처 굽기 | 기존 UV / 자동 UV / 트라이플래너 |
| 임포트 설정 | Humanoid 자기 아바타 / Generic / Height Offset 유무 |

이럴 때는 쓰지 않는다.
- 답이 하나로 정해진 설정(단위 스케일, 축 방향). 체크리스트로 끝낸다.
- 비교할 화면이나 수치를 만들 수 없는 과제. 먼저 측정 방법부터 만든다.

## 절차

1. **후보를 정한다.** 2~3개로 제한한다. 후보마다 "무엇이 다른가"를 한 줄로 적는다. 크레딧이 드는 후보(유료 생성·자동 리깅·애니메이션 서비스 등)는 비용을 적고 **사람 승인을 받은 뒤** 돌린다.
2. **같은 조건으로 돌린다.** 입력 파일·클립·프레임 범위·카메라·조명을 고정한다. 후보끼리 독립이면 서브에이전트로 병렬 실행하고 **워크트리를 나눈다.** 같은 파일이나 열려 있는 Unity·Blender는 동시에 건드리지 않는다.
3. **같은 지표 표로 비교한다.** 아래 표준표의 항목을 쓴다. 표는 `scripts/probe-metrics.py`로 만든다. 렌더는 정면·측면·뒷면을 같은 프레임으로 나란히 둔다.
4. **채택·기각 근거를 적는다.** 수치와 렌더를 함께 본다. 이긴 후보도 진 지표가 있으면 적는다.
5. **교훈을 반영한다.** `lessons/`에 아래 형식으로 기록한다. 다시 쓸 만한 함정은 프로젝트의 함정 목록과 이 스킬 문서에도 옮긴다.

## 지표 표준표

기준값은 **임시 표시용**이다. 근거가 없는 값은 [확인 필요]로 둔다. 프로젝트가 정한 값이 있으면 `--thresholds`로 바꾼다.

| 지표 | 정의 | 재는 법 | 임시 기준 |
|---|---|---|---|
| 손·발 끝 위치 오차 | 원본 동작 대비 손·발 뼈 위치 차이의 최대값(m) | 골반 기준 상대 위치로 바꾸고, 골반 높이 비율로 원본을 맞춘 뒤 프레임마다 거리 | ≤0.05m [확인 필요] |
| 간선 최대 늘어남 | 바인드 자세 대비 간선 길이가 늘어난 최대값(mm). 어깨·팔꿈치 영역 | 어깨·팔 뼈에 주로 묶인 간선을 골라 프레임마다 길이 비교. 줄어든 쪽은 세지 않는다 | ≤30mm. 한 사례(웹 캐릭터, 어깨 155자세)의 임시 기준이다. 다른 모델은 [확인 필요] |
| 발 미끄러짐 | 발이 닿아 있는 동안 수평으로 밀린 최대 거리(cm) | 발 뼈 높이가 그 발의 최저 높이 +3cm 안이면 닿음으로 본다. 닿은 구간 시작점에서 멀어진 최대 거리 | ≤5cm [확인 필요] |
| 바닥 관통·뜸 | 가장 낮은 메시 점이 바닥(0) 아래로 내려간 깊이, 또는 한 번도 닿지 않고 떠 있는 높이(cm) | 프레임마다 전체 메시 최저점 | 관통 ≤1cm, 뜸 ≤2cm [확인 필요] |
| 반복 이음새 | 반복 클립의 첫 프레임과 끝 프레임 차이. 회전(°)과 위치(cm) | 회전은 부모 기준 회전의 각도 차이. 위치는 골반은 절대 위치, 나머지 뼈는 골반 기준 위치 | 5°, 2cm [확인 필요] |
| 열린 모서리 수 | 면 하나에만 붙은 모서리 수 | 원본(rest) 메시에서 셈 | 측정만. 삼각형 수에 가깝거나 많으면 정점이 갈라져 표면이 조각난 신호 |
| 삼각형 수 | 메시 삼각형 수 | 원본 메시 | 프로젝트 예산(`asset-budget`) [확인 필요] |
| 용량 | 파일 크기(MB) | 입력 파일 | 프로젝트 예산 [확인 필요] |
| 정면·측면·뒷면 렌더 | 같은 프레임의 세 방향 렌더 | 입력 JSON의 `renders`에 경로를 적으면 존재를 확인 | 3장 모두 있어야 외형 판정 가능 |

주의할 점
- 간선 늘어남(mm)은 메시 해상도에 따라 달라진다. **같은 메시끼리만** 비교한다.
- 원시 프레임에서 잰 값과 엔진 요약값은 정의가 다를 수 있다. 섞어서 비교하지 않는다.

## 스크립트

| 파일 | 하는 일 |
|---|---|
| `scripts/blender-dump-frames.py` | Blender 배치로 클립 하나의 프레임별 뼈·정점 위치를 JSON으로 뽑는다. 원본 파일은 저장하지 않는다 |
| `scripts/probe-metrics.py` | 후보 JSON 여러 개를 받아 위 지표 표를 만든다. 표준 라이브러리 + numpy만 쓴다 |

### 사용법

```bash
# 1) 후보마다 프레임 뽑기 (FBX·GLB·blend)
blender -b --factory-startup --python scripts/blender-dump-frames.py -- \
  --in cand_a.fbx --out a.json --candidate a-current [--action Wave] [--loop]

# 2) 같은 지표 표로 비교 (원본 동작이 있으면 --ref)
python -I scripts/probe-metrics.py a.json b.json c.json --ref source.json --md probe.md --out probe.json

# Unity 배치가 낸 클립별 요약(metrics.json)을 그대로 표로
python -I scripts/probe-metrics.py --unity-metrics preview/metrics.json [--unity-metrics exp/metrics.json] [--keys Wave]
```

종료 코드: `0` 기준 초과 없음 / `1` 초과 있음 / `3` 측정 불가(입력 없음). 초과는 **표시**일 뿐 판정이 아니다.

### 입력 형식 (프레임 JSON)

Unity 배치로 직접 만들 때도 이 형식을 따른다.

```json
{
  "candidate": "a-current",
  "clip": "Emote_Wave",
  "fps": 30,
  "loop": false,
  "up": "y",
  "units": "m",
  "bones": {"Hips": [[x, y, z], ...], "LeftHand": [...], "LeftFoot": [...]},
  "rotations": {"LeftHand": [[w, x, y, z], ...]},
  "effectors": {"hand_l": "LeftHand", "hand_r": "RightHand", "foot_l": "LeftFoot", "foot_r": "RightFoot"},
  "mesh": {
    "rest": [[x, y, z], ...],
    "frames": [[[x, y, z], ...], ...],
    "edges": [[0, 1], ...],
    "edge_groups": {"LeftShoulder": [0, 5, 9]},
    "min_up": [0.0, ...]
  },
  "stats": {"triangles": 15309, "open_edges": 12757, "file_mb": 4.1},
  "renders": {"front": "front.png", "side": "side.png", "back": "back.png"}
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `bones` | 예 | 뼈 이름 → 프레임별 월드 위치. `Hips` 계열 뼈가 있어야 위치 오차·이음새를 잰다 |
| `up` | 예 | `"y"`(Unity·glTF) 또는 `"z"`(Blender) |
| `rotations` | 아니오 | 부모 기준 회전(쿼터니언). 없으면 이음새 회전은 측정 불가 |
| `effectors` | 아니오 | 없으면 이름(Left/Right·.L/.R + Hand/Foot)으로 찾는다 |
| `mesh.rest` | 아니오 | 바인드 자세 위치. 없으면 첫 프레임을 기준으로 쓴다 |
| `mesh.min_up` | 아니오 | 프레임별 전체 메시 최저 높이. 없으면 `frames`의 최저점을 쓴다 |
| `stats`·`renders` | 아니오 | 있으면 그대로 표에 넣는다. `renders` 경로는 JSON 파일 기준 상대 경로 |

### 실제 실행 예 (2026-10-23)

자동 리깅 서비스가 낸 이모트 원본 FBX 3개를 Blender 5.2 배치로 뽑아 돌렸다. 원본 리그·원본 메시 기준이며, 게임 캐릭터에 리타깃한 결과가 아니다. **한 사례의 값이다.**

| 지표 | Wave | Dance1 | Dance3 |
|---|---|---|---|
| 간선 최대 늘어남(mm) | 71.7 | 135.8 | 123.9 |
| 발 미끄러짐(cm) | 0.3 | 4.4 | 4.5 |
| 바닥 관통 / 뜸(cm) | 0 / 1.3 | 2.9 / 0 | 6.2 / 0 |
| 반복 이음새 회전(°) / 위치(cm) | 반복 아님 | 21.4 / 14.1 | 7.0 / 3.3 |
| 열린 모서리 / 삼각형 | 12757 / 15309 | 같음 | 같음 |

- Dance1 이음새 회전 21.4°(LeftHand)는 같은 날 Unity 측정값 21.5°(LeftHand)와 맞았다.
- Dance3은 Unity 측정이 0°인데 원본 FBX는 7.0°다. 측정 대상(원본 리그 vs 리타깃된 캐릭터)이 달라 생긴 차이로 보이며 [확인 필요]다.
- Wave를 자기 자신에 `--ref`로 넣으면 위치 오차 0.000m로 나온다(계산 점검용).

## 교훈 기록 형식

`lessons/YYYY-MM-DD-<과제>.md` 한 파일에 과제 하나를 적는다.

| 항목 | 적을 것 |
|---|---|
| 날짜 | 작업한 날 |
| 과제 | 무엇을 정하려 했나 |
| 후보 | 2~3개와 서로 다른 점 |
| 수치 | 지표 표(같은 조건). 어디서 쟀는지 |
| 채택 | 고른 후보 또는 합친 방식 |
| 이유 | 수치와 렌더 근거 |
| 적용 범위 | 이 교훈을 써도 되는 모델·리그·엔진 |
| 반례 | 안 맞았던 경우, 아직 모르는 경우 |
| 검사 통과 / 외형 승인 | **따로 적는다.** 자동 검사 통과는 사람의 외형 승인이 아니다 |

## 하지 말 것

- 정답 없는 비교에서 **수치 하나로 결론 내기.** 지표 표와 렌더를 함께 본다.
- **한 모델의 통과를 다른 모델의 근거로 쓰기.** 기준값도 모델마다 다시 확인한다.
- **크레딧이 드는 후보를 승인 없이 돌리기.** 비용을 먼저 보여 준다.
- 후보마다 카메라·프레임·입력을 바꾸기. 그러면 비교가 아니다.
- 실패 후보를 사람의 작업 화면이나 기본 파일에 덮어쓰기. 복사본·별도 씬에서 돌린다.
