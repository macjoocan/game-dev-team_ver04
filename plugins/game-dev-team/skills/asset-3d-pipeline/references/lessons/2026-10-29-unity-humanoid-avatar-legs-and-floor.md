# Unity Humanoid 동작에서 다리가 뒤집히고 발이 떨릴 때

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-26 (다리 뒤집힘), 2026-10-29 (이모트 발 떨림) |
| 과제 | 자동 리깅 서비스 동작을 기존 캐릭터에 Humanoid로 재생하니 ① 발이 한 프레임에 찌그러지고 ② 이모트 중 발이 바닥에서 떨림 |
| 조건 | 기존 캐릭터 Avatar가 **팔만 T자세, 다리는 바인드 A자세**. 이모트는 그 캐릭터 FBX Avatar로 재생. 게임 코드가 이모트 중 바닥 높이를 매 프레임 보정 |
| 상태 | **완료.** 두 문제 모두 고친 뒤 원본 수준으로 돌아옴 |

> 아래 수치는 **한 사례의 값**이다. 다른 모델에 옮겨 쓰지 않는다.

## 증상과 원인

| 증상 | 원인 | 아닌 것 |
|---|---|---|
| 다리·발 비틀림 근육이 한 프레임에 ±1.5씩 뒤집혀 발이 찌그러짐. 원본 Generic은 최대 25°로 멀쩡 | Avatar 기준 자세에서 다리가 곧지 않음(A자세) | 키 압축·Avatar 출처는 원인 아님 |
| 이모트 중 바닥 발이 20mm 떨림(원본 7~10mm) | ① Avatar 기준 자세에서 팔만 T자로 펴서 다리 비틀림 근육이 ±3까지 나감 ② 게임 코드가 바닥을 매 프레임 "가장 낮은 발 뼈"로 다시 재서 몸이 튐 | 압축 설정 아님 |

## 고친 법

| 대상 | 방법 | 결과 |
|---|---|---|
| Avatar 기준 자세 | 팔은 수평, 다리(위·아랫다리)는 곧게 아래, 발끝은 앞으로 편다. 클립 FBX마다 자기 Avatar를 만든다 | 다리 뒤집힘 사라짐 |
| 게임 바닥 보정 | 이모트 시작 때 선 높이와 **클립 전체 최저**로 한 번만 정한다. 매 프레임 다시 재지 않는다 | 발 떨림 20 → 7~10mm |
| 다른 동작 | 같은 Avatar 수정으로 걷기 등도 원본에 더 가까워짐 | 손발 거리 차 3% → 0.6% |

## 확인한 것

| 함정 | 처리 | 근거 |
|---|---|---|
| 원본 FBX 키를 다듬어 고치려 함 | 되돌렸다. 사람이 "Blender·프리뷰에서는 멀쩡하고 게임에서만 흔들림"이라고 했다. **원본을 고치기 전에 프리뷰에서도 흔들리는지 먼저 묻는다** | 사람 확인 |
| 뒤집힘 찾기 | 곡선 프로브(한 프레임 차 > 1.0인 근육)와 다리 뼈 쿼터니언 각도 차로 찾는다 | 프로브 |
| Avatar 프로필 함수만 따로 실행 | 전체 재생성을 전제로 한 함수라 손바닥·손목·눈 값이 0이 됐다. 빌더는 원래 순서대로 돌린다 | 결과 비교 |
| Unity 배치 렌더에서 동작이 멈춘 것처럼 찍힘 | 매 프레임 `BakeMesh`로 굽거나, 검사는 직접 선형 스키닝으로 계산한다 | 렌더 |

## 적용 범위와 반례

- 적용 범위: Humanoid Avatar를 코드로 만들거나 고치는 프로젝트에서 다리·발 이상, 이모트 바닥 떨림이 나올 때.
- 먼저 볼 것: Avatar 기준 자세(팔·다리·발 방향), 게임 코드의 바닥 보정 방식.
- 반례·미확인: 다리가 원래 T자세로 곧은 리그에서는 이 문제가 안 생길 수 있다 [확인 필요].

## 검사 통과 / 외형 승인

| 구분 | 상태 |
|---|---|
| 검사 | 근육 곡선 프로브, 발 높이 떨림, 손발 거리 비교 |
| 외형 승인 | 사람이 게임에서 확인 |

## 놓친 것

- 처음에 키 압축·Avatar 출처를 의심했다. **Avatar 기준 자세**부터 봤으면 빨랐다.
- 원본 동작부터 고치려 했다. "어디서는 멀쩡하고 어디서만 이상한지"를 먼저 갈랐어야 했다.
