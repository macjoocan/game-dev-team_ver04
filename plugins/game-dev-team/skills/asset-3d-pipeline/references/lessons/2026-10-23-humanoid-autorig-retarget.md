# 자동 리깅 동작을 기존 Humanoid 캐릭터에 붙이기 (진행 중)

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 과제 | 자동 리깅 서비스로 만든 새 리그의 이모트 동작 12종을, 이미 게임에 있는 사람형 캐릭터(Unity Humanoid)에 붙이는 방법 정하기 |
| 조건 | 사람형 캐릭터 + 자동 리깅 서비스 + Unity Humanoid. 새 리그는 기존 캐릭터와 루트 이름·휴식 자세가 다름 |
| 상태 | **진행 중.** 후보 (a)(b)(c) 비교 수치가 아직 나오는 중이다 |

> 아래 수치는 **한 사례의 값**이다. 다른 모델에 옮겨 쓰지 않는다.

## 후보

| 후보 | 방식 | 다른 점 |
|---|---|---|
| (a) 지금 방식 | 이모트 FBX 하나에서 Create From This Model로 아바타를 만든다. 나머지 FBX는 그 아바타를 Copy한다. Humanoid 근육 공간으로 기존 캐릭터에 재생 | 기준 |
| (b) 아바타 보강 | (a)의 아바타를 보강한다. 보강 내용은 결과와 함께 적는다 [확인 필요] | 아바타 매핑 |
| (c) 리타깃 없음 | 새 리그에 리타깃 없이 재생 | 리타깃을 거치지 않음 |

같은 클립을 같은 카메라(정면·45°)·25fps로 렌더한다. 손 위치 오차·어깨 간선 늘어남(mm)·발 미끄러짐으로 비교한다.

참고: (a)의 자동 매핑은 Spine=`Spine02`, Chest=`Spine01`, UpperChest=`Spine`이었다. 기존 캐릭터 아바타에는 Chest·UpperChest가 없어, 그 두 마디 회전이 기존 캐릭터에서는 Spine에 합쳐져 보였다.

## 수치 (지금까지)

손 흔들기 클립 하나를 Unity 배치로 재고 `probe-metrics.py --unity-metrics`로 묶었다.

| 지표 | Height Offset 적용 | 시험 1 | 시험 2 | 새 리그에 Generic 재생 |
|---|---|---|---|---|
| 발 미끄러짐(cm) | 0.7 | 0.7 | 0.7 | 0.4 |
| 바닥 관통(cm) | 0 | 0 | 0 | 0 |
| 바닥 뜸(cm) | 0 | 3.0 | 3.0 | 1.2 |

- 시험 1·2가 각각 어떤 설정인지는 이 기록에서 확정하지 않았다 [확인 필요].
- 손 위치 오차·어깨 늘어남은 아직 없다. (a)(b)(c) 결과가 나오면 이 표에 채운다.

12종 전체((a) + Height Offset)의 측정 요약:

| 지표 | 값 |
|---|---|
| 발 미끄러짐 | 2종은 1cm 이하. 나머지 10종은 6.5~23.5cm. 원본 동작에 발 디딤이 섞여 있음 |
| 반복 이음새 | 반복 클립 4종 중 1종이 21.5°(손)·골반 19.2cm. 나머지 3종은 0 |
| 바닥 | Height Offset 적용 후 관통 0.1cm 이하. 앉는 동작은 적용 전 26cm 가라앉음 |

## 지금까지 확인한 것

| 함정 | 처리 | 근거 |
|---|---|---|
| 기존 캐릭터 아바타를 Copy From Other로 빌리면 실패 | 루트 이름(`Armature`)이 달라 Unity가 거부한다. 매핑만 복사하면 휴식 자세가 달라 다리가 들린다. 이모트 FBX에서 **자기 아바타**를 만들어 Humanoid로 임포트한다 | 배치 임포트 로그, 렌더 |
| 배치 렌더에서 동작이 멈춘 것처럼 찍힘 | 재생 위치를 바꿔도 SkinnedMeshRenderer가 다시 스키닝되지 않는다. 매 프레임 `BakeMesh`로 구워 렌더한다 | 렌더 비교 |
| 클립마다 발 높이가 다름 | 클립마다 Height Offset(`level`)으로 가장 낮은 메시 점을 바닥 0에 맞춘다 | 오프셋 없음 뜸 3.0cm → 적용 후 0 |
| Humanoid는 추가 뼈 동작을 버림 | 손가락·턱 동작이 필요하면 Generic으로 가져온다 | 이전 작업 기록 |

## 채택·이유

- 아직 없음. 현재 결과물은 (a)로 만들었다. (a)(b)(c) 비교가 끝나면 채택과 이유를 적는다.

## 적용 범위와 반례

- 적용 범위: 자동 리깅 서비스의 새 리그 동작을, **루트 이름·휴식 자세가 다른** 기존 Humanoid 캐릭터에 붙일 때.
- 반례·미확인: 같은 서비스 리그로 만든 캐릭터끼리는 아바타 복사가 될 수도 있다 [확인 필요].
- 원본 FBX와 리타깃 결과의 이음새가 다른 클립이 있었다(원본 7.0°, 리타깃 후 0°). 원인 [확인 필요].
