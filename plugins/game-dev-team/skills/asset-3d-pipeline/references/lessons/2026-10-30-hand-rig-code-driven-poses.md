# 손 뼈를 고칠 때 게임 쪽 손 자세 값도 같이 맞추기

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-30 |
| 과제 | 1인칭 실사 손 리그의 손가락 · 엄지 뼈가 실제 마디와 어긋나 손이 어색하게 꺾임. 뼈를 고치되 게임에서 손이 쥐는 자리는 지금과 같게 유지하기 |
| 조건 | 손목 아래만 있는 손 모델(뼈 16개). 클립이 없고, 게임 코드가 표 값(손 위치 · 손가락 굽힘 0~1 · 엄지 값 5개)으로 매 프레임 뼈를 돌림. 좌우 손은 정확한 거울상 |
| 상태 | **완료.** (c) 채택(사람 결정). 게임 반영은 구현 담당 |

> 아래 수치는 **한 사례의 값**이다. 다른 모델에 옮겨 쓰지 않는다.

## 후보

| 후보 | 방식 | 다른 점 |
|---|---|---|
| (a) 원래 뼈 | 뼈 · 가중치 그대로 | 기준 |
| (b) 새 뼈 + 지금 값 | 손가락 · 엄지 뼈를 메시 모양으로 다시 맞추고 가중치 새로. 게임 표 값은 그대로 | 뼈만 바꿈 |
| (b′) 손가락만 새 뼈 | 엄지는 원래 뼈로 되돌리고, 엄지 둘레 가중치는 원래 것 · 새 것을 여러 방식으로 섞음 | 엄지만 원래대로 |
| (c) 새 뼈 + 변환한 값 | (b) + 엄지 값 변환: 원래 뼈에서 엄지 세 점(갈라지는 마디 · 가운데 마디 · 끝)이 가던 자리에 새 뼈 엄지가 오도록 값 5개를 다시 찾음 | 뼈와 값을 같이 바꿈 |

- 손 검사: 반쯤 쥠 · 주먹 · 엄지 접기 자세에서 손 메시 변이 가장 많이 늘어난 길이(mm)와, 뼈 회전을 빼고 센 뒤집힌 면 수.
- 쥐는 자리: 게임 계산식을 그대로 옮긴 1인칭 카메라 장면에서, 같은 프레임의 손 메시 엄지 끝을 (a)와 비교.

## 수치

손 검사(오른손, 엄지를 손바닥 쪽으로 감는 주먹):

| 후보 | 반쯤 쥠 | 주먹 | 엄지 접기 |
|---|---:|---:|---:|
| (a) 원래 뼈 | 7.02 (320) | 12.76 (1,096) | 3.76 (297) |
| (b) · (c) 새 뼈 | **3.48 (26)** | **8.54 (905)** | 4.84 (27) |
| (b′) 엄지 원래 뼈 + 새 자동 가중치 | | 23.4 | 13.6 |
| (b′) 엄지 원래 뼈 + 가중치 정점 단위로 섞기 | 24.07 | 47.5 | |
| (b′) 엄지 원래 뼈 + 엄지 몫만 원래 가중치 + Delta Mush(주변 정점과 섞어 부드럽게 만든 모양) 굽기 | 6.63 | 14.88 | 5.25 |

괄호는 뒤집힌 면 수.

쥐는 자리(게임 동작 11개, 엄지 끝 차이):

| 후보 | 차이 |
|---|---|
| (b) 새 뼈 + 지금 값 | 엄지가 다른 자리로 감. 쥐기 동작에서 손가락과 겹치는 깊이가 원래와 달라짐(예: 0.05 → 0.49cm) |
| (b′) | 0mm (엄지 뼈가 원래와 같음) |
| **(c) 새 뼈 + 변환한 값** | **0~1.6mm** (변환표 29개 중 최대 1.8mm) |

## 확인한 것

| 함정 | 처리 | 근거 |
|---|---|---|
| 코드가 표 값으로 움직이는 손은 뼈를 옮기면 같은 값이 다른 자리로 간다 | 모델만 넘기지 않고 표 값 변환표를 같이 넘김 | (b) 1인칭 비교 |
| 손가락 자동 맞추기가 엄지 3마디를 손에서 튀어나온 부분에만 놓아 엄지 뿌리가 손 밖으로 9.7cm 빠짐 | 엄지 뿌리(손목 쪽 관절)는 원래 자리에 두고 나머지 두 관절만 자동 결과 사용 | 뼈 비교 그림 |
| 작은 손 메시(약 0.35m)에서 Blender 자동 가중치가 해를 못 찾고 0을 냄(도구는 "0개 바꿈"으로 조용히 끝남) | 임시 복사본(아마추어 + 메시)을 10배로 키워 계산하고 가중치만 옮김 | 모든 정점에 가중치 생김 |
| 원래 엄지 뼈는 관절이 실제 마디보다 1~1.4cm 안쪽 → 접으면 마디가 아닌 곳에서 꺾임 | 뼈를 실제 마디로 옮기고 값을 변환함((c)) | (b′) 엄지 접기 5.25~13.6mm |
| 옛 가중치와 새 가중치를 정점 단위로 섞음 | 경계가 찢어짐. 섞지 않고 한 뼈대 기준으로 다시 만듦 | 주먹 47.5mm |
| 주먹 자세에서 엄지 끝을 손바닥 가운데로 감음 → 엄지가 손가락 밑으로 파고듦 | 엄지 끝 마디를 검지 · 중지 가운데 마디 바깥에 얹도록 각도를 찾음(뼈를 원기둥으로 보고 겹침 벌점) | 사람 확인("정권 주먹") |
| 게임 코드가 값 일부만 받음(엄지 값을 3개로 받는 곳) | 변환 값 5개가 안 들어가 코드 수정 필요로 넘김 | 변환표 |
| 좌우가 정확한 거울인 손 | 한쪽만 고치고 뼈 · 가중치를 거울로 복사(정점 1:1 대응 확인) | 뼈 오차 0 |

## 채택 · 이유

- **채택: (c) 새 뼈 + 변환한 값** (사람 결정).
- 이유
  - 손 검사가 가장 좋음(주먹 12.76 → 8.54mm, 반쯤 쥠 뒤집힌 면 320 → 26).
  - 쥐는 자리는 지금 게임과 같음(1.8mm 이내). 사람은 "꺾이는 모양"과 "쥐는 자리"를 둘 다 원했다.
- (b′)는 쥐는 자리는 같지만 엄지 꺾임이 다시 나빠져 버림.
- 대가: 게임 표 5곳(손짓 · 물건 쥐기 · 냄비 · 창문 넘기 · 손전등)을 같이 바꿔야 함. 하나라도 빠지면 그 동작의 엄지가 어긋남.

## 적용 범위와 반례

- 적용 범위: 클립 대신 **코드가 표 값으로 뼈를 돌리는** 손 · 팔(1인칭 손, 절차적 손 자세)을 고칠 때.
- 먼저 볼 것: 이 손이 게임에서 어떻게 움직이는지. 클립(Generic · Humanoid)인지, 코드 구동인지. Generic 클립이면 대신 클립을 새 뼈대로 다시 굽는다.
- 반례 · 미확인
  - 손가락 4개의 쥐기 값은 변환하지 않았다. 손가락 끝 자리가 1~2cm 다를 수 있다 [확인 필요].
  - 코드가 그 자리에서 계산하는 엄지(쉬는 자세 섞기, 원통 감싸 쥐기 등)는 아직 원래 뼈 기준이다.
  - Unity에서 직접 보지 않았다. 게임 계산식을 Blender로 옮긴 장면에서 쟀다.

## 검사 통과 / 외형 승인

| 구분 | 상태 |
|---|---|
| 검사 | 손 검사 수치, 변환표 29개 오차, 1인칭 비교 6장면, 내보낸 FBX 다시 열어 구조 대조(물체 · 뼈 · 재질 수 같음, 모든 정점 가중치) |
| 외형 승인 | 사람이 Blender 1인칭 장면에서 보고 확정. **게임 안 외형은 아직 확인 안 함** |

## 놓친 것

- 처음에 1인칭 손이 클립으로 움직인다고 보고 Blender에 "애니메이션"을 찾았다. **손이 게임에서 어떻게 움직이는지**부터 확인했어야 했다.
- 엄지 뼈를 옮긴 뒤 쥐기 자세가 이상해진 원인을 처음엔 게임 값 쪽으로 봤다. 원래 뼈 장면과 나란히 놓는 비교 장면을 먼저 만들었으면 빨리 갈렸다.
- 스크립트로 임시 물체를 바로 지우고, 화면에 안 띄운 장면을 움직이다 Blender가 두 번 꺼졌다. 임시 물체는 장면에서 빼고 갱신한 뒤 지운다.
