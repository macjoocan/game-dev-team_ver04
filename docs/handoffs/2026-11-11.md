## [증거] 구현과 실제 생성물

### 검사 도구

- `lib-sprite-sequence.mjs`: 로드·숫자 순서 정렬·공통 입력 검사·측정 설정·입력 해시.
- `sprite-qa.mjs`: 네 방향 경계 접촉을 추가한다. 접촉한 프레임 이름과 최소 여백을 남긴다.
- `motion-qa.mjs`: 동작을 명시해 하단 윤곽 변화·인접 변화·상단 위치 범위를 관찰한다.
- 신규 입력·경계·종료 코드 테스트와 기존 모션·스테이지 검사를 합쳐 **45개 통과, 실패·생략 0개**다.

세부 근거는 [구현 보고](../art/sprite-motion-observer-2026-11-11.md), [실행 명령과 소스 해시](../../out/sprite-motion-implementation-20261111/validation.json), [테스트 원시 출력](../../out/sprite-motion-implementation-20261111/tests.stdout.log)에 있다.
집의 원래 설계 전체를 구현한 것은 아니다. 라벨 수집·교정과 자동 등급 승격은 보류했다.

## [기준] 판정의 의미

피사체 알파는 128 이상, 배경은 20 미만이다. 매 프레임에 피사체와 배경 2% 이상이 필요하다.
빈 입력·배경 부족·크기 혼합은 exit 3이다. 문제 프레임을 빼고 계산하지 않는다.
기존 색·형태·아틀라스 실패는 exit 1로 유지한다.

잘림 의심은 경고만 낸다. `--tight-crop`은 지정 방향에 모든 프레임이 닿을 때만 면제한다.
모션 관찰의 exit 0은 계산 완료다. `liftRange`는 실제 발 들기나 품질 점수가 아니다.
기존 baseline 경고의 34px는 희미한 알파까지 포함한 값이다.
같은 v2의 알파 128 기준 피사체 하단 범위는 6px였다. 두 값을 실제 발 관절 이동량으로 설명하지 않는다.

## [공백] 아직 하지 않은 것

8키포즈를 26프레임 수준의 부드러운 동작으로 확정하지 않았다.
발 미끄러짐·체중 이동·칼 길이 불변·반복 경계를 자동 승인하지 않는다.
실제 스테이지의 캐릭터 교체와 바쁜 전투 화면 검수도 아직이다.
기존 C와 rigid의 형태 미달은 이번 코드 변경 전후에 같았다.
프로젝트 공통 아트 게이트는 기존 참조 폴더가 없어 측정 불가다.
