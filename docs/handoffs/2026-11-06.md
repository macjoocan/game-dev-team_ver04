## 추가 인수인계: PixelOE 도트 변환

사용자는 비교 결과에 “와우 좋네 ㅋㅋㅋ”라고 평가했다. 특정 해상도를 고른 것은 아니다. [피드백 원문](../../.review-loop/feedback/chr.silver.pixeloe.walk.preference-20261106.json)을 보존했고 자동 검사 결과는 바꾸지 않았다.

- 도구: [PixelOE 공식 GitHub](https://github.com/KohakuBlueleaf/PixelOE), 1.0.1·`7ce444b36d3876a151d845d4493240e904454d89`, Apache-2.0.
- 입력: 기존 은발 걷기 C의 투명 PNG 26장. 원본은 그대로다. 새 원화·동작 생성과 추가 유료 호출은 0회다.
- 결과: 단순 축소 96px, PixelOE 64·96·128px. 후보당 26장, 총 104장이다. 도트 높이는 캔버스 기준이며 모든 후보에 공통 32색을 적용했다.
- 기준 설정: `pixel_size=4`, `thickness=2`, `mode=contrast`, `backend=torch`. PixelOE는 RGB에 적용하고 원본 알파 마스크는 따로 축소했다. 프레임별 재중앙 정렬은 하지 않았다.
- 확인: 최대 32색·반투명 0·경계 접촉 0/26. 브라우저 이미지 130개 로딩과 재생·프레임 이동·배경 전환을 확인했다. 자동 도트 검사는 외톨이 픽셀 비율 때문에 네 후보 모두 exit 1이다.
- 검수 카드: `chr.silver.pixeloe.walk@1`. 상세 근거는 [실험 보고서](../../out/pixel-probe-20261106/REPORT.md), 전달 파일 해시는 [publish-files.json](../../out/pixel-probe-20261106/publish-files.json)에 있다.

결과물과 비교 화면은 저장소에 포함한다. 재생에는 PixelOE·Torch·GPU가 필요 없다.

```powershell
python3 -m http.server 8199 --bind 127.0.0.1 --directory out/pixel-probe-20261106
```

`http://127.0.0.1:8199/`에서 재생한다. [정지 비교](../../out/pixel-probe-20261106/comparison.png)와 [128px GIF](../../out/pixel-probe-20261106/pixeloe128.gif)도 제공한다.

재변환할 때만 아래 소스와 Python 의존성이 필요하다. `vendor/`와 `deps/`는 Git 전달 대상에서 제외했다. 새 PC에서는 기존 ComfyUI의 Python 또는 별도 환경에 Torch·torchvision·kornia·SciPy·NumPy·Pillow·OpenCV를 준비한다. 실제 사용 버전은 [environment.json](../../out/pixel-probe-20261106/environment.json)에 기록했다.

```powershell
git clone https://github.com/KohakuBlueleaf/PixelOE.git out/pixel-probe-20261106/vendor/PixelOE
git -C out/pixel-probe-20261106/vendor/PixelOE checkout --detach 7ce444b36d3876a151d845d4493240e904454d89
# 위 폴더가 이미 있으면 새로 복제하지 말고 현재 커밋을 먼저 확인한다.
& 'D:/ComfyUI/ComfyUI_windows_portable/python_embeded/python.exe' -u out/pixel-probe-20261106/run-pixeloe.py
node out/pixel-probe-20261106/check.mjs
```

D 드라이브 경로는 이번 PC 기준이다. 다른 PC에서는 준비한 Python 실행 파일로 바꾼다. 재생성 전에 채택 결과를 별도 버전으로 보존한다. 다음 개선은 선택한 크기의 잔무늬 정리이며, PixelOE 시험을 생산용 승인으로 확대하지 않는다.

- 플러그인 전체 CI는 로컬에서 **16/16 통과, exit 0**이다. 원시 출력과 종료 코드는 [ci.txt](../../out/day-handoff-20261106/ci.txt), [ci-result.json](../../out/day-handoff-20261106/ci-result.json)에 보존한다. 최초 실행은 Windows 시스템 Bash의 WSL 접근 오류로 막혔다. Git Bash를 지정해 다시 실행했다. 원격 Ubuntu CI와의 플랫폼 차이는 남는다.
- 전달 파일의 크기와 SHA-256은 [publish-files.json](../../out/day-handoff-20261106/publish-files.json)에 기록한다. 대용량 AI 모델, 설치된 의존성, 복제한 외부 저장소, 임시 latent는 전달 목록에서 제외한다.

## 기준: 재생과 재제작

저장소 루트에서 아래 명령을 **서로 다른 터미널**에 실행한다. 미리보기에는 GPU와 생성 모델이 필요 없다. `python`이 없으면 설치된 Python 실행 파일 경로로 바꾼다.

```powershell
python -m http.server 8197 --bind 127.0.0.1 --directory out/experiments/local-motion-20261106
python -m http.server 8198 --bind 127.0.0.1 --directory out/experiments/silver-slash-20261106
node skills/review-loop/scripts/review-loop.mjs serve --project . --port 4180
```

걷기는 `http://127.0.0.1:8197/compare.html`, 베기는 `http://127.0.0.1:8198/`에서 본다. 베기는 Space 또는 공격 버튼으로 시작한다. 먼저 1배속 B/C를 비교하고, 명중·빗나감과 작은 크기도 확인한다. GIF는 시간 반올림과 마지막 대기가 있으므로 타이밍 판단은 HTML에서 한다.

| 베기 안 | 총시간 | 타격 시점 | 명중 정지 |
|---|---:|---:|---:|
| A: 원본 일정 속도 | 1600ms | 원본 재생 기준 | 없음 |
| B: 자세 선택·시간 조절 | 430ms | 157ms | 없음 |
| C: B + 명중 반응 | 명중 480ms / 빗나감 430ms | 157ms | 명중 시 50ms |

수치는 게임에 넣기 전 비교용 가정이다. 조절값은 베기 폴더 `feel.json`, 재생은 `timeline.mjs`에 모았다. 아틀라스는 패킹 순서가 아니라 파일 이름으로 시간과 원본 번호를 연결했다. `export.mjs`의 보정 처리를 빼면 재생 순서가 틀어질 수 있다.

재제작할 때만 ComfyUI와 D 드라이브 모델이 필요하다. 현재 경로는 `D:\ComfyUI\ComfyUI_windows_portable`이다. Wan Animate 2 INT8, LightX2V LoRA, UMT5, CLIP Vision, Wan VAE를 사용했다. 배경 제거는 `D:\AI\models\rembg\birefnet-general-lite.onnx`다. 설치된 Python 의존성은 Git에 포함하지 않는다. 같은 PC에서는 기존 설치를 먼저 확인한다.

걷기는 기존 Ludo 26장 동작을 참조했다. 베기는 Quaternius CC0 `Sword_Attack_RM` 동작을 사용했다. 두 결과의 제작 근거를 섞지 않는다. 실행 그래프와 영수증을 먼저 읽고, 이미 끝난 생성을 다시 제출하지 않는다.

걷기에서 확인한 수정은 전체 `VAEDecode`와 공통 캔버스 여백이다. 시간축 타일 디코딩은 색 변화·잔상을 재현했다. 프레임마다 무기 외곽으로 다시 중앙 정렬하면 몸이 흔들리므로 공통 원점을 유지한다.
