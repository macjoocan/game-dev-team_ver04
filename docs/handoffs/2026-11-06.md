## 증거: 결과와 실행 기록

- 걷기: `chr.silver.local-wan-animate2.walk@1`. `c-alpha/`의 투명 PNG 26장과 `c-preview/`를 사용한다. 테두리 접촉 0/26, 오른쪽 최소 여백 24px다. 루프 점수는 0.95, 반복 경계 변화 비율은 1.24다.
- 베기: `chr.silver.local.slash@1`. `alpha-repaired/`와 `export/`가 보정 결과다. 7번 칼날은 원본 픽셀로 복구했다. 영역 밖과 나머지 24장은 그대로인지 검사했다.
- 베기 재생 로직 5개 검사와 브라우저의 명중·빗나감·완료 검사를 통과했다. 원시 결과는 베기 폴더 `qa/`에 있다.
- 플러그인 전체 CI는 로컬에서 **16/16 통과, exit 0**이다. 원시 출력과 종료 코드는 [ci.txt](../../out/day-handoff-20261106/ci.txt), [ci-result.json](../../out/day-handoff-20261106/ci-result.json)에 보존한다. 최초 실행은 Windows 시스템 Bash의 WSL 접근 오류로 막혔다. Git Bash를 지정해 다시 실행했다. 원격 Ubuntu CI와의 플랫폼 차이는 남는다.
- 전달 파일의 크기와 SHA-256은 [publish-files.json](../../out/day-handoff-20261106/publish-files.json)에 기록한다. 대용량 AI 모델, 설치된 의존성, 복제한 외부 저장소, 임시 latent는 전달 목록에서 제외한다.

검증 시작 커밋은 `4c43b68`이다. 이번 인수인계 커밋에는 그 뒤의 소스·문서·검토 결과가 함께 담긴다. 개별 보고서의 “push하지 않음”은 해당 제작 시점의 기록이다.

## 기준: 재생과 재제작

저장소 루트에서 아래 명령을 **서로 다른 터미널**에 실행한다. 미리보기에는 GPU와 생성 모델이 필요 없다. `python`이 없으면 설치된 Python 실행 파일 경로로 바꾼다.

```powershell
python -m http.server 8197 --bind 127.0.0.1 --directory out/experiments/local-motion-20261106
python -m http.server 8198 --bind 127.0.0.1 --directory out/experiments/silver-slash-20261106
node skills/review-loop/scripts/review-loop.mjs serve --project . --port 4180
```

걷기는 `http://127.0.0.1:8197/compare.html`, 베기는 `http://127.0.0.1:8198/`에서 본다. 베기는 Space 또는 공격 버튼으로 시작한다. 먼저 1배속 B/C를 비교하고, 명중·빗나감과 작은 크기도 확인한다. GIF는 시간 반올림과 마지막 대기가 있으므로 타이밍 판단은 HTML에서 한다.

| 베기 안 | 총시간 | 타격 시점 | 명중 정지 |
|---|---:|---:|---:|
| A: 원본 일정 속도 | 1600ms | 원본 재생 기준 | 없음 |
| B: 자세 선택·시간 조절 | 430ms | 157ms | 없음 |
| C: B + 명중 반응 | 명중 480ms / 빗나감 430ms | 157ms | 명중 시 50ms |

수치는 게임에 넣기 전 비교용 가정이다. 조절값은 베기 폴더 `feel.json`, 재생은 `timeline.mjs`에 모았다. 아틀라스는 패킹 순서가 아니라 파일 이름으로 시간과 원본 번호를 연결했다. `export.mjs`의 보정 처리를 빼면 재생 순서가 틀어질 수 있다.

재제작할 때만 ComfyUI와 D 드라이브 모델이 필요하다. 현재 경로는 `D:\ComfyUI\ComfyUI_windows_portable`이다. Wan Animate 2 INT8, LightX2V LoRA, UMT5, CLIP Vision, Wan VAE를 사용했다. 배경 제거는 `D:\AI\models\rembg\birefnet-general-lite.onnx`다. 설치된 Python 의존성은 Git에 포함하지 않는다. 같은 PC에서는 기존 설치를 먼저 확인한다.

걷기는 기존 Ludo 26장 동작을 참조했다. 베기는 Quaternius CC0 `Sword_Attack_RM` 동작을 사용했다. 두 결과의 제작 근거를 섞지 않는다. 실행 그래프와 영수증을 먼저 읽고, 이미 끝난 생성을 다시 제출하지 않는다.

걷기에서 확인한 수정은 전체 `VAEDecode`와 공통 캔버스 여백이다. 시간축 타일 디코딩은 색 변화·잔상을 재현했다. 프레임마다 무기 외곽으로 다시 중앙 정렬하면 몸이 흔들리므로 공통 원점을 유지한다.

## 공백: 아직 확인하지 않은 것

- 베기 타격감에 대한 사용자 평가와 실제 엔진 임포트는 아직 없다. HTML의 전방 범위 판정은 게임의 정밀 충돌·콤보·취소 규칙을 대신하지 않는다.
- 걷기와 베기 모두 자동 실루엣 검사 미달과 알파 경고가 남았다. 자세 변화의 영향과 실제 외형 문제를 사람이 구분해야 한다.
- 베기 화면 플래시 검사는 exit 0이지만 **조건부**다. 최대 변화 면적 6.5%라는 측정이 있으며, 무조건 안전 통과로 쓰지 않는다.
- 생성 모델 해시는 이번에 다시 검사하지 않았다. 노드·모델 선택지 확인만 했다.
- `docs/pipeline/state.json`이 없어 열린 게이트는 미확인이다. 기존 art-gate도 샘플 누락으로 측정 불가였다. 이번 CI 통과와 아트 승인은 별개다.
- 이전 검수 카드의 모든 과거 산출물을 전달하는 것은 아니다. 오늘의 전달 목록에 있는 파일을 기준으로 재개한다.
