# 2026-11-11 추가 인수인계: 은발 베기와 팔 중복 수정

## [주장] 베기는 v6 수정본부터 검수한다

최신 베기 후보는 **v6**다. 마이어의 1570년 검술 교본을 참고한 v5에서 팔 중복을 고쳤다.
걷기 비교 기준은 기존 `silver-gpt-qa-20261111/v3`이며, 베기 v3와 다른 실험이다.
플러그인 버전은 0.54.0을 유지한다. 이번에는 공용 스킬이나 게임 로직을 바꾸지 않았다.

사용자는 교본 참고 v5를 보고 “오 이제 좀 괜찮네”라고 평가했다.
이어 “지금 이미지 보니가 같은 시점으로 보기 317ms 이 부근에서 팔이 3개네 ㅋㅋㅋ”라고 지적했다.
v6는 해당 6번 자세만 교체했다. **수정된 v6에 대한 사용자 재검수는 아직 없다.**

## 다른 PC에서 바로 이어가기

저장소 루트에서 실행한다. 재생에 Python·GPU·ComfyUI·외부 생성 API는 필요 없다.

```powershell
node out/experiments/silver-reference-slash-20261111/serve.mjs
```

- 최신 수정 비교: `http://127.0.0.1:8232/armfix-review.html`
- 교본 참고 전후: `http://127.0.0.1:8232/historical-review.html`
- 검 궤적 비교: `http://127.0.0.1:8232/arc-review.html`
- 상체 포즈 비교: `http://127.0.0.1:8232/motion-review.html`
- 초기 타이밍 비교: `http://127.0.0.1:8232/review.html`

서버의 기본 `/`는 초기 비교 화면이다. 최신 화면은 `armfix-review.html`로 직접 연다.
317ms를 선택하면 왼쪽 v5와 오른쪽 v6의 6번 자세를 비교할 수 있다.
양쪽은 460ms이며 시간표는 `[20,130,35,25,30,100,60,60]`이다.
6번 자세 구간은 240ms 이상 340ms 미만이다. 각 시간은 원작 실측값이 아닌 제작 설정이다.

프리뷰는 프레임의 RGBA를 고치지 않는다. 준비 자세를 기준으로 표시 크기만 맞춘다.
원본·개별 프레임·프롬프트·QA·HTML·검수 캡처를 함께 전달한다.
텍스트 문서는 목록의 `hashMode`에 따라 줄바꿈을 LF로 맞춰 해시를 비교한다. 이미지·실험 원문은 바이트 그대로 비교한다.
파일 목록과 SHA-256은 [전달 목록](../../out/day-handoff-20261111-slash/publish-files.json)에 있다.
공개 조건을 확인하지 않은 참고 도판, 추출 게임 이미지, 86MB 원본 목록과 개인 작업 원장은 제외했다.
교본 출처 링크와 조사 보고서는 남겼으며, 제외한 이미지 없이도 스프라이트 비교는 재생된다.

## [증거] 수정 경과와 검증

대상 소스 기준은 `bba068ca03a2511c47b4b2a96bc8d97190e41419`다.
다음 표는 이번 세션의 후보 변화이며, 이전 후보를 삭제하지 않았다.

| 단계 | 변경 | 사용자 피드백·결과 |
|---|---|---|
| 로컬 자료 조사 | `D:\99.기타`의 `out_` 폴더 32개 조사 | Soulbound·WizardOfLegend의 공격 자세, 다른 게임의 시간·관절 자료 확인 |
| v1·v2 | GPT 내려베기 8포즈와 여백 수정 | 초기 타이밍 비교는 “둘 차이가 읍는데 ㄷㄷ” |
| v2 타이밍 강화 | 준비와 타격 자세 유지 시간을 늘리고 통과 자세를 짧게 배치 | 리듬은 좋지만 모션 자체가 어색하고 멋있지 않다는 피드백 |
| v3 | 상체와 다리를 포함한 6포즈 재설계 | 뒤에서 찌르는 느낌, 더 길게 휘두르기를 요청 |
| v4 | 큰 각도 변화를 가진 8포즈 | 실제 검술 도감을 찾아 참고하자는 요청 |
| v5 | 교본의 높은 준비 자세와 끝까지 통과하는 베기 참고 | 긍정 평가 뒤 317ms의 팔 중복 발견 |
| v6 | 6번 자세만 해부학적 오류 수정 | 나머지 7개 PNG가 v5와 SHA-256까지 같음. 재검수 대기 |

v6는 512×512 프레임 8장이다. `sprite-qa`는 exit 0, 경고는 고아 섬·구멍·프린지 3종이다.
`motion-qa --gait other`의 exit 0은 관찰값 계산 완료이며 공격 품질 통과가 아니다.
알파 128 기준 경계 접촉은 0/8이다. 여백은 위 138px, 아래 51px, 왼쪽 82px, 오른쪽 55px다.
피사체 하단 범위 0은 프레임 정렬 결과다. 발 접지가 검증됐다는 뜻이 아니다.

브라우저에서 317ms에 양쪽 6번 자세가 표시되고 이미지가 모두 로드되는 것을 확인했다.
가로 넘침은 없었다. v5 한 번 재생은 보이는 탭에서 460ms에 정지했다.
숨겨진 탭에서는 `requestAnimationFrame`이 멈춘 사례를 남겼다.

## 검술 출처와 게임 레퍼런스 후보

[Joachim Meyer, 1570, 두삭 제3장](https://sprechfenster.org/meyer/1570/dusack-chapter-3-the-four-cuts/)의 원문·번역과 B 도판을 확인했다.
번역자는 페이지 표기 기준 Rebecca L. R. Garber다.
높은 준비 자세, 대각선 베기 선, 몸이 검을 따라 돌아가며 끝까지 통과하는 설명을 참고했다.
원래 두삭은 우리 직선 한손검과 다르다. 8포즈 연결과 재생 시간은 게임용 각색이다.
도판이 연속 동작을 제공하거나 역사적 정확성을 검증해 준다고 설명하지 않는다.
자세한 범위는 [교본 연구 기록](../../out/experiments/silver-reference-slash-20261111/HISTORICAL-STUDY.md)을 따른다.

아래 게임은 Steam 상점을 확인한 **다음 분석 후보**다. 아직 영상의 프레임별 분석은 하지 않았다.
사용자가 특정 작품을 선택한 것도 아니다.

## [기준] 다음 담당자가 지킬 구분

일반 정합성 통과와 관절·손·무기의 정확성은 다르다.
v5도 정합성 검사를 통과했지만 팔이 세 개였다. 모든 키포즈를 정지 화면으로 확인한다.
수정된 프레임과 유지한 프레임을 구분하고, 유지 대상은 해시로 확인한다.
사람의 긍정 평가를 출시 승인이나 공통 규칙 승격으로 바꾸지 않는다.

## [공백] 아직 하지 않은 것

실제 스테이지의 스프라이트 교체, 충돌·피격 판정 연결, 바쁜 전투 화면 검수는 하지 않았다.
검술 전문가 검수와 스팀 후보의 프레임별 분석도 미실행이다.
루트 아트 게이트는 이전부터 참조 폴더 누락으로 측정 불가다. 이번에 통과로 바꾸지 않았다.
설치본 0.52.0은 갱신하지 않았고 소스 버전은 0.54.0이다.

## [잔여 위험] 재개 순서

1. v6의 317ms 팔과 앞뒤 프레임 연결을 재검수한다.
2. 손목·검 길이·빈손·얼굴·망토를 정지 화면과 재생 화면에서 함께 확인한다.
3. 반투명 테두리와 작은 알파 잔여물을 실제 배경 위에서 확인한다.
4. 스팀 후보에서 대표 동작을 고르고 준비·통과·마무리 자세를 분석한다.
5. 다음 시안이 선택되면 실제 스테이지 크기로 연결한다.

개인 작업 원장은 Git에 포함되지 않는다. 다른 PC에서는 이 문서와 검수 카드를 먼저 읽는다.
프레임 재제작 스크립트는 기존 산출물을 덮어쓸 수 있으므로, 재생만 할 때는 실행하지 않는다.
