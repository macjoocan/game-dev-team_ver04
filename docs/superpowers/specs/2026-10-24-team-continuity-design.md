# 데브팀 자체 작업 재개와 인계

사용자는 Hermes 설치 대신 작업 재개·역할 인계·승인된 경험 재사용·검증 루프라는 구조를 기존 Codex/Claude 환경에 붙이는 방향을 승인했다. 외부 소스 코드를 복사하거나 별도 모델을 호출하지 않는다.

## 구현 범위와 선택

의존성 없는 `scripts/team-work.mjs` CLI를 추가한다. 프로젝트 인자는 필수다. 작업 기록은 프로젝트 `.team-work/state.json` 하나에 원자적으로 교체 저장한다. 스키마 버전 1, revision, tasks 배열, events 배열, lessonProposals 배열을 둔다. 기록에 비밀을 넣지 않도록 안내하고 이 레포에서는 `.team-work/`를 Git에서 제외한다. 다른 PC로 자동 동기화하는 기능은 아니다.

- `add`: 안정된 작업 ID, 제목, 역할, 다음 행동을 등록한다. 역할은 기존 6개 역할만 허용한다.
- `checkpoint`: 작업 상태(todo/active/blocked/review/done), 다음 행동, 요약, 막힌 이유를 기록한다. blocked는 이유가 필요하다. done은 첨부 증거 파일들이 현재도 같은 해시일 때만 기록할 수 있다. done은 담당 작업 완료 기록이며 사람 승인이나 게이트 통과를 뜻하지 않는다.
- `handoff`: 담당 역할을 바꾸고 다음 행동·인계 메모를 저장한다. 기록상 이전/새 역할을 이벤트에 남긴다. 실제 에이전트 프로세스를 실행하지 않는다.
- `evidence`: 기존 검증 출력 또는 산출물 파일을 프로젝트 상대 경로로 첨부하고 SHA-256을 기록한다. 검사 실행이나 통과 여부를 창작하지 않는다. brief에서 누락/변경을 다시 검사한다. 기본 최대 2MiB의 일반 파일만 허용하고 연결 경로, `.git`, `.secrets`, `.env`는 거부한다. 증거 디렉터리 재귀 탐색은 하지 않는다.
- `lesson`: 작업별 교훈 제안과 증거 파일을 기록한다. 사람 승인 전 공통 규칙으로 승격하지 않는다. 기존 `.review-loop/rules.json`이 승인 공통 규칙의 정본이다.
- `brief`: 원장을 변경하지 않고 작업·최근 이벤트·교훈 제안·증거 최신성을 출력한다. 기존 상태/검수 인계 수집 결과를 합쳐 열린 게이트와 수정 피드백, 활성 규칙을 함께 보여준다.

모든 변경 명령은 `--actor codex|claude-code|human`을 명시한다. 이 값은 감사용 자기 신고이며 인증 수단이 아니다. 완료 기록에 필요한 증거는 실제 검증 통과나 사람 사인오프를 대체하지 않는다. 체크포인트·인계가 산출물을 바꾸지는 않는다.

## 저장과 복구

짧은 쓰기 구간에 `.team-work/write.lock`을 배타 생성한다. 기존 잠금은 프로세스 종료 여부와 무관하게 자동 탈취하지 않는다. 상태 JSON 손상·버전 불일치는 복구 안내 오류로 종료하고 초기화로 덮어쓰지 않는다. 임시 파일은 state.json과 같은 디렉터리에 배타 생성 후 rename한다. 잠금 해제는 자신이 잡은 잠금에만 적용한다. 모든 경로의 연결 파일/부모를 거부한다. 임시 파일과 잠금이 남으면 원본 보존 후 사람이 확인한다.

프로젝트 파일을 여러 개 잠그는 트랜잭션이나 OS 샌드박스는 아니다. JSON 크기는 2MiB로 제한하고 초과 시 원장을 바꾸지 않는다. 작업 ID 중복·잘못된 상태·역할·알 수 없는 옵션은 오류다. CLI 실패는 exit 1, brief의 미확인 원본/낡은 증거/손상 원장은 exit 3, 수집 또는 변경 완료는 0이다. blocked와 열린 게이트는 데이터이며 CLI 실패로 혼동하지 않는다.

## 호환과 배포

기존 인계 수집 구현은 중립 이름 `team-handoff.mjs`로 옮기고 기존 `hermes-handoff.mjs`는 호환 진입점으로 유지한다. 기존 호출과 출력 계약을 유지한다. Hermes 설정 예시는 선택적 참고 자료로 남긴다. README에서는 자체 기능을 먼저 안내한다. 사용법은 배포되는 `scripts/team-work.md`에 둔다. 소스와 배포 미러를 공식 sync 스크립트로 동기화한다. 설치 캐시 자동 갱신이나 Git push는 이 작업 범위에 없다.

## 검증

실패하는 테스트를 먼저 작성한다. 세션 간 상태 재로딩·역할 인계·중복 ID·손상 원장 보존·잠금 거부·연결 경로 차단·증거 해시 변경·미승인 교훈 격리·기존 인계 CLI 호환·실제 저장소의 unknown 상태를 검증한다. 기존 candidate harness와 art-gate는 그대로 쓰며 동일 검증 실행기를 중복 구현하지 않는다. 전체 테스트 결과에 기존 Windows 타임아웃 실패를 분리해 보고한다.
