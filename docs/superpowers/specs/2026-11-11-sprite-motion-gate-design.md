# 스프라이트 모션 판정 — 잘림 게이트와 보행 지표 교정 체계 (설계)

- 날짜: 2026-11-11
- 대상 스킬: `sprite-pipeline` (+ `review-loop` 읽기 전용 연동 1건)
- 상태: **설계 — 사람 승인 전. 구현 착수 전이다.**
- 빌더 체크 1회 반영 완료 (§10에 무엇이 바뀌었는지 적었다)

---

## 1. 왜 지금 이걸 하나

`.review-loop` 원장에 등록된 산출물은 104건이다. 상태 분포는 `review 90 · revise 13 · rejected 1`,
**승인은 0건**이다. 저널에 남은 사람 결정 20건에도 `approve`가 하나도 없다. 돌아가는 결과물이
안 나오는 게 아니라, 기계가 통과시킨 것과 사람이 승인하는 것이 서로 다른 축에 있다. 기계는
캔버스 정합·떨림·색 드리프트·알파를 재고, 사람은 "발이 땅에 붙었나", "칼이 잘렸나",
"허벅지가 다리 위에 겹쳐 보인다"로 결정한다. 관측 #0090이 이 간극이다.

그래서 **게이트를 먼저 만들지 않고 계측기부터 검증했다.** 사람이 이미 판정해 둔 시퀀스에 후보
지표 9개를 대고, 지표가 사람의 결정을 재현하는지를 봤다. 결과:

- **9개 중 1개**만 사람 라벨과 일치했다 (테두리 잘림).
- 1개(발들림)는 신호가 진짜지만 **보행 종류에 종속**돼 전역 임계선을 그을 수 없다.
- 7개는 긍정/부정이 겹친다.
- 사람이 가장 많이 지적한 축(**파츠 겹침**)은 측정 수단이 아직 없다.

이 설계는 그 결과를 그대로 제품화한다. **검증된 것만 게이트로 올리고, 검증 안 된 것은 측정값으로만
보고하며, 앞으로 지표가 게이트로 승격되는 절차 자체를 만든다.**

## 2. 목표 · 비목표 · 반목표

### 목표

1. **캔버스 잘림 검사** — 칼·먼지·머리가 캔버스 경계에서 잘린 시퀀스를 잡는다. 사람이 세 번
   지적했고 실제 재작업을 유발한 결함이다. **차단 등급은 §9 열린 결정이다.**
2. **보행 지표 보고** — 발들림을 측정해 리포트에 싣되 **게이트로 쓰지 않는다.**
3. **지표 승격 절차** — 사람 라벨 코퍼스와 채점 도구를 만든다. 앞으로 어떤 검사든
   "**사람이 승인한 작업을 몇 건 떨어뜨리는가**"로 채점되고, 그 수가 0일 때만 게이트가 된다.

목표 3이 본체다. 1·2는 그 절차를 통과한 결과물과 통과하지 못한 결과물이다.

### 비목표 (이번에 안 한다)

- **파츠 겹침·접합 판정.** 사람이 가장 자주 지적한 축이지만(관측 #0050) 실루엣 지표로는 구조적으로
  측정이 안 된다. 내부 지표 2종(내부 단차 비율·솔기 최대 런)도 분리에 실패했다. 미해결로 남긴다.
- **보행 방향(facing) 판정** — 관측 #0049. 별도 불변식이며 범위 밖.
- **타이밍·타격 프레임** — `polish`의 `feel-audit` 소관.
- **그림이 좋은지 / 재미** — 사람.

### 반목표 (이게 생기면 이 작업은 실패다)

1. **사람이 승인한 작업을 떨어뜨리는 게이트.** 지난 턴에 제안했던 발들림 0.25 임계선은, 라벨을
   하나 더 넣자 사람이 "너무 좋음"이라 한 걷기(0.221)를 떨어뜨리는 것으로 드러났다. 위험한
   이유는 **떨어진 작업은 사라지기 때문에 게이트가 제 일을 한 것처럼 보인다**는 데 있다 (관측 #0092).
2. **퇴화 입력이 만점을 받는 지표.** 컷아웃 전 전면 불투명 렌더는 9개 지표 중 4개에서 **최고점**을
   받았다. 0.000은 "완벽"이 아니라 "잴 게 없었다"였다 (관측 #0091·#0060).
3. **공용 원장을 기계가 변형시키는 것.** 조회 한 번이 `.review-loop/items.json`에 머신 로컬 상태를
   쓴 사례가 이미 있다 (관측 #0059). 이 설계의 어떤 도구도 원장에 쓰지 않는다.
4. **자기 게이트가 이미 통과했다고 주장하는 설계 문서.** 이 문서의 초안이 바로 그랬다 — §4C의
   승격 규칙("긍정 5건")을 세워 놓고 같은 문서에서 잘림 검사가 그 규칙을 통과했다고 적었는데,
   스스로의 정의로 다시 세어 보니 명시적 긍정은 **1건**이었다. §9로 옮겼다.

## 3. 근거 — 측정 결과

재현에 필요한 모든 정의를 §3.4에 적었다. 측정에 쓴 탐침은 세션 스크래치패드에 있고
(`crop-probe.mjs`·`crop-ref.mjs`·`gait-probe2.mjs`), **구현 시 `motion-qa.mjs`로 이식해 단일 출처로
만든다.** 스크래치패드는 세션과 함께 사라지므로 수치의 출처가 레포에 남아야 한다.

### 3.1 테두리 잘림 — 규칙은 "접촉"이 아니라 **변별 혼재**다

처음 생각한 규칙("테두리에 닿으면 미달")은 틀렸다. 상용 출하본이 닿는다. 그리고 **시퀀스 단위로
재도 틀렸다** — 이 레포의 `sprite-normalize`는 발을 baseline에 맞추는 바닥 정렬이라, 아무 변이나
닿으면 접촉으로 치면 지상 동작은 영구히 "전수 접촉"이 되고 **칼이 위로 빠져나가는 건 영영 안 보인다.**

그래서 **네 변을 각각 분류한다.**

| 라벨 | 시퀀스 | 상 / 하 / 좌 / 우 (접촉 프레임수) | 판정 | 사람이 한 말 |
|---|---|---|---|---|
| 부정 | thrust | 0 · 0 · 0 · **16 혼재** | 미달 | "칼이 캔버스 밖에서 잘리는 문제를 수정" |
| 부정 | sword-v2 걷기 | 0 · 0 · 0 · **3 혼재** | 미달 | "칼 중간에 짤리는건 어쩔 수 없나?" |
| 부정 | roll | 0 · **2 혼재** · **1 혼재** · 0 | 미달 | "먼지가 좌우 스프라이트 경계에서 잘리는 것 같음" |
| **긍정** | 은발 C안 | 0 · 0 · 0 · 0 (여백 46/48/89/**24**px) | 충족 | 잘림 수정 후 — "이정도면 잘나오는듯" |
| 언급없음 | slash-v4 | 0 · 0 · 0 · 0 (여백 39/29/23/17px) | 충족 | 각도만 지적 |
| 언급없음 | run-v2 | 0 · 0 · 0 · 0 | 충족 | — |
| 언급없음 | idle | 0 · 0 · 0 · 0 | 충족 | — |
| **부정** | **hit (피격)** | 0 · 0 · **7 혼재** · **2 혼재** (좌우 여백 0px) | **미달 ✓** | "뒤에 망토만 짤렸네 / 니가 말한 zoom 부분도 미결 사항임" (2026-11-11 확인) |
| 레퍼런스 | 사나비 Chap2_Mid_A / _B | 40전수 · 40전수 · 0 · 40전수 | 측정불가 | 상용 출하본 |
| 레퍼런스 | 사나비 Checkpoint_Signboard | 51전수 · 51전수 · 0 · 0 | 측정불가 | 상용 출하본 |
| 레퍼런스 | 사나비 Nemo | 0 · 0 · 0 · 0 | 충족 | 상용 출하본 |

**점수 (정직하게):**

- 사람 부정 **4/4 전부 잡았다.** (피격은 2026-11-11에 사람이 확인해 부정으로 확정)
- 사람 긍정 **1/1 통과.** 오거절 0.
- 상용 레퍼런스 중 시퀀스로 성립한 것 **혼재 0건.** 오거절 0. (나머지 사나비 그룹은 프레임마다
  캔버스가 달라 시퀀스가 아니다 — 규칙이 스스로 적용을 거부한다.)
- 언급 없음 3건(slash-v4·run-v2·idle)은 전부 충족.
- 접촉 정의를 1px·2px·3px로 바꿔도 **판정은 전부 동일**했다. 먼지 한 점이 거절을 만드는
  민감도 문제는 이 표본에서 나타나지 않았다. 실제 접촉 런은 6~61px로 티끌이 아니었다.

**명시적 사람 긍정은 1건이다.** 초안이 "5건"이라 적은 것은 틀렸다. 언급 없음은 긍정이 아니고,
상용 레퍼런스는 사람 라벨이 아니다.

**경고 — 라벨을 준 조건이 라벨의 일부다.** 피격 시퀀스에는 `"걷기/피격 : 너무 좋음"`이라는
사람 발언이 있다. 그런데 같은 사람이 **프레임 단위로 확대해서 보자** "중간중간 스프라이트가
미결 수준임"이라고 했다. **재생을 보고 내린 판정은 프레임 단위 판정이 아니다.** 저널 발언을
그대로 긍정 라벨로 옮기면 "사람이 승인한 작업"이라는 코퍼스의 근거 자체가 오염된다.
그래서 코퍼스는 라벨마다 **어떤 조건에서 봤는지**(`playback` / `per-frame`)를 같이 적고,
`playback` 라벨은 프레임 단위 검사의 긍정 근거로 쓰지 않는다.

### 3.2 발들림 — 신호는 진짜인데 전역 임계선이 없다

| 라벨 | 시퀀스 | 발들림 |
|---|---|---|
| 상용 | 마리 분노 걷기(무겁고 느림) | 0.254 |
| 상용 | 전사 걷기 | 0.278 |
| 상용 | 메카 걷기 | 0.387 |
| 상용 | 주인공 달리기 | 0.451 |
| 상용 | 강선 걷기 | 0.616 |
| 긍정 | scail2 걷기 ("걷기/피격 : 너무 좋음") | **0.221** |
| 부정 | rigid 걷기 (사람이 거절) | **0.202** |

- 긍정 최악 0.221 vs 부정 최선 0.202 → 여유 **0.019**. 표본 하나 추가로 0.117에서 붕괴했다.
- 상용끼리도 0.254~0.616로 벌어진다. 느린 걷기(0.254)가 일부 긍정(0.221)보다 높고, 보류 표본의
  달리기는 0.488로 걷기들(0.22~0.35)보다 높다.
- 즉 **지표는 보행 강도를 제대로 재고 있다.** 그게 단일 선을 그을 수 없는 이유다.

측정값으로는 유효, 게이트로는 무효. **보행 종류를 알기 전에는 판정할 수 없다.**

### 3.3 나머지 7개

윤곽 변화·연결 성분 최대·실낱 관절 최대·내부 단차 비율·솔기 최대 런·상하 흔들림·체고 — 긍정과
부정이 겹친다. 사람이 "허벅지가 다리 위에 겹쳐 보인다"고 지적한 v9/v10은 파일 해시가 다른데도
**6개 지표에서 소수점 셋째 자리까지 같은 값**을 냈다. 겹침은 실루엣에 흔적을 남기지 않는 내부
결함이라 실루엣 파생 지표로는 원리상 못 잡는다.

### 3.4 정의 (규범적 — 구현은 이대로 한다)

**불투명**: `alpha >= 128`. 기존 `sprite-qa`의 판정과 같은 값을 쓴다.

**변 접촉**: 해당 변의 경계 줄(상=`y=0`, 하=`y=h-1`, 좌=`x=0`, 우=`x=w-1`)에서 불투명 픽셀의
**최장 연속 런이 2px 이상**이면 그 프레임은 그 변에 접촉한 것이다.

**변 상태**: 시퀀스 N장 중 그 변에 접촉한 프레임 수 `t` → `t=0` 전무 · `t=N` 전수 · 그 사이 혼재.

**여백**: 프레임의 불투명 bbox에서 각 변까지의 거리(px). 시퀀스 보고값은 변별 최솟값.

**발들림 (`liftRange`)**: 프레임마다 불투명 bbox를 잡고, 그 폭을 **64칸**으로 나눈다. 칸 `b`의
값은 `c_b = (y1 − (그 칸의 가장 아래 불투명 행)) / bbox높이` — 0이면 바닥에 닿음, 클수록 들림.
전체 프레임의 50% 이상에서 값이 존재하는 칸만 쓰고, 칸마다 `max(c_b) − min(c_b)`를 구해 **칸 평균**을
낸다. 단위 없음, 체고 정규화라 스프라이트 크기와 무관하다.

**알파 전제**: 투명 픽셀 비율이 2% 미만인 프레임이 **과반**이면 그 시퀀스는 컷아웃 전 원본이다.
어떤 수치도 내지 않고 **측정 불가**다.

## 4. 만들 것

### A. 캔버스 잘림 검사 — `sprite-qa.mjs`에 추가

기존 `sprite-qa.mjs`는 이미 캔버스 정합과 알파 품질을 판정한다. 잘림은 같은 계열(캔버스에 대한
내용물의 적합)이므로 새 스크립트를 만들지 않는다.

**판정 (변별로 하고, 시퀀스 판정은 변별 결과를 모은다):**

| 네 변의 상태 | 판정 | 뜻 |
|---|---|---|
| 한 변이라도 **혼재** | **잘림** | 여백을 두고 잡은 캔버스를 어떤 포즈가 넘었다 |
| 혼재 없고 한 변이라도 **전수** | **측정 불가** | 그 변엔 여백 설계가 없다 — 타이트 크롭인지 전부 잘린 건지 구분할 수 없다 |
| 전부 **전무** | **충족** | 네 변 모두 여백이 있다 |

**전수를 "통과"로 두지 않는 이유**가 중요하다. 초안은 전수를 정상(타이트 크롭)으로 통과시켰는데,
그러면 **컷아웃 전 전면 불투명 렌더가 네 변 전수 → 통과**로 떨어진다. 반목표 2가 그대로 재현된다.
전수는 "괜찮다"가 아니라 "이 변으로는 판정할 수 없다"가 맞다. 알파 전제 검사가 전면 불투명을
먼저 걸러내지만, 두 방어선을 다 둔다.

`--tight-crop <변목록>`으로 사람이 "이 변은 원래 여백이 없다"고 선언할 수 있다. 선언된 변의
전수는 측정 불가에서 빼고 통과로 본다. **선언 없이 도구가 스스로 면제하지 않는다.**

리포트에는 변별 접촉 프레임 수·상태·최소 여백 표를 싣는다. "여백 24px"은 사람이 인계 문서에
실제로 쓰는 수치다.

**종료 코드 (기존 레포 계약 유지):** `validate.yml`의 "판정 도구 입력-없음 계약(전부 exit 3)"을
깨지 않는다. 한 도구 안에 여러 검사가 있을 때:

- 미달이 하나라도 있으면 **1**. (실제 결함을 찾은 실행은 미달 보고가 맞다.)
- 미달이 없고 측정 불가가 있으면 **3**. 리포트 [주장]에 어느 검사가 왜 측정 불가인지 적는다.
- 전부 충족이면 **0**.

### B. 보행 지표 — 새 스크립트 `motion-qa.mjs` (게이트 아님)

`sprite-qa.mjs`에 넣지 않는다. 그건 "미달이면 exit 1"인 게이트 도구이고 발들림은 게이트가
아니다. 섞으면 나중에 누군가 임계선을 켠다.

```
node skills/sprite-pipeline/scripts/motion-qa.mjs <프레임폴더> [--gait walk|slow-walk|run|other]
```

1. **알파 전제 검사 먼저** (§3.4). 걸리면 `exit 3`, 숫자 없음.
2. 발들림·윤곽 변화·상하 흔들림·연결 성분을 측정해 **보고만** 한다.
3. `--gait`가 주어지고 그 종류의 교정 대역이 §4C에 **존재할 때만** 대역 대비 위치를 표시한다.
   없으면 "이 보행 종류의 교정 표본이 N건이라 대역이 없다"고 적는다.
4. 통과/미달을 판정하지 않는다. 정상 종료 `0`, 측정 불가 `3`.

보행 종류는 **입력받고 추론하지 않는다.** 발들림으로 종류를 추론한 뒤 그 종류의 대역으로 발들림을
판정하면 순환이다.

### C. 교정 코퍼스와 채점 도구 ← 본체

**`skills/sprite-pipeline/references/motion-labels.json`** — append-only.

```jsonc
{
  "schemaVersion": 1,
  "ingestCursor": "<마지막으로 훑은 reviews.jsonl 행 id>",
  "samples": [
    {
      "id": "scail2-sword-v2-walk",
      "kind": "human",                 // human | reference
      "artifact": "out/sprite-lab/scail2-sword-v2-alpha",   // 동작 단위 폴더
      "action": "walk",                // 원장 항목 1개 → 표본 N개
      "subject": "fantasy",            // 대상 교란 추적
      "gait": "walk",                  // walk|slow-walk|run|other|null. 보행 동작일 때만
      "labels": {                      // 축별 사람 판정
        "motion": "positive",          // positive | negative | null(언급 없음)
        "canvasFit": "negative",
        "partAttachment": null,
        "identity": null
      },
      "quote": "모션은 딱 좋은데 칼 중간에 짤리는건 어쩔 수 없나?",
      "viewing": "playback",           // playback | per-frame. 어떤 조건에서 보고 내린 판정인가
      "source": ".review-loop/reviews.jsonl#<행 id>",
      "measured": { "liftRange": 0.221, "cropSides": { "right": "혼재" } },  // 캐시(§5 Q2)
      "measuredOn": "macjo-main",
      "recordedAt": "2026-11-11"
    }
  ]
}
```

설계상 중요한 네 가지:

- **축별 라벨이다.** 사람은 한 문장에서 모션은 칭찬하고 잘림은 지적한다. 시퀀스에 단일
  좋음/나쁨 라벨을 붙이면 모션 지표가 잘림 때문에 오거절당한다. 축은 넷 —
  `motion` · `canvasFit` · `partAttachment` · `identity`. 저널 20건이 실제로 이 넷으로 갈린다.
- **표본 단위는 원장 항목이 아니라 동작 폴더다.** `demo.fantasy.motion-court@1` 한 항목 안에
  걷기·피격·베기·찌르기가 있고 판정이 서로 다르다 — "걷기/피격 : 너무 좋음 / 베기 : 뒤로 확
  이동 / 찌르기 : 어색". 항목 하나를 표본 하나로 잡으면 이 한 줄이 긍정 2·부정 2를 동시에
  만들어 채점이 망가진다.
- **`viewing: playback` 라벨은 프레임 단위 검사의 긍정 근거가 아니다.** §3.1의 경고가 근거다.
  재생으로 "좋다"고 한 시퀀스가 확대해서 보면 미결일 수 있고, 실제로 그랬다. 승격 규칙의
  "긍정 5건"은 `viewing: per-frame` 긍정만 센다. `playback` 긍정은 기록은 하되 세지 않는다.
- **`kind: reference`는 오거절 검사 전용이다.** 상용 출하본(사나비)은 사람 라벨이 아니라
  **"이걸 떨어뜨리면 규칙이 틀린 것"**이라는 반증 표본이다. `quote` 대신 출처(게임·추출 경로)를
  적고, **검출력 계산에는 절대 쓰지 않는다.** 초안이 긍정 수를 부풀린 원인이 이걸 안 나눠서였다.
- **`.review-loop/`에 쓰지 않는다.** 원장은 사람 결정의 정본이고 두 PC가 공유한다. 코퍼스는
  거기서 **읽어 파생한 사본**이며 `source`로 출처를 가리킨다 (반목표 3 / 관측 #0059).

**`skills/sprite-pipeline/scripts/motion-calibrate.mjs`** — 채점 도구.

```
node ... motion-calibrate.mjs --check <검사id> --axis canvasFit
node ... motion-calibrate.mjs --check footLift --axis motion --gait walk --threshold 0.25
```

- **검사는 술어(predicate)로 받는다. 스칼라 임계선은 그 한 종류일 뿐이다.** 잘림 규칙은
  범주형(혼재/전수/전무 + 면제 분기)이라 `--metric X --threshold N` 형태로는 채점할 수 없다.
  그러면 승격 절차를 정의한 도구가 정작 승격시킬 규칙을 채점 못 하고, 잘림 검사만 손으로
  특례 통과하게 된다. 각 검사는 `(시퀀스) -> '충족'|'미달'|'측정불가'` 함수를 export 하고,
  채점 도구는 그 함수를 코퍼스 전체에 돌린다.
- 출력 맨 위는 항상 **오거절 건수와 그 표본의 사람 발언**이다. 여유(margin)는 그 아래다.
  여유를 먼저 보면 이번처럼 틀린 선을 제안하게 된다 (관측 #0092).
- 그다음 줄은 **상용 레퍼런스 거절 건수**, 그다음이 검출력, 그다음이 측정 불가·건너뜀 수.

**승격 규칙:**

> 검사가 게이트(미달 등급)가 되려면 네 조건을 모두 만족해야 한다.
> 1. 해당 축에 `kind:human` **긍정 라벨 5건 이상**
> 2. 그 긍정을 **한 건도 떨어뜨리지 않음**
> 3. `kind:reference` 표본을 **한 건도 떨어뜨리지 않음**
> 4. 해당 축의 사람 부정을 **과반 이상 잡음**
>
> 1번만 미달이고 2·3·4를 만족하면 **경고 등급**으로 넣을 수 있다(게이트를 막지 않는다).
> 어느 것도 못 하면 측정값으로만 보고한다.

**지금 상태로 적용하면:** 잘림 검사는 2·3·4를 만족하고(오거절 0, 레퍼런스 거절 0, 부정 3/3)
**1번에서 걸린다(긍정 1건).** 규칙대로면 **경고 등급**이다. 발들림은 보행 종류 라벨이 없어
어느 것도 못 하므로 측정값 보고만 한다.

### D. 코퍼스 유입 경로 — `motion-labels.mjs ingest`

이게 없으면 코퍼스는 과거 20행에서 얼어붙고, 어느 축도 긍정 5건에 도달하지 못하고, 어떤 검사도
영영 승격되지 않는다. **관측 #0090(아무도 도달할 수 없는 종료 상태)과 똑같은 모양이다.**

```
node ... motion-labels.mjs ingest        # 제안만 출력
node ... motion-labels.mjs ingest --apply --from <행id>
```

- `.review-loop/reviews.jsonl`을 **읽기만** 한다. `ingestCursor` 이후의 사람 결정 행을 훑는다.
- 행 하나를 동작 단위 표본 후보로 쪼개고, 문장에서 축별 라벨과 보행 종류를 **제안**한다.
- 제안을 표로 출력한다. `--apply` 없이는 아무것도 쓰지 않는다.
- 사람이 확인한 뒤 `--apply`로 코퍼스에 append 하고 `ingestCursor`를 옮긴다.
- 자동 라벨링은 하지 않는다. 사람 발언의 해석은 사람이 확인한다.

이게 문서 머리말의 "`review-loop` 읽기 전용 연동 1건"이다.

## 5. 열린 질문에 대한 답 (초안에서 미정이던 것)

**Q1. 보행 종류 라벨을 누가 붙이나.** → §4D. 도구가 제안하고 사람이 `--apply`로 확정한다.

**Q2. 코퍼스가 `out/` 같은 gitignore 경로를 가리켜도 되나.** → **(a)+(b) 둘 다 한다.**
읽을 수 없는 표본은 측정 불가로 건너뛴다. **그리고 측정값을 코퍼스에 캐시한다**(`measured`·
`measuredOn`). 캐시 없이 건너뛰기만 하면, 두 번째 PC에서는 로컬에 우연히 남아 있는 것만으로
"오거절 0, 긍정 N건"이 계산돼 **승격 판정이 기계마다 달라진다.** 그래서:

> `motion-calibrate`는 **코퍼스 표본을 전부 읽거나 캐시로 메울 수 있을 때만 승격 판정을 낸다.**
> 하나라도 메울 수 없으면 표본별 결과는 출력하되 **승격 판정은 "측정 불가"로 거부한다.**

검사 구현이 바뀌면 캐시는 무효다. 캐시 항목에 검사 버전을 같이 적고, 버전이 다르면 캐시를 쓰지 않는다.

## 6. 내가 정한 것 (사람 결정 아님)

- 잘림 검사는 `sprite-qa.mjs`에, 보행 지표는 별도 `motion-qa.mjs`로 — 게이트와 비게이트를 한
  종료 코드에 섞지 않기 위해서.
- 코퍼스는 `references/` 아래. 이 레포의 스킬은 `scripts/`와 `references/`만 쓴다.
- 종료 코드는 기존 체계(0 충족 / 1 미달 / 2 사용법 / 3 측정 불가)를 재사용하고, 혼합 시 미달 우선.
- 보행 종류는 입력받고 추론하지 않는다.
- 변 하나라도 혼재면 미달 — 혼재 프레임이 1장이어도. (sword-v2가 3/25로 실제 지적을 받았다.)
- 전수는 통과가 아니라 **측정 불가**. `--tight-crop` 선언이 있을 때만 통과.
- 접촉 정의는 최장 연속 런 2px. 1·3px에서도 판정이 같았으므로 민감하지 않은 영역의 중앙값.
- `kind: reference`는 오거절 검사에만 쓰고 검출력에 쓰지 않는다.
- 채점 도구는 스칼라가 아니라 술어를 받는다.
