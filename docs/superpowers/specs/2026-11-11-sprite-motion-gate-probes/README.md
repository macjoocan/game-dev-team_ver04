# 측정 탐침 — 설계 §3의 수치를 낸 일회용 계측기

[2026-11-11-sprite-motion-gate-design.md](../2026-11-11-sprite-motion-gate-design.md) §3의 모든
수치는 여기 있는 스크립트가 낸 것이다. **지원되는 도구가 아니다** — 설계가 구현되면
`skills/sprite-pipeline/scripts/motion-qa.mjs`와 `sprite-qa.mjs`가 이 역할을 가져가고,
이 폴더는 근거 기록으로만 남는다.

이걸 레포에 남기는 이유: 설계 문서가 "오거절 0", "부정 4/4", "발들림 0.221 vs 0.202" 같은
수치를 근거로 결론을 내리는데, 그 수치를 만든 기구가 세션 스크래치패드에만 있으면 다른 PC에서
**검증할 수 없는 주장**이 된다. 빌더 체크가 이걸 지적했다.

| 파일 | 낸 것 |
|---|---|
| `crop-probe.mjs` | §3.1 라벨 세트의 변별 접촉·여백 표. 접촉 정의를 1·2·3px로 바꿔가며 판정 안정성도 같이 본다 |
| `crop-ref.mjs` | §3.1 사나비 상용 레퍼런스의 변별 접촉 (오거절 검사) |
| `gait-probe2.mjs` | §3.2 발들림과 후보 지표 9종. 알파 전제 가드가 들어 있다 |
| `hit-sheet.mjs` | §9 결정 1의 증거 — 피격 접촉 프레임만 뽑아 닿은 픽셀을 표시한 시트 |

## 돌리기 전에 알아야 할 것

- **경로가 하드코딩돼 있다.** `D:/00.project/GameDevTeam`(레포)과
  `D:/00.project/GameGogo/out_sanabi_final/...`(사나비 추출본)을 그대로 쓴다. 다른 PC에서는
  맨 위 상수를 고쳐야 한다.
- **대상 산출물이 `out/` 아래라 gitignore 대상이다.** 그 PC에 산출물이 없으면 수치가 재현되지
  않는다. 설계 §5 Q2가 이 문제를 다룬다(코퍼스에 측정값 캐시).
- 레포 루트에서 `node <파일>`로 돌린다. 내부에서 `scripts/lib-png-read.mjs`·`lib-png.mjs`를
  `file:///` 절대 URL로 import 한다 — Windows에서 `D:/...` 맨 경로는 ESM이 거부한다.
- 탐침이지 검사 도구가 아니다. 종료 코드 규약도, 테스트도 없다.
