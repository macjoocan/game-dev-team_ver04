# Multi 3D 제작 이력과 재사용 절차

2026-10-16 · Multi에서 전달받은 제작 이력과 후속 자동화 검토 자료.

동작·리그를 먼저 확보하고 외형을 맞추는 순서를 후속 제작의 기준으로 삼는다. 생성된 외형을 기존 리그에 붙일 때는 뼈 이름뿐 아니라 rest 관절 위치·체형·가중치를 함께 맞춰야 한다.

## 최신 갱신 원화와 Standard 제작 기준

사람 확인한 기본 흐름은 **모션·리그 요구 확인 → GPT 원화 → 이미지 기반 Standard 3D → Blender 정리·검수**다. 잘 나온 기준 원화를 재사용해 생성 사용량을 줄이고, ComfyUI 보정·변형은 선택적으로 검토한다. 텍스트 단독3D는 별도 요청 때 사용한다. 이번 원화 비교의 GPT 선호와 별도2D 걷기 시험의 Ludo 선호는 서로 다른 평가다.

Multi의 Standard 연구는 누계5건·High추가0건이다. 이미지 입력에는 `provider=hunyuan3d`, `quality=standard`를 명시했다. 해당 연결에서 Tripo 이미지 입력은High로 계산됐다. 실제 제공량·잔여량은 계정 패널 확인 전 단정하지 않는다.

Standard 원본은 약139~150만삼각형·2K PBR·약42~46MB, 표시용은 약6만삼각형·약3.6~7MB다. Standard라는 이름을 저폴리·리깅·모션 준비 완료로 해석하지 않는다. 원본을 보존하고 표시용 축소 사본을 분리한다.

ComfyUI0.39/RTX5060 8GB 시험에서 기존 GPT원화+SDXL img2img denoise0.28은 얼굴·의상·구도를 상당 부분 유지했다. 독립 신규 디자인 생성과 구분한다. Animagine4의 공식 태그·CFG5·Euler a·28steps는2D캐주얼 원화를 개선했고 그 원화의 Standard3D도 별도 요청1건으로 완료했다. 모델과 프롬프트 설정을 함께 바꾼 시험이므로 모델 단독 효과로 분리하지 않는다.

다른 캐릭터 변형은 img2img0.50~0.60에서 원본에 묶였고,0.75~0.80에서는 인물 구분이 생겼으나 손 자세·체형·의상색이 이탈했다. 팀 전체 자동 양산 검증이 아니다. Animagine3D 눈썹·윗눈꺼풀 돌출과 앞머리 겹침은117정점 투영 실험 후에도 미해결·미채택이며 기본GLB를 유지한다.

수신 근거: [갱신된 문서37](3d-production-handoff-2026-10-16/latest/source-37.txt), [Standard 연구 문서38](3d-production-handoff-2026-10-16/latest/source-38.txt), [캐릭터 변형 문서39](3d-production-handoff-2026-10-16/latest/source-39.txt), [출처·해시](3d-production-handoff-2026-10-16/latest/provenance.json). 아래 초기 제작 이력과 최초 원문은 그대로 보존한다.

별도 공유된 [Motion Remap0.2 지원 범위와 검증 기록](motion-remap-0.2-2026-10-16.md)도 함께 참고한다. 리타기팅 기법의 추가가 기존 모델의 스킨 가중치·토폴로지를 자동 교정했다는 뜻은 아니다.

## 주장과 적용 범위

이 문서는 Multi 세션의 제작 기록을 공유한다. 아래 수치는 전달 문서에 기록된 결과이며 이 저장소에서 모델을 다시 열거나 측정한 결과는 아니다. 현재 Multi의 활성 단계는 파티 서빙 P-0, 사람 확인 대기다. 이 공유로 게이트나 반복 예산을 변경하지 않는다.

원문은 [수신 당시 원본](3d-production-handoff-2026-10-16/source.txt)에 바이트 그대로 보존했고, [출처와 SHA-256](3d-production-handoff-2026-10-16/provenance.json)을 함께 기록했다. 원문 안의 상대 경로와 Markdown 링크는 `C:/00.SVN/Multi/web/docs/` 또는 명시된 Multi 프로젝트 루트 기준이다. 모델·스크립트·검증 JSON은 Multi에 있으며 이 커밋에는 복사하지 않았다.

MB는 원문 기준 십진 반올림이다. 팬 캐릭터 시험과 CC0 기준 몸의 라이선스를 다른 에셋의 재사용 권한으로 확대하지 않는다.

### 실제 보정 사례

- 미쿠 어깨 폭을 **0.3838m → 0.284m**, 무릎 높이를 **0.5318m → 0.65m**로 보정하고 겨드랑이·엉덩이·발목 연결과 가중치를 조정했다. 해당 모델의 수치이며 다른 체형에 일괄 적용하지 않는다.
- 분리된 머리카락 6조각에서 몸·다리 가중치를 제거했다. 가까운 표면의 가중치를 옮길 때 머리카락·치마·소품을 별도로 확인한다.
- 미쿠 v2는 원본과 이름·계층·동작 소스를 공유하지만 rest 관절과 가중치는 다르다. 초기 캐주얼 비교의 ‘뼈 행렬 차이0’를 v2의 검증 결과로 사용하지 않는다.
- `high` 생성 옵션은 하이폴이나 관절 토폴로지를 보장하지 않았다. Subdivision으로 늘린 면 수와 새 조각 디테일, 애니메이션 변형 품질을 각각 구분한다.

## 제작과 검증 기준

1. 필요 행동과 실제 카메라를 정하고 검증된 기본 몸·리그·동작을 확보한다.
2. 관절에 맞는 원화로 외형을 만들고 체형·rest 자세·관절·가중치를 보정한다.
3. 기준과 수정본을 같은 클립·같은 시각에 정면·측면·뒷면에서 비교한다.
4. GLB를 내보내고 실제 게임의 조명·카메라·4명 표시·손발·도구·타격 시점을 확인한다.
5. 같은 stable ID의 새 버전으로 등록하고 사람의 최종 승인을 별도로 남긴다.

생성 재시도 전에 기존 job 상태와 로컬 출력을 확인한다. 원화/source/raw/final/preview/provenance를 보존한다. 연결 중단만으로 새 유료 생성을 시작하지 않는다.

기본 출력은 GLB, 단위는 미터, 피벗은 발 중심이다. 캐릭터는 +Y 위/+Z 앞이지만 올빼미에는 -Z 앞 기록이 있으므로 에셋별로 확인한다. 캐주얼·미쿠의65뼈와 뗏목·서빙의17뼈를 같은 리그로 취급하지 않는다.

뗏목·서빙6클립의 이름은 `Idle`, `Walk`, `Row`, `Repair`, `Repel`, `Rescue`다. 서빙에 연결됐다는 사실을 서빙 전용 완성 연기로 해석하지 않는다.

캐주얼 비교는11클립×9시점에서 기준·외형의 뼈 행렬 차이0을 기록했다. 미쿠 v2의11×9시점 유한값·시간 확인은 전체 자기 관통 검사가 아니다. 뗏목은6클립×3시점, 서빙은4명 로드와 행동 연결을 확인했다. 원문의 기능 테스트165/165·빌드 성공은 이전 실행 기록이며 자연스러움·재미·최종 아트 승인 근거가 아니다.

## 공백과 후속 자동화 제안

게임별 모델·스킨·뼈·bind/rest·클립·텍스처·도구/소켓 자료는 아직 미수령이다. 후보와 전달 규격은 Multi의 `web/docs/36-animation-reference-games.md`에 있다. 추출 가능 여부와 리그 호환은 미검증이다.

자료 수신 후 제안하는 순서는 스켈레톤별 그룹화 → 대표 캐릭터의 대기·이동·공격·피격 확인 → rest/축/체형 매핑 → 3등신 리타기팅 → 손발·도구 접촉 보정 → 일괄 export·미리보기·검수 등록이다. 파일 검사·매핑 프리셋·클립 목록·반복 export는 자동화 후보이며 전 자동 완성은 확인되지 않았다.

root motion·IK·additive·events·physics를 구분한다. 물리 반응 결과가 독립 클립으로 존재한다고 가정하지 않는다. 분석 가능성과 출시용 재사용 권한도 따로 기록한다.

## 잔여 위험과 상태 보존

긴 머리·치마의 물리 충돌, LOD, 최종 성능 예산, 완성 모션과 최종 아트 승인은 남아 있다. 이번 공유에서는 모델·스크립트 실행, 게임 테스트, 서버 생존 확인을 다시 수행하지 않았다.

Multi의 `party/`, `sim/`, 보류한 프로토, 타 세션 변경을 보존한다. 활성 개발 상태는 Multi의 `docs/pipeline/state.json`과 `lastHandoff`, 에셋 검수 상태는 해당 프로젝트 `.review-loop/`를 따른다. 이 문서는 플러그인 동작이나 원본 프로젝트의 승인 상태를 바꾸지 않는 공유 기록이다.
