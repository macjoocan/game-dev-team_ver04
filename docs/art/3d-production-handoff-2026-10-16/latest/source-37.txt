**동작·리그를 먼저 고르고 외형을 맞추는 방식이 후속 제작의 기준.**

이미지→3D는 정지 상태 외형을 빠르게 확인하는 데 유용했음. 생성 메시를 그대로 기존 동작에 넣는 단계에서 어깨·무릎·치마·머리카락 문제가 발생했음. 같은 뼈 이름만으로 체형 호환을 보장할 수 없음.

```text
필요 행동·카메라 정리
 → 검증된 기본 몸·리그·동작 확보
 → 관절에 맞는 원화
 → 외형 제작/이미지→3D
 → 체형·관절·가중치 보정
 → 같은 시간의 원본/수정본 비교
 → GLB·실제 게임 검수
 → 같은 stable ID에 새 버전 등록
```

생성 메시에는 원본 리그의 뼈·면 구조·가중치가 자동 보존되지 않았음. 현재 맞춤 17뼈 동작은 프로토 시안이며, 자연스러운 완성 모션 확보와 구분 필요.

## 5. 애니메이션·내보내기 기준

- 기본 출력 GLB. 단위 미터, 발 중심 피벗. 캐릭터는 GLB +Y 위/+Z 앞. 올빼미는 기존 -Z 전방 기록이 있으므로 일괄 가정 금지.
- 캐주얼/미쿠 기반은65뼈. 뗏목/서빙은 맞춤17뼈. 서로 같은 리그로 처리하지 않음.
- 선택 라이브러리11클립: 대기·걷기·조깅·질주·웅크림 대기/이동·점프 시작/공중/착지·상호작용·가슴 피격.
- 뗏목/서빙6클립 원본 이름: `Idle`, `Walk`, `Row`, `Repair`, `Repel`, `Rescue`. 서빙 전용 완성 연기로 오해하지 않음.
- 뼈·가중치·동작 내보내기와 게임 상태 전환을 각각 확인. 무기/도구 부착과 실제 타격 판정도 별도 확인.
- 장식 메시가 이동 충돌을 바꾸지 않도록 기존 게임 프록시 유지. LOD 추가·최종 성능 예산은 미결.

최신 전체 기능 테스트는165/165·빌드 성공(박물관 RDP 입력8개 추가 포함). 모델 자연스러움·게임 재미 통과 근거가 아님. 기존 Three.js 공용 청크500KB 초과 경고는 남아 있음. 이번 인수인계 작성에서는 빌드·게임 테스트 재실행 없음.

## 8. 다음 자동화 작업

사람이 게임별 모델·동작 데이터를 확보해 전달할 예정. 아직 받은 데이터 없음. [생활4종·액션8종 후보와 전달 규격](36-animation-reference-games.md)에 정리됨. 실제 추출 가능 여부·리그 호환·포함 클립은 미검증.

```text
게임별 원본 보존/파일 목록
 → 스켈레톤별 그룹
 → 대표 캐릭터1개: 대기·이동·공격·피격 확인
 → rest 자세·축·체형별 매핑
 → 3등신 리타기팅 시안
 → 손발/도구 접촉 보정
 → 동작 일괄 변환·미리보기·검수 등록
```

필요 자료: 스킨 메시+뼈+bind/rest 자세+동작+텍스처. 무기/소켓과 상대가 맞물리는 동작의 위치 기준도 함께 확보. 원본 이름/폴더 보존. OBJ만으로는 같은 수준의 리그 자동화가 어려움.

root motion·가산 동작·IK·이벤트·물리 반응을 각각 분류. Party Animals 같은 물리 결과는 독립 클립으로 존재한다고 가정하지 않음. 분석 자료와 출시용 재사용 권한을 구분해 기록.

자동화 가능한 후보: 파일 검사·뼈 매핑 프리셋·클립 목록/미리보기·반복 export·대시보드 등록. 체형/관절·가중치·손발 접촉·치마/머리 충돌은 샘플을 보고 가능 범위를 판단. 전 자동 완성은 미검증.

## 9. 후속 세션에 요청할 범위

- 먼저 이 문서와 원본 스크립트/검증 파일을 읽고 재사용 가능한 절차를 선별.
- 플러그인에 반영할 때는 ‘실제 확인한 절차’와 ‘자동화 제안’을 구분.
- 작업 이력 공유가 새 유료 생성·모델 변경·배포·게이트 승인까지 뜻하지 않음.
- `party/`, `sim/`, 보류한 프로토와 타 세션 변경 보존.
- 활성 개발 정본은 `docs/pipeline/state.json`과 `lastHandoff`. 본 문서는3D 인수인계 정본.

기존 위키 이력: [3D 작업 히스토리](https://nhncorp.dooray.com/wiki/2668173571253827735/4443942959895757018). 10월15일 게시분이며 뗏목·서빙 최신 모델까지 포함한 정리는 이 문서 참조. 위키 추가 게시 없이 세션에 전달.
