## 1. 지금 할 수 있는 것

**GPT 원화 제작부터 스프라이트 검수, 도트 변환, 웹 액션 스테이지까지 연결했습니다.**  
최근에는 실제 검술 교본을 참고해 은발 캐릭터의 베기를 개선했습니다.

최신 걷기 v3와 베기 v6는 별도 검수 후보입니다. 기존 액션 스테이지에 새 후보를 교체하는 작업은 아직입니다. 아래 검증 결과는 보존된 실행 기록이며, 위키 작성일에 모두 다시 실행한 것은 아닙니다.

| 분야 | 확보한 성과 | 현재 상태 |
|---|---|---|
| 원화·걷기 | 은발 외형 유지, 팔 동작·다리 교차를 고친 GPT 8포즈 | 걷기 v3 긍정 평가. 게임 반영 전 |

| 공통 이펙트 | 2D·3D 제작 규격, 샘플 4종, 예산 검사 | 규격 충족. 실제 엔진 검증은 별도 |

## 2. 실행 가능한 액션 1스테이지

GPT로 배경·적·핵심 자세·이펙트를 제작했습니다. 기존 걷기·베기와 묶어 실행용 이미지 묶음(아틀라스) 81프레임을 구성했습니다. 사망·재시작·탈출까지 연결했습니다.

![액션 스테이지의 큰 베기와 명중 화면](/files/4464165020254091344)

*커진 베기 궤적과 명중 화면입니다. 최신 베기 v6를 적용한 화면은 아닙니다.*

| 항목 | 구현 내용 |
|---|---|
| 연속 공격 | J 연타로 베기·되베기·마무리 연결. 다음 한 동작만 예약 |
| 명중 반응 | 피해·피격 자세·밀림·소리와 함께 화면 동작을 잠깐 정지 |
| 명중 정지 | 타격 종류에 따라 50/67/83ms. 빗나가면 적용하지 않음 |
| 큰 베기 효과 | 기존 대비 궤적을 1.50~1.73배 확대 |
| 달리기 | 같은 방향을 두 번 누르고 유지. 기존 걷기를 빠르게 재생하는 임시 표현 |
| 코드 구조 | 전투 규칙과 화면을 분리. 전투·연출 수치는 별도 설정 파일에서 관리 |

전투 검사는 **15/15 통과**했습니다. 자동 플레이에서는 적 7명 처치와 탈출을 확인했습니다. 사람의 승률이나 재미 점수를 측정한 결과는 아닙니다.

## 3. 걷기와 도트 변환

### 걷기: 색 유지와 관절 동작을 나눠 개선

처음 만든 시트는 색 분리는 좋았지만, 칼 든 팔이 고정돼 있었습니다. 다리 교차도 부족했습니다. 기존 선호 동작을 참고해 수정한 걷기 v3에는 긍정 평가가 있었습니다.

![걷기 v1과 팔·다리를 수정한 v3 비교](/files/4464165024373950567)

*왼쪽은 걷기 v1, 오른쪽은 팔·다리를 수정한 v3입니다. 두 시안은 같은 8fps로 비교했습니다.*

걷기 v3는 384×512 프레임 8장입니다. 정합성 검사는 충족했고 경계 접촉은 0/8이었습니다. 최소 여백은 15px입니다. 작은 알파 잔여물과 프린지(반투명 테두리) 경고는 남습니다.

**자동 검사 통과가 자연스러운 걷기를 보장하지는 않습니다.** 발 접지와 마지막·첫 프레임 연결은 사람 검수가 필요합니다.

[걷기·검사 개선 기록](https://github.com/macjoocan/game-dev-team_ver04/blob/cdd14a658c801bfa3d07a2492c3a2ecb4adbb6b0/docs/handoffs/2026-11-11.md)

### PixelOE: 같은 원본으로 도트 크기 비교

기존 은발 걷기 26장에 단순 축소와 PixelOE를 적용했습니다. 후보당 26장, 총 104장입니다. 전체에 같은 32색 팔레트를 사용했습니다.

![원본·단순 축소·PixelOE 64·96·128px 비교](/files/4464165019869065409)

*왼쪽부터 원본, 단순 축소 96px, PixelOE 64·96·128px입니다. 숫자는 캐릭터 키가 아닌 캔버스 높이입니다.*

최대 32색, 반투명 픽셀 0, 경계 접촉 0/26을 확인했습니다. 사용자는 긍정 평가했지만 크기를 선택하지는 않았습니다. 외톨이 픽셀 비율 때문에 자동 도트 검사는 네 후보 모두 미달입니다.

도구: PixelOE 1.0.1, Apache-2.0. 이번 변환의 추가 유료 호출은 0회입니다.

## 4. 최신 베기: 교본 참고와 팔 중복 수정

속도만 바꾼 초기 비교는 차이가 작았습니다. 준비·통과·마무리 시간을 나눈 뒤 리듬은 좋아졌지만, 휘두르는 자세가 어색하다는 피드백을 받았습니다.

이후 큰 검 궤적을 시험하고, [마이어의 1570년 두삭 교본](https://sprechfenster.org/meyer/1570/dusack-chapter-3-the-four-cuts/)을 참고했습니다. 높은 준비 자세와 몸 반대편까지 이어지는 베기를 게임용으로 각색했습니다. 교본은 연속 프레임 자료가 아니며, 실제 검술을 정확히 복원한 결과로 보지 않습니다.

| 단계 | 변경 | 확인한 결과 |
|---|---|---|
| v1·v2 | 내려베기 제작과 여백 수정 | 타이밍 차이만으로는 부족 |
| v3·v4 | 상체 동작과 큰 각도 변화 추가 | 찌르기처럼 보이는 문제와 자세 개선 요구 |
| v5 | 교본 참고, 몸 반대편까지 베기 | 긍정 평가 뒤 317ms 팔 중복 발견 |
| v6 | 6번 자세의 여분 팔 제거 | 나머지 7개 PNG의 해시 일치 확인. 재검수 대기 |

![317ms 팔 중복 수정 전 v5와 수정 후 v6](/files/4464165021577397363)

*317ms의 같은 자세 비교입니다. 왼쪽 v5의 여분 팔을 오른쪽 v6에서 제거했습니다.*

최신 베기는 512×512 프레임 8장, 총 460ms입니다. 문제 자세는 240ms 이상 340ms 미만에 표시됩니다. 수정 전후 시간표는 같습니다.

[베기 v5·v6 비교 HTML 내려받기](dooray://1387695619080878080/page-files/4464165168678653892)

파일을 내려받아 브라우저로 열면 이미지가 함께 재생됩니다. 서버·GPU·생성 API는 필요 없습니다. 317ms를 선택하거나 0.5배속으로 앞뒤 연결을 비교할 수 있습니다. 근거 문서 링크를 열 때는 인터넷이 필요합니다.

[베기 인수인계](https://github.com/macjoocan/game-dev-team_ver04/blob/cdd14a658c801bfa3d07a2492c3a2ecb4adbb6b0/docs/handoffs/2026-11-11-slash.md) · [팔 수정 보고·검사 원문](https://github.com/macjoocan/game-dev-team_ver04/blob/cdd14a658c801bfa3d07a2492c3a2ecb4adbb6b0/out/experiments/silver-reference-slash-20261111/ARM-REPAIR.md)

## 5. 제작을 반복할 수 있게 만든 기술

| 기술 | 이번에 확인한 범위 | 구분할 한계 |
|---|---|---|
| 원화와 모션 분리 | GPT 외형을 유지하고 동작·프레임·시간표를 별도로 비교 | 원화 생성과 전체 제작이 무료라는 뜻은 아님 |
| 프레임 정규화 | 공통 캔버스와 기준점, 파일별 해시 기록 | 하단 정렬만으로 발 접지를 검증하지 못함 |
| 정합성 검사 | 빈 피사체·배경 부족·크기 혼합을 측정 불가로 처리 | 실패한 프레임을 빼고 통과시키지 않음 |
| 모션 관찰 | 하단 윤곽과 인접 프레임 변화 측정 | 발 들기·모션 품질 점수가 아님 |
| 부분 수정 | 문제 프레임만 교체하고 나머지 파일의 해시 비교 | 손·팔 개수와 관절 연결은 별도 육안 검수 |
| 검수 기록 | 원본·후보·사용자 발언·QA를 같은 검수 보드에 보존 | 긍정 평가를 출시 승인으로 바꾸지 않음 |
| 엔진 공통 FX | 2D 시트, 3D 링 메시·파티클 데이터, 샘플 4종 제작 | 실제 엔진의 GPU 비용·중첩·플래시는 미검증 |

초기 Ludo 생성 실험은 있었습니다. 이후에는 보유한 동작과 로컬 후처리를 재사용하는 방향으로 진행했습니다. 최신 GPT 이미지·베기 수정에서는 별도 유료 영상 API로 전환하지 않았습니다.

[검사 도구 구현 근거](https://github.com/macjoocan/game-dev-team_ver04/blob/cdd14a658c801bfa3d07a2492c3a2ecb4adbb6b0/docs/art/sprite-motion-observer-2026-11-11.md) · [공통 FX 검사 원문](https://github.com/macjoocan/game-dev-team_ver04/blob/cdd14a658c801bfa3d07a2492c3a2ecb4adbb6b0/out/fx-common-v2-qa/fx-check.json)
