# Ludo 공개 로직 조사와 은발 걷기 검증

확인일: 2026-11-06. 프로젝트 커밋: `4c43b68`.
조사 소스: Ludo CLI 0.2.5, `34d13c3f04a229cad39e40aa3fab0327f004edf2`.

## 주장

Ludo의 공개 후처리 코드를 우리 스프라이트 파이프라인에 활용할 수 있다. 공식 CLI는 MIT 라이선스이며, Asset Toolbox는 로그인·크레딧 없이 로컬에서 실행된다. Hydra의 생성 모델 코드·가중치는 조사한 공식 공개 자료에서 찾지 못했다. 이 도구만으로 생성 품질까지 무료로 재현할 수 있다고 결론 내릴 수는 없다.

사용자는 “은발 Ludo · 한 주기 후보 26장 이게 젤 깔끔한데”라고 평가했다. 26장을 후속 비교 기준으로 유지한다. 최종 프로덕션 승인으로 해석하지 않는다.

## 증거

소스를 실험 폴더에 받아 TypeScript로 빌드했다. `probe.mjs`로 원본 36장과 선택본 26장을 각각 시트로 합치고, 루프와 발 기준점을 측정했다. 입력 62개 파일의 실행 전후 SHA-256은 같았다. 생성 호출은 0회다. `LUDO_TELEMETRY=0`, `DO_NOT_TRACK=1`을 설정했다.

| 대상 | 루프 점수 | 경계 변화 / 평소 변화 | 경계 판정 | 내부 큰 변화 |
|---|---:|---:|---|---|
| 원본 36장 | 0.34 | 2.38 | jump | 33번째 프레임 진입 |
| 선택본 26장, 원본 04~29 | 1.00 | 1.02 | smooth | 없음 |

원시 출력은 아래 파일에 그대로 보존했다. 종료 코드 0은 명령 실행 성공이며 아트 전체 통과를 뜻하지 않는다.

26장 기준점은 원본 415×489 캔버스에서 `(203, 487)`이다. Unity 정규화 피벗은 `(0.4892, 0.0041)`이다. 바닥 행은 486으로 추정됐다. 26장 모두 허용 오차 안에 있다는 결과이며, 모든 발이 정확히 같은 행이라는 뜻은 아니다. 오버레이에서도 기준선이 장화 아래에 놓이는 것을 확인했다. 이 값은 캔버스를 바꾸면 다시 계산해야 한다.

## 기준과 활용 방법

| 공개 로직 | 소스에서 확인한 동작 | 활용 판단 |
|---|---|---|
| `src/toolbox/loop.ts` | 알파를 곱한 RGBA 차이와 실루엣 외곽 거리 중 큰 값을 쓴다. 평소 인접 프레임 변화량으로 정규화해 반복 경계를 평가한다. 중복·멈춤·왕복도 보고한다. | 기존 주기 선택 도구 뒤에 독립 검사로 연결한다. 프레임을 자동으로 자르는 기능은 없다. |
| `sprite-analysis.ts` | 바닥 행을 프레임 다수에서 찾는다. 얇게 돌출된 부분을 줄여 몸통 범위를 추정하고, 몸 아래 지면에 닿는 픽셀로 발 중심을 잡는다. | 칼 끝이나 망토 때문에 중심이 쏠리는 문제를 줄일 후보다. 오버레이 검수를 함께 둔다. |
| `packMath.ts`, `pack.ts` | 웹 Export Pack 계산을 옮긴 코드라고 명시돼 있다. 첫 프레임의 캐릭터 높이를 기준으로 모션 크기를 맞추고 공통 캔버스·바닥에 배치한다. | idle·walk·attack 여러 모션의 내보내기에 활용한다. 웅크린 첫 자세는 크기 추정에 영향을 줄 수 있다. |
| `align.ts` | 서버 정렬 함수의 포트라고 명시돼 있다. 여러 크기에서 영상 상관도를 비교하며, 신뢰도가 낮으면 바닥·중심 정렬로 대체한다. | 서로 다른 동작을 이어 붙일 때 시험한다. 프레임마다 강제로 적용하면 원래 움직임을 해칠 수 있다. |
| 엔진 내보내기 | Unity 메타·클립, Godot 리소스, TexturePacker 형식을 지원한다. | 별도 실험 출력으로 먼저 엔진 임포트를 확인한다. 이번에는 엔진 실행을 하지 않았다. |

루프 점수는 `1 / (1 + (off - 1)^2)`를 소수 둘째 자리로 반올림한다. 공개 코드 기준 0.8 이상은 clean, 0.5 미만은 visible hitch 대역이다. 1.00은 완벽한 동작을 증명하지 않는다. 실제 평가 함수에는 발 접지 단계나 관절 속도를 직접 검사하는 항목이 없다. 소스 주석에 적힌 서버의 DINOv3 기반 검사와도 다른 측정이다. 서버 구현 자체는 확인하지 못했다.

첫 적용은 버전을 고정한 외부 CLI 연결이 적합하다. 원본을 별도 보존하고 JSON을 검수 기록에 첨부한다. CLI 종료 코드 12(입력·격자 문제)는 우리 판정의 측정 불가로 다뤄야 한다. 종료 코드 0을 시각 QA 통과로 바꾸면 안 된다. 코드를 복사해 배포할 경우 MIT 저작권·허가문을 함께 보존한다.

## 공백

- 공개 소스에서 재사용 가능한 범위는 후처리·정렬·측정·내보내기다. Hydra 생성, 시간축 배경 제거, 서버 루프 선택의 전체 구현은 확보하지 못했다.
- 공식 문서의 Fix Loop는 Forge로 새 영상을 만드는 기능이다. 현재 26장 선택처럼 기존 픽셀을 보존하는 작업과 결과가 다를 수 있다.
- 14.4FPS는 기존 영상 길이에서 추정한 재생값이다. 서비스의 원래 프레임별 시간표는 확인하지 못했다.
- 이번 검증은 캐릭터 1종·원본 1개에 대한 두 구간 비교다. 다른 캐릭터·동작에 대한 일반 성능은 아직 모른다.
- Unity/Godot 임포트, 실제 게임 화면, pack·sequence 실행 검증은 하지 않았다. 프로젝트 `docs/pipeline/state.json`이 없어 열린 게이트는 미확인이다.

## 잔여 위험

기존 sprite-qa의 실루엣 미달과 알파·떨림 경고는 그대로 남긴다. 이번 루프 점수가 이를 해소하지 않는다. 머리카락·장비의 정체성, 칼과 손의 동작 연결, 실제 화면에서의 발 미끄러짐은 별도로 검수해야 한다.

공개 도구의 몸통 추정도 픽셀 형태에 의존한다. 망토가 두껍게 이어진 캐릭터에서는 일부가 몸통에 포함될 수 있다. 충돌체와 발 기준점을 사람 확인 없이 확정하지 않는다.

추천 순서는 26장 기준본 유지, 로컬 루프·피벗 검수 연결, 여러 모션의 공통 내보내기 검증이다. 완전 무료 생성 실험은 그 다음에 별도 후보로 비교한다.
