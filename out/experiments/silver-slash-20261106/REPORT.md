# 은발 검사 베기와 타격 타이밍 비교

## 주장

GPT 은발 원화를 유지한 베기 시안과 비교 화면을 만들었다. Quaternius의 CC0 베기 동작을 로컬 Wan Animate 2로 옮겼다. 추가 유료 생성은 0회다. 이번 시안은 사람 검수 대기이며 프로덕션 승인이 아니다.

| 안 | 구성 | 공격 시간 |
|---|---|---|
| A | 원본 동작 25장을 균일 재생 | 1600ms |
| B | 12개 자세 선택, 구간별 재생 시간 적용 | 430ms |
| C | B와 같은 타이밍, 명중 시 정지·표적 반응·별도 궤적 | 명중 480ms, 빗나감 430ms |

원본 8~12번은 검이 몸 뒤로 돌아가 잘 보이지 않았다. B·C에서는 이 구간을 제외했다. 선택한 원본 번호는 `0,2,4,5,6,7,13,14,16,18,21,24`다. 타격 자세인 7번을 짧게 유지하고 복귀로 이어진다. 원본은 A에서 그대로 비교할 수 있다.

투명 처리 과정에서는 7번의 흐릿한 칼날이 지워졌다. 원본 RGB에 남은 칼날을 사용해 지정 영역의 투명도만 보정했다. 새 칼을 그려 넣지 않았다. 보정 영역 밖의 픽셀과 나머지 24장은 바뀌지 않았음을 검사했다.

## 기준

640×512 공통 캔버스, 고정 clip scale, 제자리 베기다. 칼을 머리 위로 들어 앞으로 내려베고, 몸과 앞다리에 힘이 실리는지 본다. 준비 자세는 읽을 시간을 주고, 칼 통과 구간은 짧게 만든다. 타격 이벤트는 157ms에 시작한다. 수치는 검토용 가정이며 게임 밸런스 확정값이 아니다.

기존 정규화 도구도 별도 후보로 실행했다. 프레임별 무기 외곽을 중앙에 맞추면 가로 이동량이 -31~70px가 된다. 따라서 메인 결과는 생성 시 공통 원점을 유지했다. 근거: [qa/normalization-decision.json](qa/normalization-decision.json).

패킹 도구는 높이순으로 프레임을 반환한다. 이번 내보내기 어댑터는 파일 이름으로 원본 번호·재생 시간을 연결한 뒤 재생 순서를 복원한다. [export/snappy.json](export/snappy.json)의 `durationMs`를 사용한다. 원시 패킹 JSON도 `.raw`로 보존했다. 공용 도구는 수정하지 않았다.

## 공백

Unity·Godot 등 실제 엔진 임포트와 전투 중 검수는 하지 않았다. HTML의 판정은 정해진 전방 범위와 표적 위치로 계산한다. 검 픽셀의 정밀 충돌이나 콤보·입력 취소 규칙은 구현하지 않았다. 비교 버튼은 재생을 다시 시작할 수 있다. 실제 게임의 공격 간격과 분리해서 봐야 한다.

생성 모델 해시는 이번에 다시 검사하지 않았다. 사전 검사는 노드와 선택지만 확인했다. 처음 `--host`에 URL 형식을 넣은 오류는 수정해 다시 검사했고, 입력 파일을 서버 선택지에 맞춰 배치한 뒤 통과했다. 시작 art-gate는 기존 샘플 누락으로 측정 불가였다. 열린 게이트 원장 파일은 없다.

다른 캐릭터·무기·방향의 품질을 보장하지 않는다. GIF는 10ms 단위로 시간을 반올림하고 끝에 700ms 대기를 넣었다. 정확한 타이밍 비교는 HTML을 사용한다. 효과음의 주관적인 품질은 검수하지 않았다.

## 잔여 위험

공격 중 큰 자세 변화에 대해 자동 실루엣 검사가 미달을 보고했다. 이 수치만으로 캐릭터 붕괴라고 단정하지 않지만 통과로 덮지도 않는다. 빠른 동작에서 칼날 흐림, 망토의 세부 변화, 준비·복귀 연결은 사람이 확인해야 한다. 모션 감소 옵션은 궤적·흔들림·표적 반동을 끄며 명중 정지는 유지한다.

비교 화면: `http://127.0.0.1:8198/`. 추가 결제·커밋·push는 하지 않았다. 로컬 모델은 실행 후 메모리에서 내렸고 비교 서버는 유지했다.
