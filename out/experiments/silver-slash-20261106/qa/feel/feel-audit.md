
# 연출 상수 감사 (feel bible)

`C:\00.SVN\game-dev-team_ver04\out\experiments\silver-slash-20261106\feel.json` · 이벤트 1개 · 60fps · 액션 간격 1800ms

## [주장]
판정: **충족**

> **"느낌이 좋은가"는 판정하지 않는다** — 그건 사람이 사인오프한다.
> 여기서 보는 건 느낌과 무관하게 틀린 것(논리 모순·예산 초과·접근성 누락)이다.

## [증거]
```
이벤트     무게  hitStop  (ms)  흔들림px  흔들림ms  플래시ms  반응fr  이징  길이ms  피드백총
---------  ----  -------  ----  --------  --------  --------  ------  ----  ------  --------
hit_light  1     3        50    2         80                                        130     
```
> 피드백총 = hit-stop(게임이 멈추므로 직렬) + max(흔들림, 플래시)(병행).
> 예산 = 액션 간격 1800ms × 0.6 = 1080ms

## [기준]
`C:\00.SVN\game-dev-team_ver04\out\experiments\silver-slash-20261106\feel.json` 의 `_thresholds`(없으면 도구 기본값). 현재 적용값:
입력 반응 ≤ 50ms · hit-stop 2~12프레임 ·
흔들림 ≤ 400ms / 12px · 피드백 예산 0.6

hit-stop 권장 범위의 출처는 업계 관행이다 — 3~5프레임이 흔하고 40~80ms 대,
넓게는 3~12프레임(0.05~0.2초)까지 쓴다. 무게에 따라 나누는 게 정석이다.

## [공백]
- **"느낌이 좋은가"는 이 도구 밖이다.** 사람 사인오프가 P1·P2 게이트의 본체다.
- 선언된 값과 **실제 구현이 일치하는지는 검사하지 않았다.** 코드가 이 표를 읽어야 의미가 있다 —
  숫자를 코드에 따로 박아두면 이 감사는 장식이다.
- 실제 프레임 유지(연출이 프레임을 깎지 않는가)는 실기기 프로파일링 몫이다.
- 이펙트 자체의 광과민성 위험은 `flash-check.mjs` 가 본다 — 이 도구는 수치 표만 본다.
- 부류 `hit` 는 항목이 1개라 **무게 순서를 검사하지 못했다** — 비교 대상이 없다.
