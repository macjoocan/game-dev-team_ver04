# 은발 내려베기 — 레퍼런스 기반 1차 후보

## 주장

Soulbound의 검 공격 흐름을 참고해 은발 캐릭터의 내려베기 8포즈를 만들었다.
외형 기준은 기존 은발 걷기 v3다. 기본 image_gen으로 생성 1회, 여백 보정 1회를 실행했다.
별도 유료 영상 API는 사용하지 않았다. 생성 자체가 무료라는 의미는 아니다.
상태는 사람 검토 대기다. 실제 게임에 반영하거나 출시용으로 승인하지 않았다.

## 증거

대상 소스 커밋: `bba068c`.
참고: `D:\99.기타\out_soulbound\sprite_metadata.json`의 `sDCMobResurrectedPioneerSword_Attack_E`.
사용한 포즈 순서는 8748, 8747, 8739, 8744, 8754다.
프롬프트에는 로컬 조사 콘택트 시트 중 해당 행만 동작 참고로 지정했다.

- `raw/silver-slash-v1.png`: 최초 생성. 오른쪽 5번 프레임과 왼쪽 6번 프레임에 경계 접촉 경고가 났다.
- `raw/silver-slash-v2.png`: 포즈를 유지하며 여백을 늘리도록 재편집한 후보.
- 두 원본은 1536×1024이며, 정확한 4×2 격자로 잘라 384×512 프레임 8장씩 만들었다.
- v2는 네 방향 모두 경계 접촉 0/8이다. 최소 여백은 위 83px, 아래 73px, 왼쪽 45px, 오른쪽 8px다.
- 알파 128 이상 피사체 하단의 프레임 간 범위는 2px다. 발 관절 추적값은 아니다.
- 원본 색·알파를 유지했다. 프레임별 확대·축소나 위치 보정은 하지 않았다.

일반 `sprite-qa`는 v2를 **미달(exit 1)**로 판정했다.
준비·머리 위 검·전방 공격 자세의 실루엣 IoU가 대표 프레임보다 낮다.
큰 공격 포즈 변화가 원인일 수 있으나, 이 해석으로 자동 미달을 통과 처리하지 않았다.
떨림·기존 baseline·작은 분리 영역·구멍·프린지 경고도 보존했다.
기존 baseline 경고 66px는 낮은 알파까지 포함한다. 선명한 피사체 하단 범위 2px와 다른 측정이다.

`v1/qa/`, `v2/qa/`와 각 `.stdout.log`·`.stderr.log`가 도구 원문이다.
`evidence.json`에 프레임 SHA-256·피사체 경계·참고 원본·검사 결과를 저장했다.

## 기준

`feel.json`에서 재생 시간을 관리한다. 아래 값은 이번 후보용 수동 설계이며 원작 타이밍이 아니다.

| 포즈 | 균등(ms) | 타격 타이밍(ms) |
|---|---:|---:|
| 준비 | 80 | 100 |
| 힘 모으기 | 80 | 110 |
| 검 들기 | 80 | 75 |
| 내려치기 | 80 | 35 |
| 타격 자세 | 80 | 55 |
| 끝까지 베기 | 80 | 65 |
| 회수 | 80 | 100 |
| 정리 | 80 | 100 |

두 버전의 동작 시간은 640ms이고, 반복 전 대기 300ms를 똑같이 둔다.
피격 대상·충돌·게임 정지는 연결하지 않았다. 타격 자세를 보여주는 시간은 실제 hit-stop과 다르다.

## 화면 확인

Playwright로 1160×1000 밝은 배경과 390×844 어두운 배경을 확인했다.
작은 표시는 캔버스 높이 160px이며 가로 넘침은 없었다. 두 이미지의 로드와 자연 크기 384×512를 확인했다.
250ms에서 균등은 0기준 프레임 3, 타격 타이밍은 프레임 2였다.
재생 시작 뒤 약 183ms에서 양쪽 프레임이 2/1로 진행했다.
프레임 선택·배경 변경·크기 변경도 확인했다.

## 공백과 잔여 위험

공격의 체감·검 길이 불변·손의 정확한 그립·회수 연결은 사람 검수가 필요하다.
가장자리 알파와 일부 내부 빈 공간을 정리하지 않았다. 실제 배경 위 합성 검수를 더 해야 한다.
일반 실루엣 검사 미달은 유지한다. 프로젝트 공통 아트 게이트도 기존 참조 폴더 누락으로 측정 불가다.
소스 코드·공용 스킬은 바꾸지 않았으며 새 결과를 GitHub에 푸시하지 않았다.
