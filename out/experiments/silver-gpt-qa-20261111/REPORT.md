# 새 은발 시트 생성·팔과 다리 수정 검증

## [주장]

새 GPT 시트를 만들고 개선한 입력·잘림·모션 검사로 확인했다.
사용자가 v1의 색 분리는 좋지만 다리 교차와 칼 든 팔을 고쳐 달라고 요청했다.
v3는 그 피드백을 반영한 최신 후보다. 색과 디자인을 기준으로 유지하며 팔·다리 포즈를 수정했다.
팔의 앞뒤 포즈와 다리 전환이 달라졌지만, 사람의 최종 모션 승인은 아직 없다.

후속으로 사용자는 “오우 좋아졌네”라고 평가했다. v3를 다음 비교 기준으로 보존한다.
이 긍정 평가를 전체 검사 통과나 출시 승인으로 확대하지 않는다.
정본 피드백은 `.review-loop/feedback/chr.silver.gpt-qa-20261111.preference.json`에 기록했다.

## [증거]

생성·편집은 기본 image_gen으로 3회 실행했다. 별도 유료 API나 CLI 생성은 사용하지 않았다.
원본 PNG와 프롬프트는 raw/ 및 prompt-v1.txt, prompt-v2.txt, prompt-v3.txt에 보존했다.
각 시트를 같은 크기의 8칸으로 잘랐다. 알파·색·크기·위치 보정이나 보간은 하지 않았다.
대상 도구는 4ceb944 위의 미커밋 개선 코드다.

| 후보 | 정합성 / 종료 코드 | 경계 접촉 방향 수 | 최소 여백 | 피사체 하단 범위 | 하단 윤곽 변화량 |
|---|---|---:|---:|---:|---:|
| v1 | 충족 / 0 | 0 | 39px | 4px | 0.294847 |
| v2 | 미달 / 1 | 0 | 14px | 6px | 0.322144 |
| v3 | 충족 / 0 | 0 | 15px | 2px | 0.306774 |

피사체 하단 범위는 알파 128 이상인 픽셀의 최하단 위치 범위다.
발 관절이나 발 접지를 직접 측정한 값은 아니다.
v2는 기존 baseline 검사에서 34px 산포 경고가 나왔고 형태 검사도 실패했다.
기존 baseline은 희미한 알파까지 포함한 외곽으로 계산한다. 표의 알파 128 이상 기준인 6px와 다르다.
34px를 실제 발 관절의 이동량으로 해석하지 않는다.
v3는 C 모션의 0·3·6·9·13·16·19·22번 포즈를 참고한 뒤 다시 검사했다.

원시 출력은 [v1 검사](v1/sprite-qa.stdout.log), [v2 검사](v2/sprite-qa.stdout.log), [v3 검사](v3/sprite-qa.stdout.log), [v3 모션 관찰](v3/motion-qa.stdout.log)에 있다.
파일 해시·설정·사용자 피드백·비교값은 [evidence.json](evidence.json)에 남겼다.
요약 표는 원시 출력을 대신하지 않는다.

[수정 전후 재생 화면](review.html)을 만들었다. 같은 8fps로 비교하며 0.5배 재생과 프레임 선택을 지원한다.
Playwright로 이미지 로드, 재생 진행, 프레임 선택, 가로 넘침 없음을 확인했다.
[밝은 배경 320px 화면](review-light.png)과 [390px 화면의 어두운 배경·128px 표시](review-mobile-dark.png)를 직접 확인했다.
투명 알파가 합성됐고 칼·다리 실루엣을 볼 수 있었다. 시간에 따른 자연스러움 판정은 스크린샷만으로 끝내지 않는다.

## [기준]

입력·잘림·모션 기준은 sprite-pipeline의 공통 계약을 그대로 사용했다.
색·형태 실패를 피하려고 임계값을 완화하지 않았다. tight-crop 면제도 쓰지 않았다.
하단 윤곽 변화량은 품질 점수가 아니다. 실제로 v1도 자동 검사에는 통과했지만 사용자 수정 요청을 받았다.

## [공백]

새 시트는 8키포즈 후보이며 26프레임 모션과 같은 부드러움을 확인한 것은 아니다.
발 미끄러짐·체중 이동·팔과 다리의 정확한 반대 박자·칼 길이 불변·루프 연결을 자동 판정하지 않았다.
실제 게임 에셋 교체와 바쁜 전투 화면 검수는 하지 않았다.
프로젝트 공통 아트 게이트는 기존 참조 폴더가 없어 측정 불가였다.

## [잔여 위험]

v3에는 작은 분리 영역·내부 빈 공간·프린지 경고가 남아 있다.
낮은 알파가 넓게 남으면 기존 프린지 계산값이 커질 수 있다. 이를 곧바로 화면 결함 비율로 읽지 않는다.
가장 좁은 여백은 15px다. 표시 배율이나 후속 크롭을 바꾸면 다시 검사한다.
이미지 편집은 픽셀 단위 보존을 보장하지 않는다. 얼굴·의상·색은 시각적 기준으로 유지 요청했다.
자동 통과를 사람 승인으로 올리지 않고 검토 상태로 남긴다.
