# 집 작업 수신과 스프라이트 판정 설계 검토

2026-11-11 · Codex · 수신 커밋 `4ceb944` · 사용자 선택: 설계와 측정 결과를 먼저 검토

## 주장

집에서 올린 4개 커밋을 fast-forward로 받았다. 소스는 0.53.0이다. 잘림을 경고부터 시작하고 보행 수치를 판정과 분리하는 방향은 유지할 만하다. 다만 현재 탐침을 그대로 제품 코드로 옮기기 전에 입력 검증, 측정 정의, 승격 조건과 자료 버전을 보완해야 한다.

원본 설계·제품 코드·사람 라벨은 수정하지 않았다. 검토용 사본과 합성 입력은 이 폴더에만 만들었다. 검수 조회 도구가 수신 전에 자동으로 쓴 1건은 `review-before-pull/`에 보존한 뒤 원격 원장을 받았다. 이후 측정은 원장에 쓰지 않았다.

## 증거: 재현한 수치와 반례

실행 명령은 `node out/resume-20261111/review-probes.mjs`다. 원본 탐침의 식은 유지했다. import·PC 경로를 바꾸고 함수 export와 검토 입력만 추가했다. 원시 결과와 탐침 해시는 [measurements.json](measurements.json)에 있다.

| 입력 | 잘림 탐침 | 보행 탐침 | 해석 |
|---|---|---|---|
| 정상 합성 입력 4장 | 충족 | 수치 생성 | 대조군 |
| 전부 빈 이미지 4장 | **충족** | 유효 프레임 부족 | 잘림 탐침에는 빈 내용물 방어가 없다 |
| 본체 알파가 정확히 128인 4장 | 충족 | **유효 프레임 부족** | 규범은 `>=128`, 보행 탐침은 `>128`이다 |
| 배경 알파 10, 본체 255인 4장 | **알파 없음** | 수치 생성 | 투명 픽셀 정의가 `===0`과 `<20`으로 다르다 |
| 32×32·40×40 캔버스 혼합 | 충족 | 수치 생성 | 탐침 자체에는 크기 일치 방어가 없다 |
| 고정된 발·고정된 망토 | 충족 | `liftRange=0` | 대조군 |
| 같은 발·움직이는 망토 | 충족 | **`liftRange=0.111702`** | 발이 안 움직여도 하단 실루엣 변화로 수치가 올라간다 |

실제 은발 C안 26장의 최소 여백은 위 46·아래 48·왼쪽 89·오른쪽 24px였다. 접촉 기준 1·2·3px에서 모두 네 변 접촉 0장으로, 설계의 기록과 일치했다. C안의 `liftRange`는 0.318646, rigid 8장은 0.202283이었다. rigid의 설계 값 0.202는 재현했다.

이 PC에는 잘림 표의 동작 폴더 8개 중 C안 1개만 있다. 피격·찌르기 등 7개와 사나비 추출본은 없다. 따라서 ‘부정 4/4 검출’과 ‘0.221 대 0.202’ 전체 비교를 이 PC에서 다시 확인했다고 주장하지 않는다.

## 설계에서 먼저 보완할 부분

### 1. 입력 검증과 알파 정의를 공통으로 정한다

`crop-probe.mjs`는 빈 프레임의 `margin=null`을 제외한 뒤 네 변 접촉 0으로 통과시킨다. 공통 입력 계약에 빈 내용물, 읽기 실패, 크기 혼합, 충분한 유효 프레임 수를 넣어야 한다. 잘린 프레임 일부를 말없이 버리고 나머지만 채점하면 안 된다.

알파 128의 포함 여부와 투명 픽셀 기준도 한 정의로 맞춘다. 원본의 알파 전제 검사와 내용물 마스크가 같은 개념인지 명시한다. 기존 `sprite-qa`에 크기 검사가 있다는 것과, 단독 교정 술어가 크기 검사를 수행한다는 것은 별개다.

근거: [설계 §3.4](../../docs/superpowers/specs/2026-11-11-sprite-motion-gate-design.md#34-정의-규범적--구현은-이대로-한다), 두 탐침과 위 합성 반례.

### 2. `liftRange`는 하단 윤곽 변화로 해석한다

망토만 움직인 반례에서 수치가 0에서 0.111702로 바뀌었다. 이 지표가 실제 발의 높이나 접지를 직접 재는 것은 아니다. 보행 강도와 연관될 수 있지만 의상·무기·자세도 섞인다. ‘발들림’ 대신 ‘하단 윤곽 변화량’처럼 실제 계산을 설명하는 이름이 맞다. 보고 전용으로 남긴다는 결정은 유지한다. 이번 반례만으로 정상 걷기 대역이나 새 임계선을 제안하지 않는다.

### 3. 경고 등급과 종료 코드의 관계를 정한다

§4A는 측정 불가가 하나라도 있으면 exit 3을 요구한다. §9는 현재 잘림 경고가 게이트를 막지 않는다고 정했다. 모든 프레임이 바닥에 닿는 정상적인 타이트 크롭에서 잘림 항목만 측정 불가가 되면, exit 3 역시 자동 실행을 실패시킬 수 있다.

권장안은 등급별 결과를 분리하는 것이다. 경고 후보의 미달·측정 불가는 보고서에 남기되 기존 검사의 최종 종료 코드를 올리지 않는다. 파일이 없거나 전체 입력 자체가 유효하지 않은 경우의 exit 3은 유지한다. 차단 등급 승격 뒤에는 기존 0/1/3 계약을 적용한다. 이는 아직 채택되지 않은 검토 제안이다.

### 4. 승격은 표본 수 외의 근거도 고정한다

§9의 ‘긍정 5건 도달’은 §4C의 네 조건 전체, `per-frame` 조건, 모든 표본의 측정 가능성까지 만족했을 때로 명확히 쓴다. 같은 동작을 다섯 번 평가하거나 버전을 여러 개 등록한 경우를 독립된 다섯 표본으로 셀지 정해야 한다. 나중의 확대 검수로 기존 라벨이 바뀌었을 때 어떤 라벨이 유효한지도 필요하다.

캐시는 검사 버전뿐 아니라 입력 프레임 목록·내용 해시·측정 설정에 묶는다. 같은 `out/` 경로의 파일이 바뀌거나 서로 다른 PC에 다른 버전이 있으면, 검사 코드 버전만으로는 같은 표본임을 보장하지 못한다. 캐시와 실제 파일이 다를 때는 그 표본을 미확인으로 남기고 승격을 보류하는 편이 맞다.

피격의 후속 사람 발언 3개는 현재 `reviews.jsonl` 검색에서 찾지 못했다. 발언이 없었다는 뜻은 아니다. 현재 근거는 설계 §9에만 있으므로 저널 전용 ingest로는 가져올 수 없다. 설계 기록 등 별도의 출처 연결 경로가 필요하다. 현재 긍정 1건도 `per-frame`으로 확인한 건인지 명시해야 한다. 재생을 보고 한 긍정 발언을 임의로 바꾸지 않는다.

§4C에는 부정 3/3, §3·§9에는 4/4가 남아 있다. 이는 문서 수치 정리 대상이다.

## 기준과 유지할 결정

- 잘림 검사는 우선 경고로 둔다. 경계 접촉은 결함 후보이며, 원본 밖의 내용물을 직접 관측한 것은 아니다.
- 보행 지표는 보고용이다. 임계선을 찾아 승인된 모션을 탈락시키지 않는다.
- 파츠 겹침·접합·정체성은 별도 문제로 남긴다. 이 설계가 해결했다고 쓰지 않는다.
- 코퍼스는 읽기 전용 원장에서 파생하고, 후보 라벨을 사람 확인 없이 확정하지 않는다.

## 공백과 잔여 위험

이번 결과는 탐침 검토다. 제품화된 검사 도구의 버그를 발견했다는 뜻은 아니다. 합성 반례는 정의와 방어 로직을 검증하며 사람에게 자연스러운 모션을 증명하지 않는다. 의도적으로 테두리를 오가는 효과와 실제 잘림을 구별할 추가 표본도 필요하다.

수신 후 플러그인 구조 검사는 통과했다. 테스트는 16개 중 전투 15개 통과, PixelFX 1개 건너뜀이다. `.art-tools/pixelfx`가 없기 때문에 새 내보내기의 실제 동작까지 검증한 것은 아니다. Codex·Claude 설치본은 0.52.0이며, 소스 0.53.0과 다르다. 설치 갱신과 제품 구현은 이번 설계 검토에서 수행하지 않았다.
