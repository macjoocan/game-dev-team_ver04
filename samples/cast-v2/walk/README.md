# 걷기 8프레임 — 새 캐스트 실측 (2026-10-02)

`walk-composite` 를 **cast-v2 도트에 처음 돌려봤다.** 도구는 있었지만 이 캐스트에 돌려본 적이 없었다.

## 결과

```
          의상차   다리차
chaser     0.11   13.28
hero       0.94   16.30
lunger     0.20    7.20
boss       0.14   24.76
```

**의상차 1 미만 · 다리차 7~25** — 상체는 고정이고 다리만 움직인다.
(Hex 때 성공 기준이 "의상 0 · 다리 11" 이었다)

## 쓴 설정과 그 이유

```bash
node .../walk-composite.mjs <도트.png> --out <dir> --frames 8 --nearest --hip 0.45 --bob 0
```

### `--hip 0.45` — 기본값 0.72 는 이 캐스트에 안 맞는다
기본값으로 돌리면 **엉덩이선이 발목에 간다.** 다리가 선보다 위에 있어서 상자에 장화만 들어가고,
대신 몸 전체가 흔들린다. 실측(hero):

```
hip=0.72  의상차 20.21  다리차  5.11
hip=0.50  의상차 12.05  다리차 16.37
hip=0.45  의상차  0.75  다리차 11.03   <- 채택
```

### `--bob 0` — 도트에서 상하 흔들림은 쓸 수 없다
`bob` 은 몸통을 위아래로 움직여 걷기를 판다. 그런데 **1px 이 최소 단위**이고
96px 스프라이트에서 1px 은 과하다. 실측(hero, hip 0.45):

```
bob=0      의상차  0.39  다리차  9.79   <- 채택
bob=0.006  의상차 12.05  다리차 16.37
bob=0.018  의상차 12.05  다리차 16.37
```

**`0.006` 과 `0.018` 이 같은 결과다** — `Math.max(1, round(BH*BOBR))` 의 1px 바닥 때문에
둘 다 1px 이 된다. 큰 스프라이트(128px+)에서는 쓸 수 있지만 여기서는 0 이 맞다.

## 도구 수정 — 다리 상자 씨앗을 발띠로

**맨 아랫줄 한 줄**로 씨앗을 잡고 있었는데, 그 줄 사정에 통째로 휘둘렸다:

| | 한 줄 씨앗 | 발띠(아래 12%) |
|---|---|---|
| lunger | **7px** (창끝+발 몇 픽셀) | 27px |
| boss | **98px** (망치 머리가 깔림) | 99px* |
| hero | 32px | 52px |

lunger 다리차가 **0.72 -> 7.20** 으로 10배 올랐다. 손으로 준 상자(6.95)와 같은 수준이라
**`--box` 를 손으로 줄 필요가 없어졌다.**

\* boss 는 위로 따라 올라가며 다시 벌어진다. 바닥에 닿은 소품이 많으면 여전히 넓다.

## 남은 한계 — 소품이 같이 늘어난다

다리 상자에 걸린 **방패·창·망치**가 다리와 함께 압축된다. 확대하면 보이고,
**게임 크기(1~2x)에서는 많이 줄어든다**(`preview-2x.png`).

도구가 원래 경고하던 것이고 구조적 한계다 — 다리와 소품이 **가로로 겹치면** 색으로도 위치로도 못 가른다.
거슬리면 `--box lx,rx` 로 좁히거나, 소품을 별도 레이어로 분리해야 한다(`rig-split` 축).
