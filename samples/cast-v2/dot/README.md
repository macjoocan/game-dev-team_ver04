# 도트 변환 — 정직한 결과

같은 컷아웃 원본을 `pixel-quantize` 로 내리고 캐스트 공용 팔레트를 먹였다.
**도트 계약은 충족한다**(공용 24색 · 반투명 0% · 외톨이 2.7~14.3%). 그런데 **좋은 도트는 아니다.**

## 크기가 전부다 (size-sweep.png)

주인공 하나로 48 / 64 / 96 / 128px 을 비교했다.

- **48px**: 얼굴이 뭉갠다. 48px 캐릭터의 얼굴은 **6x6 픽셀**이다 — 눈·코·입이 들어갈 자리가 없다
- **64px**: 아직 눈이 안 읽힌다
- **96px 부터**: 눈과 표정이 읽히기 시작한다
- **128px**: 선명하다

처음에 게임 크기(36~64px)로 뽑았다가 전부 알아볼 수 없어서 올렸다.

## 한계 — 이건 축소한 일러스트지 도트가 아니다

96px 에서도 주인공 눈이 비어 있고 해골 눈구멍이 하나 뭉갰다.
**확산 모델은 격자를 못 만든다**(VAE 가 연속 RGB 를 뱉는다). 축소는 격자에 맞추는 것이지
도트를 그리는 것이 아니다. 계약은 "도트인가"를 보지 "좋은가"를 보지 않는다 — 통과했는데도 이렇다.

진짜 도트로 가려면 둘 중 하나다:
1. **도트 전용 생성**(Retro Diffusion 등) — 격자 스냅·팔레트 제한이 파이프라인에 포함돼 있다
2. **96px 이상으로 뽑고 얼굴만 손본다** — 6x6 얼굴은 어차피 사람이 찍어야 한다

이 폴더는 **"축소 경로가 어디까지 되는가"의 실측 기록**이다. 프로덕션 도트의 기준선이 아니다.
